# Contributing to CertMuse

Thank you for helping make CertMuse easier to understand, safer to reuse, and more useful to certification-learning teams.

## Before you begin

This is a source-only release. Please read [the release scope](docs/RELEASE_SCOPE.md) before opening an issue or pull request. Requests for private deployment configuration, production data, examination materials, credentials, or operational scripts cannot be accepted through this repository.

## Good contributions

- Clarify public documentation or domain terminology.
- Fix a focused defect with a reproducible explanation.
- Improve accessibility, consistency, error handling, or developer readability.
- Propose a narrowly scoped enhancement with its learner or operator value explained.

## Issue first when the change is substantial

For a feature, behavior change, or cross-module refactor, open an issue first. State the problem, affected users, expected outcome, and any compatibility risk. This keeps proposals aligned before implementation effort is invested.

## Pull request checklist

1. Keep the pull request focused on one clear outcome.
2. Explain the user-facing or maintenance value in the description.
3. Preserve existing public contracts unless the change explicitly documents a migration path.
4. Add or update tests when a runnable test environment is available; otherwise state the exact validation you performed and what could not be run.
5. Do not include generated files, local environment files, credentials, private documents, user data, or copyrighted examination material.
6. Update public documentation when behavior, scope, or contributor expectations change.

## Review expectations

Maintainers review correctness, scope, maintainability, security, documentation, and compatibility. A request may be closed when it depends on unpublished infrastructure or exceeds the public release scope; that is a boundary decision, not a judgment on the proposal.

## Community standards

Be constructive, specific, and respectful. By participating, you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).
