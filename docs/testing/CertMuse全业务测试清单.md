# CertMuse 全业务测试清单

## 执行入口

```powershell
.\tools\test-certmuse.ps1
```

该命令先运行前后端质量门禁，再启动独立 Docker Compose 项目 `certmuse-e2e`。它使用专属卷和
专属网络和卷，不会暴露端口或复用本机正在运行的 `3000`、`18080` 或其数据库。
报告、截图、trace 预留位置和服务日志写入 `work/e2e-reports/<timestamp>/`；默认结束后销毁容器和卷。

开发时可使用 `-SkipQualityGates` 缩短反馈，或以 `-KeepEnvironment` 保留隔离栈排查；两者都不能作为完整验收结论。

## 覆盖矩阵

| 测试层 | 已自动化边界 | 成功路径 | 失败路径 |
| --- | --- | --- | --- |
| 单元 | 管理端、学生端 CertMuse API/组件/页面；后端全 reactor | 现有 Vitest/JUnit 行为与覆盖率阈值 | 校验、状态分支、异常处理 |
| HTTP + 数据库 | JSONL 导入预检 | 认证、上传、幂等、异步进度、问题分页 | 未认证、请求号冲突、格式/映射错误、未知批次 |
| 浏览器 | 公共页、认证、学生受保护路由、管理端主要菜单 | 页面可达、登录分流、管理员路由 | 错误凭据、未认证访问、404/401 |
| 外部 AI | 本地 OpenAI 兼容替身 | 固定响应 | 429、503、超时注入能力 |

`tests/e2e/page-manifest.json` 是页面用例 ID 的唯一清单。每个后续实现的业务页必须先添加清单项，再补充：加载/空态、成功动作、前置或权限失败、服务失败，以及写操作的幂等或冲突断言。

## 当前已知缺陷与边界

管理端规则配置、规则命中日志、题池健康、运营看板，以及教材/题目/审核详情和其余规则、洞察占位页，当前明确渲染“页面已建立 · 功能待接入”。可由菜单访问的页面由浏览器套件报告为 `expected_defect`；隐藏详情页由源文件断言跟踪，二者都不计为业务通过。功能实现后必须删除缺陷标记并新增真正的成功和失败用例。

学生完整诊断、任务、练习、模拟卷、真题、错题和画像闭环还需要稳定的测试题目、教材、试卷及会话夹具。测试不得以 `VITE_APP_STUDENT_MOCK=true` 代替真实跨层验收；在夹具未补齐前，这些流程的不可达状态应在报告中列为阻塞缺陷，而非通过。
