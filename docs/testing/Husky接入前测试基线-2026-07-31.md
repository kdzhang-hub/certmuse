# Husky 接入前测试基线（2026-07-31）

## 目的

确认 CertMuse 当前已有的前端检查、前后端单元测试、后端构建、JSONL 测试夹具及容器配置能够稳定执行，为后续接入 Husky 提供可重复的门禁命令。

## 前端结果

执行命令：

```powershell
pnpm --dir web/admin typecheck
pnpm --dir web/admin lint
pnpm --dir web/admin test:unit
pnpm --dir web/admin test:coverage
pnpm --dir web/admin build
```

结果：

- Vue/TypeScript 类型检查通过。
- Oxlint 检查通过。
- Vitest：1 个测试文件、5 个测试用例全部通过。
- 当前被测文件 `src/utils/validate.ts`：语句覆盖率 61.29%，分支覆盖率 50%，函数覆盖率 45.45%，行覆盖率 61.29%。
- Vite 生产构建通过，共转换 3404 个模块。

说明：上述覆盖率只针对当前纳入测试的 `validate.ts`，不能视为整个前端项目覆盖率。

## 后端结果

执行命令：

```powershell
.\backend\mvnw.cmd -f .\backend\pom.xml "-Dmaven.test.skip=false" test
```

结果：

- Maven Reactor 41 个模块全部成功。
- Surefire 共生成 4 份测试报告。
- 共执行 11 个测试，失败 0，错误 0，跳过 0。
- 其中 CertMuse 业务模块 10 个测试，若依 Admin 的 `dev` 标签示例测试 1 个。

为使全 Reactor 测试可运行，Surefire 的环境标签筛选从根 POM 移至实际具有 JUnit 测试依赖的 `ruoyi-admin` 和 `ruoyi-certmuse` 模块；`dev/local/prod/exclude` 标签语义保持不变。

已知非阻断警告：Mockito 当前通过动态加载 Byte Buddy Agent 启用 inline mock maker。Java 21 下测试通过，但未来 JDK 可能默认禁止动态 Agent 加载，需要后续按照 Mockito 官方方式显式配置 Agent。

## Husky 接入结论

当前已具备可接入 Husky 的基础门禁命令：

```text
前端：typecheck → lint → test:unit → build
后端：Maven 全 Reactor test（显式启用测试）
基础设施：Docker Compose 配置检查
```

覆盖率报告适合在 Jenkins 中完整生成和归档；本地 Husky 可只执行 `test:unit`，避免同一套测试重复运行两次。
