# Husky 部署验证（2026-07-31）

## 配置

- Husky：9.1.7
- Git Hooks路径：`.husky/_`
- 根依赖锁：`pnpm-lock.yaml`

### pre-commit

```sh
pnpm --dir web/admin lint
```

用途：在创建提交前执行快速前端静态检查。

### pre-push

```sh
pnpm run check:frontend
./backend/mvnw -f ./backend/pom.xml -Dmaven.test.skip=false test
docker compose -f infra/docker/compose.yml config --quiet
```

用途：

1. 前端类型检查；
2. 前端lint；
3. 前端单元测试；
4. 前端生产构建；
5. 后端41模块编译及JUnit测试；
6. Docker Compose配置解析。

## 实际验证

执行：

```powershell
git hook run pre-commit
git hook run pre-push
```

结果：

- 两个钩子均返回退出码0。
- 前端5个单元测试全部通过。
- Vite生产构建成功，转换3404个模块。
- 后端41个Maven模块全部成功。
- 后端共12个测试，失败0、错误0、跳过0。
- Docker Compose配置解析通过。
- 完整钩子验证耗时约65秒。

本次验证不会创建提交，也不会向远端推送。

## 使用限制

- 开发者可以使用 `--no-verify` 绕过本地Git钩子，因此仍需Jenkins或GitHub Actions作为不可绕过的合并门禁。
- 当前pre-push要求本地具有Node.js、pnpm、JDK 21、Git及Docker CLI。
- 当前只要求测试通过，未设置覆盖率阈值。前端全源码行覆盖率仅0.18%，不适合立即设置较高阈值。
- 首次克隆后需要在仓库根目录执行 `pnpm install`，由 `prepare` 脚本激活Husky；前端还需按锁文件安装依赖。
