# U04-U06 首次诊断前后端交接文档 V1

## 1. 适用范围与兼容结论

学员端现有 `web/student` 已接入预检、创建、会话、题目、草稿保存、暂停、交卷预检、交卷、结果状态、结果重试和报告共 11 个首次诊断接口。除会话响应新增时间事实和本文件第 2 节的新接口外，既有 URL、方法、请求体、错误码和状态枚举保持兼容。

本轮后端不修改学生端或管理端代码。学生端按本文件接入后，才能使“题目实际显示后开始计时”的事实完整成立。

## 2. 新增计时事件接口

```http
POST /api/assessment/diagnostics/{sessionId}/timer-events
X-Request-Id: <UUID>
Content-Type: application/json
```

```ts
type DiagnosticTimerEventType = 'ENTER' | 'HEARTBEAT' | 'HIDDEN' | 'LEAVE';

interface DiagnosticTimerEventRequest {
  eventType: DiagnosticTimerEventType;
  questionOrder: number; // 冻结题单范围内的正整数
  leaseId: string | null; // ENTER 为 null；其他事件为最近 ENTER 返回的租约
}

interface DiagnosticTimerEventVo {
  eventAccepted: boolean;
  leaseId: string | null;
  questionOrder: number;
  timerState: 'RUNNING' | 'STOPPED' | 'REPLACED';
  estimatedDurationSeconds: number;
  effectiveElapsedSeconds: number;
  serverTime: string;
}
```

写请求遵守既有 `X-Request-Id` 幂等规则：网络重试复用同一请求号；新的用户动作生成新的请求号。`ENTER` 成功后保存 `leaseId`。`REPLACED` 表示其他窗口或设备已取得租约，旧页面必须停止心跳和本地动画。

## 3. 时间事实与前后端分工

后端负责：以服务端时间确认题目有效区间、累计单题和整场有效用时、持久化租约、判断 20 秒心跳失效、标记失效题目的时间证据、返回预计总时长和已确认有效总时长。后端不进行每秒写库，不返回展示文案，不自动交卷。

前端负责：显示倒计时及超时正向计时、按生命周期发送事件、每 10 秒心跳、网络重连后的界面校准，以及旧租约提示。前端不得上传客户端计算秒数作为评分或画像输入。

会话接口在原有字段外增加：

```ts
interface DiagnosticSessionTiming {
  estimatedDurationSeconds: number;
  effectiveElapsedSeconds: number;
  serverTime: string;
}
```

前端以此为权威基准。在两次心跳间，可用本地单调时钟平滑显示；刷新、恢复、重连、换设备或心跳成功后必须重新以服务端值校准。

## 4. 页面事件顺序

1. 当前题真实渲染完成且页面可见时，发送 `ENTER`。批量预取题目不得发送 `ENTER`。
2. 保存成功的 `leaseId` 后，页面可见期间每 10 秒发送 `HEARTBEAT`。
3. 进入隐藏状态发送 `HIDDEN`；恢复可见后，完成当前题渲染再发送新的 `ENTER`。
4. 切题、暂停、交卷和组件卸载前尽力发送 `LEAVE`；即使请求失败，后端会在 20 秒后关闭租约。
5. 切题时先 `LEAVE` 旧题，再渲染新题并 `ENTER` 新题。

后端对同一会话只保留一个当前租约。新窗口或新设备 `ENTER` 会替换旧租约，不会重叠累计。

## 5. 倒计时和超时显示

前端由 `estimatedDurationSeconds` 与 `effectiveElapsedSeconds` 计算展示：

```ts
const remainingSeconds = Math.max(estimatedDurationSeconds - effectiveElapsedSeconds, 0);
const overtimeSeconds = Math.max(effectiveElapsedSeconds - estimatedDurationSeconds, 0);
```

- `remainingSeconds > 0`：显示剩余时间倒计时。
- 相等时：显示“超时 00:00”。
- 超过后：显示“超时 00:01、00:02 ……”的正向计时。
- 不显示负数，不自动交卷。
- 页面隐藏和暂停时停止本地动画；重新获得租约后重新校准。

## 6. 异常与 mock

- 20 秒无有效心跳：后端保留此前确认时间，但该题时间证据失效；前端重新进入后取得新租约。
- 401/403：沿用全局登录/无权限处理。
- `DIAGNOSTIC_SESSION_NOT_FOUND`：重新查询 onboarding。
- `DIAGNOSTIC_STATE_CONFLICT`：按 `nextAction` 分流。
- `DIAGNOSTIC_IDEMPOTENCY_CONFLICT`：停止自动重试。
- `REPLACED`：停止旧页面计时，提示“诊断已在其他窗口或设备继续”。

学生端需要在 `diagnostics.ts` 增加 `sendDiagnosticTimerEvent()`、请求/响应类型，并在 mock 模式下同步补齐 mock 实现。

## 7. 联调验收

- 真实呈现后才开始累计；预取不计时。
- 可见页面每 10 秒心跳；隐藏、切题、暂停和交卷不再累计。
- 断网超过 20 秒后恢复，断网部分不计入有效时间，且不产生时间风险。
- 两个标签页同会话不重复累计；旧标签接收 `REPLACED`。
- 刷新、重连、换设备后时间显示被服务端值校准。
- 倒计时归零后切换为正向超时计时，用户仍可继续答题或主动交卷。
