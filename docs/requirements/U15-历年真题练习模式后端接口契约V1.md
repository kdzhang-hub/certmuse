```yaml
document_version: 1.1

```

## 1. 目标与边界

本契约只补齐学生端“历年真题”的**练习模式**。它采用与知识点练习 U09 一致的做题思路和交互方式：逐题提交、即时反馈、答题卡导航和随时结束。真题练习保留独立路由、VO、错误码和领域实现，不要求与知识点练习接口或内部实现完全相同。

唯一的题目来源差异是：知识点练习按知识点实时筛选并冻结题单；真题练习按用户选定的一个已发布 `PAST_PAPER` 题集修订，按原卷顺序冻结该卷题目。真题的年份、月份、科目、题集名称等展示信息由真题列表页已有读模型和路由查询参数提供，本答题接口不再增加只供展示的字段。

本契约包含：开始/恢复真题练习会话、进入会话、读取题目、逐题提交、即时反馈和结束练习。

本契约不包含：

- 真题列表、详情、预览、答案预览和正式考试模式；正式考试接口及页面保持不变。
- 知识点练习、每日任务、错题本、模拟考试、学习记录等页面或接口的改动。
- 限时、草稿、统一交卷、考试成绩、异步结果生成等正式考试行为。
- 多选 `CHOICE`、`CASE`、`ESSAY` 的练习作答；V1 只支持单选 `CHOICE`。含任意其他题型或选择模式的真题卷不提供练习入口，仍可按原有能力浏览或参加其正式考试。
- 数据库迁移。本功能必须只使用既有真题迁移已经提供的表、列、约束和索引。

## 2. 既有数据模型与复用边界

### 2.1 不新增数据库结构

实现只能使用下列既有关系，不新增表、列、索引或另一份“真题练习答题”数据：

| 用途 | 既有存储 | 约束口径 |
| --- | --- | --- |
| 真题及固定题集修订 | `cm_collection`、`cm_collection_revision`、既有题集题目关系 | 仅当前已发布、`collection_type='PAST_PAPER'` 的修订可开始。 |
| 会话与冻结题单 | `cm_learning_session`、`cm_session_question` | `session_type='past_paper_practice'`；`collection_revision_id` 非空；复用 `uk_cm_learning_session_active_past_paper_practice`。 |
| 已提交答案及判题 | `cm_question_attempt`、`cm_attempt_answer` | 仅在提交时写入；不得将未提交的页面选择写入草稿或答案表。 |
| 幂等回放 | `cm_idempotency_record` | 使用现有真题动作记录，不创建另一个幂等表。 |
| 错题和画像证据 | 既有错题派生逻辑、`cm_learning_evidence`、`cm_knowledge_profile` | 只从已提交的尝试派生；不将答案预览或未提交选择当作学习证据。 |

`cm_past_paper_draft`、`timing_mode`、`deadline_time`、`formal_attempt_no` 是正式考试专用能力；练习模式不得读取或写入它们。

### 2.2 真题练习会话冻结规则

创建会话时在单一事务中确定 `cm_collection_revision`，按该修订的原卷 `question_order` 升序写入完整 `cm_session_question` 快照。不得在后续读取、提交或结算时回查可变的题目、题集、知识点或答案内容。

每题须复用知识点练习的快照语义：

- `presentation_snapshot` 只含题面、`CHOICE` 选项、图片、`selectionMode` 和题目呈现所需元数据；绝不含答案、解析或评分事实。
- `grading_snapshot` 冻结答案、解析和选择规则；提交后只从该快照计算正误和返回解析。
- `knowledge_snapshot` 冻结当时有效的知识点关联；已提交答案才可据此写错题和画像证据。
- `evidence_group_key`、难度、科目、规则版本等字段遵循当前 `PastPaperService` 与既有学习证据约束；不得因本功能改写既有画像计算口径。

开始前校验整卷：题数大于零；题号恰好为连续且唯一的 `1..N`；每题快照源完整；每题均为 `selectionMode='single'` 的 `CHOICE`；选项标签非空且唯一；正确答案恰好一个并属于冻结选项。任一条件不满足时整卷不可练习，不能跳过坏题、不能创建部分题单。

同一用户、同一学习目标、同一真题修订只能有一个 `in_progress` 的 `past_paper_practice` 会话。不同真题修订可并存；练习会话与同卷正式考试会话可并存，二者互不覆盖。

## 3. 共同接口约定

### 3.1 响应、认证与权限

全部成功和业务失败响应使用 `R<T>`；真实 HTTP Status 必须等于 `R.code`。前端只能根据 `data.errorCode` 分支，不能匹配 `msg`。

所有本契约接口均要求已登录，且 Sa-Token 权限为：

```text
certmuse:student AND certmuse:assessment:past-paper:answer
```

用户 ID、当前学习目标、真题修订和题目可见性全部由服务端从登录态和路径资源确定；请求体不得传 `userId`、`goalId`、`sessionType`、答案、评分、题集修订快照或画像字段。

401/403 沿用认证授权兼容格式，仅承诺 `code`、`msg` 和 `data:null`。预期 4xx 不返回 `traceId`；未预期 500 返回安全文案、非空 `traceId`、空 `fieldErrors` 和 `details:null`。

```ts
interface PastPaperPracticeErrorVo {
  errorCode: string;
  retryable: boolean;
  traceId: string | null;
  fieldErrors: Array<{
    field: string;
    code: 'REQUIRED' | 'INVALID_FORMAT' | 'OUT_OF_RANGE';
    message: string;
  }>;
  details: { answerPath: string } | null;
}
```

所有 ID 都是十进制正整数字符串。时间（本契约无成功响应时间字段）如将来扩展，必须是 ISO-8601 UTC 字符串，客户端按 `Asia/Shanghai` 展示。

### 3.2 与知识点练习处理方式一致的独立读模型

以下成功响应结构是真题练习独立的冻结兼容边界。字段语义对齐知识点练习答题壳，使学生端可以复用组件和状态处理；前端可以定义独立的真题练习 API 类型。

```ts
type PracticeSessionStatus = 'IN_PROGRESS' | 'COMPLETED';
type PracticeNavigationState = 'SUBMITTED_CORRECT' | 'SUBMITTED_INCORRECT' | 'UNANSWERED';

interface StartPastPaperPracticeVo {
  sessionId: string;
  totalCount: number;
  answerPath: string;
}

interface PastPaperPracticeSessionVo {
  sessionId: string;
  sessionStatus: PracticeSessionStatus;
  totalCount: number;
  submittedCount: number;
  navigation: Array<{
    questionOrder: number;
    state: PracticeNavigationState;
  }>;
  nextAction: 'CONTINUE_PRACTICE' | 'RETURN_PAST_PAPERS';
  returnPath: string | null;
}

interface PastPaperPracticeItemVo {
  sessionId: string;
  questionOrder: number;
  totalCount: number;
  question: {
    questionType: 'CHOICE';
    stem: string;
    selectionMode: 'single';
    options: Array<{ label: string; content: string }>;
    images: Array<{ url: string; alt: string | null; sortOrder: number }>;
  };
  submission: null | {
    selectedOptionLabels: string[];
    correct: boolean;
    correctOptionLabels: string[];
    analysis: string | null;
  };
}

interface SubmitPastPaperPracticeItemVo {
  questionOrder: number;
  submittedCount: number;
  feedback: NonNullable<PastPaperPracticeItemVo['submission']>;
}

interface CompletePastPaperPracticeVo {
  sessionId: string;
  sessionStatus: 'COMPLETED';
  submittedCount: number;
  returnPath: '/learning/question-bank/past-papers';
}
```

`selectionMode` 固定为 `single`，并由开始时冻结的答案规则验证。答案仍以字符串数组 `answer.value` 表示，且必须恰好包含一个有效标签。

## 4. 接口定义

### 4.1 开始或恢复真题练习

```http
POST /api/assessment/past-papers/{collectionId}/practice-sessions
Content-Type: application/json
X-Request-Id: 0f7cd9a8-4b29-4ba5-b202-b7fb5aac85dd
```

| 位置 | 字段 | 必填 | 规则 |
| --- | --- | ---: | --- |
| path | `collectionId` | 是 | 十进制正整数；必须是当前可见、已发布的 `PAST_PAPER` 题集。 |
| header | `X-Request-Id` | 是 | 标准 UUID，服务端按小写 36 字符规范化。 |
| body | `expectedRevisionId` | 是 | 当前列表/详情读模型返回的十进制正整数修订 ID。 |
| body | `expectedGoalVersion` | 是 | 当前学习目标 `rowVersion` 的非负整数。 |

```json
{
  "expectedRevisionId": "900000000000000401",
  "expectedGoalVersion": 6
}
```

服务端必须校验当前有效学习目标、资格范围、目标版本、题集当前修订和整卷可练性。成功时创建或恢复该用户、该目标、该修订的 `past_paper_practice` 会话；`answerPath` 固定为：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "sessionId": "900000000000000801",
    "totalCount": 75,
    "answerPath": "/learning/session/past-paper-practice?sessionId=900000000000000801"
  }
}
```

同一规范化载荷和同一请求号重试必须回放该成功响应，不能再次创建会话。请求号与其他用户、动作或载荷冲突时必须失败。若活动会话由另一个请求创建，服务端返回该会话的相同结构成功响应（而不是 `409`），使“开始练习”和“继续练习”共享同一前端入口。

### 4.2 进入会话和读取答题卡

```http
GET /api/assessment/past-papers/practice-sessions/{sessionId}
```

只读取当前用户的 `past_paper_practice` 会话。会话创建成功后已处于 `in_progress`；已完成会话仍返回结果状态，不得恢复作答。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "sessionId": "900000000000000801",
    "sessionStatus": "IN_PROGRESS",
    "totalCount": 75,
    "submittedCount": 2,
    "navigation": [
      { "questionOrder": 1, "state": "SUBMITTED_CORRECT" },
      { "questionOrder": 2, "state": "SUBMITTED_INCORRECT" },
      { "questionOrder": 3, "state": "UNANSWERED" }
    ],
    "nextAction": "CONTINUE_PRACTICE",
    "returnPath": "/learning/question-bank/past-papers"
  }
}
```

`submittedCount` 只统计已有有效 `submitted` 尝试的题目数；`UNANSWERED` 不代表用户没有在浏览器中选择选项，只代表尚未提交。导航必须按 `questionOrder` 升序且包含完整冻结题单。

### 4.3 读取一题

```http
GET /api/assessment/past-papers/practice-sessions/{sessionId}/items/{questionOrder}
```

`questionOrder` 是 1 到会话 `totalCount` 的整数。未提交时 `submission:null`，只返回冻结题面；已提交时返回该次冻结答案计算出的反馈。不得返回其他用户答案、当前题库修订内容、草稿或考试模式信息。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "sessionId": "900000000000000801",
    "questionOrder": 2,
    "totalCount": 75,
    "question": {
      "questionType": "CHOICE",
      "stem": "……",
      "selectionMode": "single",
      "options": [
        { "label": "A", "content": "……" },
        { "label": "B", "content": "……" }
      ],
      "images": []
    },
    "submission": null
  }
}
```

### 4.4 提交一题并获得即时反馈

```http
POST /api/assessment/past-papers/practice-sessions/{sessionId}/items/{questionOrder}/submit
Content-Type: application/json
X-Request-Id: b66f2bd5-0933-4f41-a7ea-91a9f8bb5eb0
```

```ts
interface SubmitPastPaperPracticeItemRequest {
  answer: { value: string[] };
}
```

`answer.value` 必填且必须恰好包含一个非空的冻结选项标签；空数组、多个标签、重复标签或未知标签均使用 400 `PAST_PAPER_PRACTICE_REQUEST_INVALID` 拒绝。客户端不得提交 `correct`、`correctOptionLabels`、解析、分数或 `expectedSessionVersion`。

成功时在一个事务中写入尝试与答案、以冻结快照判题、派生错题及既有允许范围内的画像证据，然后返回即时反馈。任何一个写入或证据结算失败均回滚；不得出现“前端收到正确反馈但答案/错题/证据未落库”的部分成功。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "questionOrder": 2,
    "submittedCount": 2,
    "feedback": {
      "selectedOptionLabels": ["B"],
      "correct": false,
      "correctOptionLabels": ["A"],
      "analysis": "……"
    }
  }
}
```

重复提交同一题不能覆盖首次答案。相同请求号与相同载荷仅回放首次成功响应；题目已经由任意请求成功提交时，返回 `PAST_PAPER_PRACTICE_ITEM_ALREADY_SUBMITTED`，前端重新读取该题以展示权威反馈。

### 4.5 结束练习

```http
POST /api/assessment/past-papers/practice-sessions/{sessionId}/complete
X-Request-Id: d93269c9-5a7f-4859-ad2d-2a246ce40a5c
```

请求体为空。服务端原子将当前用户活动的 `past_paper_practice` 会话标记为完成；只保留已经提交题目的既有事实，未提交题目不创建尝试、答案、错题或学习证据。相同请求号必须回放成功，已完成会话的新的完成请求也返回同一完成收据。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "sessionId": "900000000000000801",
    "sessionStatus": "COMPLETED",
    "submittedCount": 58,
    "returnPath": "/learning/question-bank/past-papers"
  }
}
```

## 5. 失败响应

通用字段校验失败使用 HTTP 400、`errorCode='PAST_PAPER_PRACTICE_REQUEST_INVALID'`，`fieldErrors` 的 `field` 必须是请求 JSON camelCase 路径（请求头为 `X-Request-Id`）。示例：

```json
{
  "code": 400,
  "msg": "请求参数格式不正确",
  "data": {
    "errorCode": "PAST_PAPER_PRACTICE_REQUEST_INVALID",
    "retryable": false,
    "traceId": null,
    "fieldErrors": [
      { "field": "answer.value", "code": "INVALID_FORMAT", "message": "答案不符合本题选择规则" }
    ],
    "details": null
  }
}
```

| 接口 | HTTP / `R.code` | `errorCode` | 触发条件 | `retryable` | 前端行为 |
| --- | --- | --- | --- | ---: | --- |
| 全部 | 400 | `PAST_PAPER_PRACTICE_REQUEST_INVALID` | 路径 ID、请求头、请求体、选项数量或格式不合法。 | false | 按 `fieldErrors` 修正，不盲目重试。 |
| 开始 | 409 | `LEARNING_GOAL_NOT_ACTIVE` | 无当前有效学习目标。 | false | 返回学习目标设置。 |
| 开始 | 422 | `LEARNING_NOT_ALLOWED` | 目标、资格或学习批次门禁不允许。 | false | 展示服务端门禁。 |
| 开始 | 409 | `PAST_PAPER_GOAL_VERSION_CONFLICT` | `expectedGoalVersion` 已过期。 | true | 刷新真题列表和目标后重试。 |
| 开始 | 404 | `PAST_PAPER_NOT_FOUND` | 题集不存在、不可见、非当前已发布真题或不属于目标资格。 | false | 返回真题列表。 |
| 开始 | 409 | `PAST_PAPER_REVISION_CHANGED` | `expectedRevisionId` 与当前修订不一致。 | true | 刷新当前真题数据，不自动开始新修订。 |
| 开始 | 422 | `PAST_PAPER_PRACTICE_UNAVAILABLE` | 空卷、题号/快照不完整或题集含非 `CHOICE` 题。 | false | 保留浏览，禁用练习入口。 |
| 写操作 | 409 | `PAST_PAPER_PRACTICE_IDEMPOTENCY_CONFLICT` | 请求号被其他用户、动作或不同规范化载荷使用。 | false | 仅在新的用户操作生成新请求号。 |
| 会话/题目/写入 | 404 | `PAST_PAPER_PRACTICE_SESSION_NOT_FOUND` | 会话不存在、非本人或类型不是 `past_paper_practice`。 | false | 返回真题列表。 |
| 读取题目 | 404 | `PAST_PAPER_PRACTICE_ITEM_NOT_FOUND` | 题号不在冻结题单内。 | false | 重新读取会话导航。 |
| 提交/完成 | 409 | `PAST_PAPER_PRACTICE_SESSION_NOT_ACTIVE` | 会话已完成，不能再作答。 | false | 重读会话并展示完成状态。 |
| 提交 | 409 | `PAST_PAPER_PRACTICE_ITEM_ALREADY_SUBMITTED` | 该题已由本用户其他请求/设备提交。 | false | 重读当前题。 |
| 全部 | 500 | `PAST_PAPER_PRACTICE_SYSTEM_FAILURE` | 未预期的查询、快照、判题、结算或序列化失败。 | true | 保留本地未提交选择，展示 `traceId`，可稍后重试。 |

## 6. 幂等、并发与安全

开始、提交和完成操作均要求 `X-Request-Id`，保留期和响应回放沿用当前 `cm_idempotency_record` 规则。规范化载荷至少包含用户 ID、操作码、会话或题集修订 ID、题号（如适用）和请求体；用户 ID 只来自登录态。相同请求号但不同载荷永不覆盖原记录。

提交和完成必须锁定会话并验证归属与 `session_type`；会话行锁是同一会话写操作的串行化边界，并由数据库唯一约束和事务保证单题只产生一次有效提交。ID 不存在、非本人和会话类型不符统一使用 404，避免资源枚举。冻结图片对象引用通过既有图片服务转换为临时访问 URL，不属于回查可变题目内容。

日志可记录 `traceId`、请求号、用户 ID、会话 ID、题集修订 ID、题号、操作码、状态和稳定错误码；不得记录题面全文、选项全文、答案、解析、原始 JSON 快照、认证令牌或 Cookie。业务 4xx 不输出堆栈；500 在边界仅记录一次完整异常，并用同一 `traceId` 关联响应。

## 7. 验收用例

| 编号 | 前置与输入 | 可断言结果 |
| --- | --- | --- |
| PP-P-01 | 当前目标下的已发布纯单选真题卷，POST 开始。 | 200；创建 `past_paper_practice/in_progress`；题目按原卷顺序冻结；返回真题练习独立开始收据。 |
| PP-P-02 | 对 PP-P-01 的同一请求号和同一载荷重试。 | 200；会话 ID、题量和路径与首次完全一致；没有第二个会话。 |
| PP-P-03 | 同卷已有活动练习，使用新请求号开始。 | 200；返回原会话，不创建第二个活动练习；正式考试会话不受影响。 |
| PP-P-04 | 真题修订变更后，以旧 `expectedRevisionId` 开始。 | 409 `PAST_PAPER_REVISION_CHANGED`；不创建会话。 |
| PP-P-05 | 真题卷含 `CASE` 或 `ESSAY`。 | 422 `PAST_PAPER_PRACTICE_UNAVAILABLE`；不创建部分题单。 |
| PP-P-06 | 首次 GET 活动会话。 | 200；会话保持 `in_progress`；导航完整并采用正确、错误、未提交三种状态。 |
| PP-P-07 | 读取未提交题目。 | 200；`submission:null`；响应不含答案、解析、评分或草稿。 |
| PP-P-08 | 提交合法单选答案。 | 200；返回即时反馈和 `submittedCount`；已提交事实派生既有错题/画像。 |
| PP-P-08A | 提交空、多个、重复或未知选项标签。 | 400 `PAST_PAPER_PRACTICE_REQUEST_INVALID`；不创建尝试或证据。 |
| PP-P-09 | 对已提交题目再次提交。 | 409 `PAST_PAPER_PRACTICE_ITEM_ALREADY_SUBMITTED`；首次答案不可被覆盖。 |
| PP-P-10 | 结束时有未提交题。 | 200；会话完成；未提交题没有尝试、错题或证据；返回真题列表路径。 |
| PP-P-11 | 非本人访问会话或把考试会话 ID 传给练习接口。 | 404 `PAST_PAPER_PRACTICE_SESSION_NOT_FOUND`；不泄露会话类型或归属。 |
| PP-P-12 | 调用所有现有知识点练习、真题正式考试路由。 | 行为、响应结构和页面内容均无改动。 |
