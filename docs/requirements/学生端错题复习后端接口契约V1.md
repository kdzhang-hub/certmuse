# 学生端错题复习后端接口契约 V1

> 状态：待实施。日期：2026-08-18。
> 路由前缀：`/api/learning/mistakes`。
> 本契约以“待订正 / 已订正”两状态为准，替代学生端旧 Mock 中的“待分析、待验证、已完成”状态。

## 1. 目标与边界

本版提供当前有效学习目标下的错题列表、错题详情、原题重做会话及选择题同步判分。

闭环固定为：正式作答错误或跳过产生错误记录 → 显示为待订正 → 在错题页重做原题 → 答对后显示为已订正。记录不物理删除；后续在其他正式场景再次答错时，产生新的错误事实，并重新显示为待订正。

本版不包含：同知识点新题验证、间隔复习、提醒、错因人工填写、案例/论文题订正、题目改判联动和错题订正对学习画像的额外结算。`cm_verification_record`、`cm_profile_settlement(settlement_type='correction')`在本版不写入；页面“已订正”不等于画像“已掌握”。

物理数据继续复用现有表：

- 错误事实：`cm_error_record`，通过`attempt_id → cm_question_attempt → cm_session_question`还原题目、来源和时间；
- 原作答：`cm_attempt_answer`；
- 题目及答案解析：`cm_session_question`的冻结`presentation_snapshot`、`grading_snapshot`；
- 重做会话与作答：`cm_learning_session(session_type='correction')`、`cm_session_question`、`cm_question_attempt`、`cm_attempt_answer`；
- 成功订正事实：`cm_correction_record`。

列表以`question_id`聚合；同一用户、同一目标、同一原题的多条`cm_error_record`在学生端只显示一行。该聚合是查询投影，不新增错题主表。

## 2. 公共约定

所有接口要求已登录的学习入口账号，且权限为`certmuse:student`与对应错题权限的 AND：

| 能力 | 权限 |
|---|---|
| 列表、详情、会话读取 | `certmuse:learning:mistake:query` |
| 创建会话、提交、结束 | `certmuse:learning:mistake:correct` |

服务端从登录上下文确定`userId`，并查询该用户唯一`active`目标；客户端不得传递或覆盖`userId`、`goalId`、题目答案、题目版本、状态或画像分数。

- 雪花 ID 一律以十进制字符串传输；时间为带时区 ISO-8601；真实 HTTP Status 等于`R.code`。
- 所有 POST 必须带`X-Request-Id`：标准 UUID，服务端标准化为小写 36 字符串；同一用户、同一动作、同一规范化载荷在 24 小时内幂等回放。
- 401/403沿用认证授权兼容格式，只承诺`code/msg/data:null`。预期 4xx 返回稳定的`data.errorCode`；5xx返回安全文案和非空`traceId`。
- 所有题面、选项、正确答案、解析均来自冻结快照，不得因题库当前修订而改变历史展示或订正判分。

学生端状态映射：

| API 状态 | `cm_error_record`条件 | 页面文案 |
|---|---|---|
| `PENDING_CORRECTION` | 此题存在至少一条`unresolved`或`correcting`错误记录 | 待订正 |
| `CORRECTED` | 此题没有待订正记录，且至少一条记录以`status='closed'`、`status_reason='correction_correct'`关闭 | 已订正 |

## 3. 接口定义

### 3.1 查询错题列表

`GET /api/learning/mistakes`

查询参数：

| 参数 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| `keyword` | string | 否 | 去首尾空格后 1–100 字符；匹配题干摘要或知识点名称 |
| `status` | enum | 否 | `PENDING_CORRECTION`或`CORRECTED`；默认`PENDING_CORRECTION` |
| `knowledgePointId` | string | 否 | 十进制正整数，过滤关联叶子知识点 |
| `source` | enum | 否 | `INITIAL_DIAGNOSIS`、`DAILY_TASK`、`SELF_PRACTICE`、`PAST_PAPER`、`SIMULATION` |
| `minWrongCount` | integer | 否 | 仅允许`2`或`3` |
| `pageNum` | integer | 否 | 默认 1，最小 1 |
| `pageSize` | integer | 否 | 默认 10，范围 1–100 |

固定按`lastWrongAt DESC,questionId ASC`分页。`total`是聚合后的题目数，不是错误记录行数。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "rows": [{
      "questionId": "900000000000000101",
      "title": "管道—过滤器架构风格的适用场景",
      "knowledgePoints": [{"id":"900000000000000301","name":"架构风格"}],
      "status": "PENDING_CORRECTION",
      "wrongCount": 2,
      "skipCount": 0,
      "sources": ["SELF_PRACTICE", "DAILY_TASK"],
      "lastWrongAt": "2026-08-18T09:12:00+08:00",
      "summary": "需要区分数据流处理与需要复杂共享状态的场景。",
      "canCorrect": true,
      "blockReason": null
    }],
    "total": 1
  }
}
```

`wrongCount`统计该`questionId`在当前目标的非跳过错误作答次数；`skipCount`统计`is_skipped=true`次数；`sources`按首次出现时间倒序去重。`canCorrect=false`时，`blockReason`为`UNSUPPORTED_QUESTION_TYPE`或`QUESTION_UNAVAILABLE`；该行仍可查看历史但不得被创建重做会话。

### 3.2 查询错题详情

`GET /api/learning/mistakes/{questionId}`

路径参数必须为十进制正整数。返回当前目标中该题最新一次错误作答的冻结题面、原答案与解析；历史按`occurredAt DESC,attemptId DESC`排序。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "questionId": "900000000000000101",
    "title": "管道—过滤器架构风格的适用场景",
    "status": "PENDING_CORRECTION",
    "wrongCount": 2,
    "skipCount": 0,
    "sources": ["SELF_PRACTICE", "DAILY_TASK"],
    "lastWrongAt": "2026-08-18T09:12:00+08:00",
    "question": {
      "questionType": "CHOICE",
      "stem": "在需要将一系列独立数据处理步骤按顺序组合的场景中，优先考虑哪种架构风格？",
      "selectionMode": "single",
      "options": [{"label":"A","content":"管道—过滤器风格"}],
      "images": []
    },
    "originalAnswer": ["B"],
    "correctAnswer": ["A"],
    "analysis": "关键在于独立处理步骤与顺序组合。",
    "history": [{
      "attemptId": "900000000000000701",
      "occurredAt": "2026-08-18T09:12:00+08:00",
      "source": "SELF_PRACTICE",
      "answer": ["B"],
      "skipped": false
    }],
    "canCorrect": true,
    "blockReason": null
  }
}
```

`QUESTION_NOT_FOUND`统一表示题目不存在、不属于当前用户目标或当前用户无权查看，避免泄露其他用户学习数据。

### 3.3 创建批量原题重做会话

`POST /api/learning/mistakes/correction-sessions`

```http
X-Request-Id: 3e52599b-1dde-4f56-a1b7-69987a83f934
Content-Type: application/json
```

```json
{"questionIds":["900000000000000101","900000000000000102"]}
```

`questionIds`为 1–20 个去重后的十进制正整数，按请求数组顺序冻结。每个题必须在当前目标处于`PENDING_CORRECTION`且`canCorrect=true`；任一题不满足时整个请求失败，不创建部分会话。

服务端锁定当前目标和既有活动`correction`会话。存在活动会话时返回409 `MISTAKE_CORRECTION_IN_PROGRESS`及`details.sessionId`，不创建第二个会话。成功时创建`cm_learning_session(session_type='correction',status='created')`及每题一条`cm_session_question`，复制原错误作答关联的题目版本和全部冻结快照；`hint_allowed=false`，不预创建`cm_question_attempt`。

```json
{"code":200,"msg":"操作成功","data":{"sessionId":"900000000000000801","totalCount":2,"answerPath":"/learning/session/correction?sessionId=900000000000000801"}}
```

### 3.4 读取重做会话与题目

```text
GET /api/learning/mistakes/correction-sessions/{sessionId}
GET /api/learning/mistakes/correction-sessions/{sessionId}/items/{questionOrder}
```

首次读取`created`会话时原子转为`in_progress`。会话只允许当前所有者读取，且必须是`session_type='correction'`；否则返回404 `MISTAKE_CORRECTION_SESSION_NOT_FOUND`。题目读取和答题卡字段与`U08-U09-知识点练习后端接口契约`的选择题读模型一致，但标题固定为“错题订正”，`returnPath`固定为`/learning/mistakes`。

题目未提交前不得返回本会话的正确答案与解析；详情页的历史解析不构成订正会话的答案泄露。

### 3.5 提交重做答案

`POST /api/learning/mistakes/correction-sessions/{sessionId}/items/{questionOrder}/submit`

```json
{"answer":{"value":["A"]}}
```

答案只支持`CHOICE`：单选必须恰含一个冻结选项；多选必须为非空、去重后的冻结选项集合。服务端只按本会话冻结`grading_snapshot`判分。

提交成功后，在同一事务内：

1. 为当前`cm_session_question`创建唯一`attempt_no=1`的`cm_question_attempt`和`cm_attempt_answer`，答案使用版本化 JSON；
2. 答错时保留`cm_error_record`原状态，不创建新的错误记录；
3. 答对时，锁定当前目标下同一`question_id`全部待订正`cm_error_record`，分别写入一条`cm_correction_record(status='success',score_rate=1)`，并更新这些错误记录为`closed`、`status_reason='correction_correct'`、`resolved_time=now()`；
4. 不写`cm_verification_record`、`cm_profile_settlement`或`cm_learning_evidence`。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "questionOrder": 1,
    "submittedCount": 1,
    "feedback": {
      "selectedOptionLabels": ["A"],
      "correct": true,
      "correctOptionLabels": ["A"],
      "analysis": "关键在于独立处理步骤与顺序组合。",
      "mistakeStatus": "CORRECTED"
    }
  }
}
```

提交同一题两次返回409 `MISTAKE_CORRECTION_ITEM_ALREADY_SUBMITTED`；答错后用户可结束当前会话，并通过新会话再次重做。已关闭记录不再被创建会话选中；将来新的正式作答再次错题会新增错误记录，因此自然恢复为`PENDING_CORRECTION`。

### 3.6 结束会话

`POST /api/learning/mistakes/correction-sessions/{sessionId}/complete`，无请求体，`X-Request-Id`必填。

结束时未提交题不产生任何作答或状态变化。服务端将会话从`in_progress`推进为`submitted → settling → completed`，返回：

```json
{"code":200,"msg":"操作成功","data":{"sessionId":"900000000000000801","sessionStatus":"COMPLETED","submittedCount":1,"returnPath":"/learning/mistakes"}}
```

## 4. 失败响应

除401/403外，错误格式如下：

```json
{"code":409,"msg":"当前错题订正状态不可继续","data":{"errorCode":"MISTAKE_CORRECTION_IN_PROGRESS","retryable":false,"traceId":null,"fieldErrors":[],"details":{"sessionId":"900000000000000801"}}}
```

| HTTP | errorCode | 条件 | 前端行为 |
|---:|---|---|---|
| 400 | `MISTAKE_REQUEST_INVALID` | 查询、路径、答案或请求号不合法 | 展示字段错误，不发起重试 |
| 404 | `QUESTION_NOT_FOUND` | 题目不在当前用户当前目标内 | 返回列表并刷新 |
| 404 | `MISTAKE_CORRECTION_SESSION_NOT_FOUND` | 会话不存在、非本人或类型不符 | 返回错题列表 |
| 409 | `MISTAKE_IDEMPOTENCY_CONFLICT` | 请求号与动作或载荷冲突 | 生成新请求号后按最新页面重试 |
| 409 | `MISTAKE_CORRECTION_IN_PROGRESS` | 当前目标已有活动订正会话 | 跳转`details.sessionId`继续 |
| 409 | `MISTAKE_CORRECTION_ITEM_ALREADY_SUBMITTED` | 本会话题目重复提交 | 刷新题目结果 |
| 409 | `MISTAKE_CORRECTION_SESSION_NOT_ACTIVE` | 会话已结束或失效 | 返回列表并刷新 |
| 422 | `LEARNING_GOAL_NOT_ACTIVE` | 无唯一活动学习目标 | 跳转目标设置 |
| 422 | `MISTAKE_NOT_PENDING_CORRECTION` | 所选题没有待订正错误记录 | 刷新列表 |
| 422 | `MISTAKE_CORRECTION_UNSUPPORTED_TYPE` | 所选题不是可同步判分的选择题 | 展示原因，不创建会话 |
| 422 | `MISTAKE_QUESTION_UNAVAILABLE` | 原题快照不完整或内容不可用 | 展示原因，不创建会话 |
| 500 | `MISTAKE_OPERATION_FAILED` | 未预期异常 | 显示安全失败提示及 traceId |

## 5. 幂等、并发与安全

- 创建、提交、结束分别使用`CREATE_MISTAKE_CORRECTION_SESSION`、`SUBMIT_MISTAKE_CORRECTION_ITEM`、`COMPLETE_MISTAKE_CORRECTION_SESSION`作为`cm_idempotency_record.action_code`；请求号与规范化载荷冲突返回409。
- 创建锁顺序为当前目标 → 当前活动订正会话 → 所有待关闭错误记录，错误记录按 ID 升序锁定，避免批量勾选死锁。
- 提交与结束都在幂等校验后锁定同一会话；结束先完成时，之后的提交不得新增作答。
- 查询、详情、会话读取和所有写入都必须以`user_id=当前登录用户`和当前`goal_id`限制；不得只按题目 ID 或会话 ID 查询。
- 操作日志不得保存题干、选项、答案、解析、完整请求体或幂等响应体；只可记录用户、目标、会话、题目数量、请求号、结果码和 traceId。

## 6. 验收用例

1. 同一题在当前目标下两次答错，列表只显示一行，`wrongCount=2`，最新时间正确。
2. 默认列表只返回`PENDING_CORRECTION`；筛选`CORRECTED`后能查看已订正历史，记录未被删除。
3. 批量选择两道待订正选择题，创建一份包含两道冻结原题的`correction`会话。
4. 重做答错后，列表仍显示待订正；答对后，同题全部待订正错误记录关闭并从默认列表消失。
5. 一题关联多个叶子知识点时，答对后每条待订正错误记录都有成功订正事实，但列表仍只有一行。
6. 已订正题在后续正式自主练习再次答错时，出现新的错误记录并重新显示待订正。
7. 选择案例或论文题创建会话返回`MISTAKE_CORRECTION_UNSUPPORTED_TYPE`，不创建任何会话、作答或订正记录。
8. 同一`X-Request-Id`重试创建、提交或结束时回放首次成功结果；不同载荷冲突不产生重复会话、作答或关闭状态。
