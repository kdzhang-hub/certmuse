# 学习记录：统一考试历史后端改造方案

> 契约版本：V1.0。状态：待实施。日期：2026-08-20。  
> 范围：仅改造学生端学习记录的后端只读查询接口；不改变考试、评分、画像或错题事实写入。  
> 对接前端：`web/student/src/views/student/history/index.vue`

## 1. 改造目标

将原“模拟试卷历史”升级为按单场已完成考试展示的“考试历史”，纳入：

| 前端考试类型 | 学习会话类型 | 报告类型 | 是否纳入 |
|---|---|---|---|
| `INITIAL_DIAGNOSIS` | `initial_diagnosis` | `initial_diagnosis` | 是 |
| `PAST_PAPER` | `past_paper_exam` | `past_paper_exam` | 是 |
| `SIMULATION` | `simulation` | `simulation` | 是 |
| - | `past_paper_practice` | - | 否，属于练习，应留在题目历史 |
| - | 每日任务、知识点练习、订正、验证 | - | 否，属于题目历史 |

未交卷、草稿、取消、无效或不属于当前用户与目标的会话，不得出现在考试历史中。完成资格固定为：首次诊断的 `submitted_time` 非空且状态为 `settling` 或 `completed`；历年真题考试和模拟考试均要求状态为 `completed`、`settled_time` 非空。

现有模拟历史已经具备真实的会话、报告、时长、修订和逐题查询能力。本次不重做考试事实，而是将其扩展为包含首次诊断、历年真题考试和模拟考试的统一只读聚合。

## 2. 路由调整

前端已切换为：

```text
GET /api/learning/history/exams
GET /api/learning/history/exams/{sessionId}
```

当前模拟专用接口：

```text
GET /api/learning/history/simulations
GET /api/learning/history/simulations/{collectionId}
```

后端应新增 `exams` 接口。旧接口可在前端稳定后删除；如需兼容旧客户端，可保留并标记废弃，但不得用新“单场考试”响应替换旧“逻辑模拟卷聚合”语义。

权限保持：

```text
certmuse:student AND certmuse:learning:history:query
```

身份与所有权只从登录态、`goalId` 和持久化记录判断，客户端不得传 `userId`。

两个接口均为 `GET`，不需要请求体或 `X-Request-Id`，也不得写入任何学习事实。真实 HTTP Status 必须等于响应中的 `code`；时间使用带时区 ISO-8601 字符串，业务时区固定为 `Asia/Shanghai`。

## 3. 接口契约

### 3.1 考试历史列表

```text
GET /api/learning/history/exams
```

| 参数 | 必填 | 规则 |
|---|---:|---|
| `goalId` | 否 | 当前用户拥有的目标；未传时使用唯一活动目标。 |
| `examType` | 否 | `INITIAL_DIAGNOSIS`、`PAST_PAPER`、`SIMULATION`。 |
| `completedFrom` | 否 | `YYYY-MM-DD`，按 `Asia/Shanghai` 过滤。 |
| `completedTo` | 否 | `YYYY-MM-DD`，按 `Asia/Shanghai` 过滤。 |
| `pageNum` | 否 | 默认 1，范围 1–10000。 |
| `pageSize` | 否 | 默认 10，范围 1–100。 |

固定排序为 `completedAt DESC, sessionId DESC`。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "rows": [{
      "sessionId": "9001",
      "examType": "PAST_PAPER",
      "title": "2025年系统架构设计师上午真题",
      "subject": {"id": "101", "name": "综合知识"},
      "completedAt": "2026-08-20T10:00:00+08:00",
      "result": {"reportStatus": "AVAILABLE", "score": "45", "maxScore": "75", "scoreRate": 0.6},
      "durationSeconds": 6200,
      "durationLimitSeconds": 7200,
      "durationStatus": "AVAILABLE"
    }],
    "total": 1
  }
}
```


`sessionId` 是唯一入口；详情不按模拟卷 `collectionId` 聚合，以便三类考试使用同一个接口。

## 4. 三类考试的数据规则

### 4.1 首次诊断

- 会话类型为 `initial_diagnosis`，标题固定为“首次诊断”。
- 报告读取 `cm_assessment_report(report_type='initial_diagnosis')`。
- 已交卷但异步报告仍在生成时，记录可见，`reportStatus=PROCESSING`，分数字段均为 `null`。
- 报告失败时，记录可见，`reportStatus=FAILED`，分数字段均为 `null`。
- 首次诊断可能跨科目；不得任取一个科目作为代表，统一返回 `subject=null`。

### 4.2 历年真题考试

- 只读取 `past_paper_exam`，不得读取 `past_paper_practice`。
- 标题读取本次会话关联的冻结题集修订名称，不读取当前题集名称。
- 报告读取 `cm_assessment_report(report_type='past_paper_exam')`。
- 单科卷返回冻结科目；多科卷返回 `subject=null`。

### 4.3 模拟考试

- 只读取 `simulation`。
- 复用当前模拟历史的已完成会话、报告、时长快照和逐题结果规则。
- 新页面按 `sessionId` 一场一行展示；不再按逻辑模拟卷聚合或进行跨修订比较。

## 5. 报告、时长与题目规则

报告状态固定为：

```text
AVAILABLE | PROCESSING | FAILED | UNAVAILABLE
```

仅 `AVAILABLE` 可返回 `score`、`maxScore`、`scoreRate`，其他状态下三者必须均为 `null`。

正式考试时长的冻结口径：

```text
durationLimitSeconds = duration_seconds_snapshot
durationSeconds = min(submitted_time, deadline_time) - started_time
```

只有开始、提交、截止、时长快照均存在，时长为正，截止时间等于开始时间加冻结时长，且提交不早于开始时，才返回 `durationStatus=AVAILABLE`。否则三个时长字段按以下规则返回：

```json
{"durationSeconds": null, "durationLimitSeconds": null, "durationStatus": "UNAVAILABLE"}
```

逐题详情只读取 `cm_session_question` 的 `presentation_snapshot`、`knowledge_snapshot`、作答和评分事实；不得回查当前题库，避免题目修订或下架改写历史。

## 6. 实现结构

### 6.1 Controller 与 Service

在 `LearningHistoryController` 新增：

```java
@GetMapping("/exams")
R<HistoryExamPageVo> exams(@ModelAttribute HistoryExamQueryBo query)

@GetMapping("/exams/{sessionId}")
R<HistoryExamDetailVo> exam(@PathVariable String sessionId,
                            @RequestParam(required = false) String goalId)
```

在 `LearningHistoryService` 与实现类新增：

```java
HistoryExamPageVo exams(long userId, HistoryExamQueryBo query);
HistoryExamDetailVo exam(long userId, String sessionId, String goalId);
```

### 6.2 新模型

新增建议：

```text
HistoryExamQueryBo
HistoryExamPageVo
HistoryExamRowVo
HistoryExamDetailVo
HistoryExamResultVo
HistoryExamRow
HistoryExamQuestionRow
```

字段必须与学生端的 `HistoryExamRow`、`HistoryExamDetail` 对齐。

### 6.3 Mapper

在 `LearningHistoryMapper.xml` 以公共 CTE 联合三类会话：

```sql
exam_facts as (
  select ... from initial_diagnosis ...
  union all
  select ... from past_paper_exam ...
  union all
  select ... from simulation ...
)
```

公共投影列：

```text
session_id
exam_type
title
subject_id / subject_name
completed_at
report_status
score / max_score / score_rate
duration_seconds / duration_limit_seconds / duration_status
```

详情查询必须同时限制：`session_id + user_id + goal_id + 允许的 session_type + 已完成状态`。

## 7. 复用、数据边界与错误处理

复用现有模拟历史中的目标范围校验、分页和日期校验、报告状态转换、冻结时长计算、题面摘要、逐题结果和订正状态逻辑。不要把三类 SQL 结果拼成无类型 Map；使用专用 Row、VO 与 Mapper 方法。

本次不新增事实表、不修改开考/交卷/评分/画像/错题写入，也不需要新的数据库迁移。当前数据库已具备 `cm_learning_session` 的 `collection_revision_id`、`started_time`、`submitted_time`、`settled_time`、`duration_seconds_snapshot`、`deadline_time`，`cm_assessment_report` 的 `report_type`、`status`、分数字段和生成时间，以及 `cm_session_question` 的冻结题面、知识点和难度快照。实施前仍须在目标环境验证初诊、模拟和真题的既有迁移均已执行。

| 场景 | 状态码 | 错误码 |
|---|---:|---|
| 无活动目标且未传 `goalId` | 422 | `HISTORY_GOAL_REQUIRED` |
| 参数、分页或日期范围错误 | 400 | `HISTORY_REQUEST_INVALID` |
| 会话不存在、越权、跨目标、未完成或类型不支持 | 404 | `HISTORY_EXAM_NOT_FOUND` |
| 快照、报告、评分或时长事实矛盾 | 500 | `HISTORY_READ_FAILED` |

预期业务失败使用统一 `R<T>` 错误载荷：

```json
{
  "code": 404,
  "msg": "考试历史不存在",
  "data": {
    "errorCode": "HISTORY_EXAM_NOT_FOUND",
    "retryable": false,
    "traceId": null,
    "fieldErrors": [],
    "details": null
  }
}
```

`HISTORY_REQUEST_INVALID` 的 `fieldErrors` 使用 camelCase 字段名和 `REQUIRED`、`INVALID_FORMAT` 或 `OUT_OF_RANGE`；400、404、422 的 `traceId=null`。`HISTORY_READ_FAILED` 为 500，必须提供安全文案、非空 `traceId`，并只在服务端记录一次完整异常。401/403 复用认证兼容格式，仅承诺 `code/msg` 且 `data=null`。

不得通过响应区分“会话不存在”和“非本人会话”；不得返回原始主观题答案、正确答案、解析、内部评分过程或数据库错误细节。

## 8. 安全与可观测性

- 所有列表与详情 SQL 必须同时限制 `user_id` 与 `goal_id`；详情还必须限制允许的 `session_type` 与完成资格。
- 返回题目时仅返回冻结题干摘要；案例、论文等主观题不返回原始作答、参考答案或评分内部信息。
- 访问日志可记录当前用户 ID、目标 ID、`sessionId`、`examType`、分页参数和 `traceId`，不得记录答案 JSON、快照全文或报告 JSON。
- 客户端错误只按稳定的 `data.errorCode` 分支，不得解析本地化 `msg`。

## 9. 测试与验收

1. 三类考试各一场，列表返回三行，按完成时间倒序。
2. 分别按三种 `examType` 筛选，只返回对应会话。
3. `past_paper_practice` 不出现在考试历史。
4. 首次诊断报告处理中，记录存在、状态为 `PROCESSING`、分数字段为空。
5. 非本人或跨目标 `sessionId` 返回统一 `HISTORY_EXAM_NOT_FOUND`。
6. 三类详情均从冻结快照读取题干、题型、难度和结果，不受当前题库变更影响。
7. 时长快照、截止时间或提交时间不合法时，返回 `durationStatus=UNAVAILABLE`，不估算。
8. 新增 PostgreSQL 集成测试，真实执行三类联合 Mapper 查询和详情查询；不能只做 XML 文本断言。
9. 运行现有学习记录单元测试、Mapper XML 测试和新增集成测试。

| 用例 | 输入 | 可断言结果 |
|---|---|---|
| 正常列表 | 当前用户有三类完成考试 | 200；三行按 `completedAt DESC, sessionId DESC` 排序。 |
| 类型筛选 | `examType=PAST_PAPER` | 200；只返回 `past_paper_exam`。 |
| 日期反向 | `completedFrom` 晚于 `completedTo` | 400 `HISTORY_REQUEST_INVALID`；字段错误指向 `completedFrom`。 |
| 无活动目标 | 未传 `goalId` 且无唯一活动目标 | 422 `HISTORY_GOAL_REQUIRED`。 |
| 越权详情 | 他人或其他目标的 `sessionId` | 404 `HISTORY_EXAM_NOT_FOUND`，不泄露存在性。 |
| 初诊处理中 | `settling` 初诊会话且没有可用报告 | 200；`PROCESSING`，三项分数为 `null`。 |
| 数据异常 | 形式考试冻结时长事实不合法 | 200；时长为 `UNAVAILABLE`；若快照、评分或报告内部矛盾则 500 `HISTORY_READ_FAILED`。 |
