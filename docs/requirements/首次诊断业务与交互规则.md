# CertMuse 首次诊断业务与交互规则 V1.0

> 适用对象：产品、交互、前端、后端与测试  
> 文档性质：首次诊断业务与交互基线，不描述具体技术实现  
> 本期范围：不少于 10 题的真实诊断会话、中断恢复、交卷、评分状态、诊断报告与初始画像

## 1. 目标与范围

用户保存有效学习目标后，需要完成一次不少于 10 题的首次诊断。诊断用于了解用户当前基础，并生成诊断报告和初始学习画像。

本流程必须满足以下业务结果：

1. 用户可以中途中断，并在再次进入时恢复原诊断和已保存进度。
2. 用户交卷后不能修改答案。
3. 连续点击、刷新、网络重试或换设备操作，不得产生重复交卷和重复结算。
4. 用户能够清楚看到答案保存、交卷和结果处理状态。
5. 诊断报告和初始画像必须来自用户本次真实作答，不得使用演示、随机或默认数据。
6. 结果处理失败时保留答卷，用户不需要重新完成本次诊断。

完整流程为：

> 设置学习目标 → 查看诊断说明 → 开始诊断 → 保存或恢复进度 → 确认交卷 → 等待评分与结果生成 → 查看诊断报告和初始画像 → 进入学习首页

## 2. 核心业务状态

| 用户状态 | 用户进入后的页面 | 可执行操作 |
|---|---|---|
| 无有效学习目标 | 学习目标设置页 | 设置并保存学习目标 |
| 已有目标、诊断未开始 | 首次诊断说明页 | 开始诊断、暂时离开 |
| 诊断进行中 | 原诊断答题页 | 继续作答、修改答案、暂停、交卷 |
| 已确认交卷 | 结果处理页 | 查看处理状态、稍后查看 |
| 结果处理失败 | 结果异常页 | 重新生成结果、稍后查看、联系支持 |
| 报告和画像已生成 | 诊断报告页 | 查看报告、查看画像、进入学习首页 |

首次学习流程未完成时，用户再次登录应恢复当前步骤，不得绕过未完成的首次诊断直接进入正常学习首页。

## 3. 首次诊断说明

### 3.1 页面信息

开始诊断前，应明确展示：

- 本次诊断的实际题量（不少于 10 题）。
- 预计完成时间。
- 本次诊断对应的学习目标或考试资格。
- 诊断用于了解当前基础，不代表正式考试成绩。
- 诊断过程中不展示答案、解析、提示和对错。
- 可以中途暂停或退出，下次继续。
- 交卷后不能修改答案。
- 完成后将生成诊断报告和初始学习画像。

### 3.2 开始诊断

用户点击“开始诊断”后进入第 1 题。

- 用户此前从未开始诊断时，进入一份新的诊断。
- 用户已有未完成诊断时，应恢复原诊断，不得重新生成另一份诊断。
- 用户连续点击“开始诊断”，只能进入同一份诊断。
- 用户可以选择“暂时不做”；再次登录后仍应进入首次诊断流程。

### 3.3 已有未完成诊断

再次进入时，应明确提示：

> 你有一份未完成的首次诊断，当前已完成 18/N 题。

页面提供“继续诊断”，不提供“重新开始”。用户不能通过退出、刷新或换设备主动清除原有诊断进度。

## 4. 诊断答题

### 4.1 页面信息

答题页应持续展示：

- 当前题号，例如“第 18/N 题”。
- 已答题数量和未答题数量。
- 当前答案保存状态。
- 题目导航。
- 上一题、下一题、暂停和交卷操作。

题号导航至少区分当前题、已作答和未作答三种状态。

### 4.2 作答规则

交卷前，用户可以：

- 选择答案。
- 修改已经选择的答案。
- 返回上一题或进入下一题。
- 通过题号导航跳转到任意题目。
- 查看已答题和未答题分布。
- 暂停并离开诊断。

诊断过程中不得展示：

- 正确答案。
- 单题是否答对。
- 当前分数或正确率。
- 题目解析或答题提示。
- 根据当前答案提前形成的能力结论。

### 4.3 上一题、下一题与题号导航

- 用户选择答案后，可以进入下一题，答案进入保存状态。
- 用户未选择答案也可以进入下一题，该题保持“未答”状态。
- 用户可以随时通过题号导航返回未答题或修改已答题。
- 最后一题的主要操作显示为“交卷”，不再显示“下一题”。
- 切换题目不能造成当前已选答案无提示丢失。

## 5. 答案保存

### 5.1 保存状态

页面应使用清晰状态告诉用户当前答案是否安全保存：

| 状态 | 页面反馈 |
|---|---|
| 保存中 | 显示“保存中”，不宣称答案已保存 |
| 已保存 | 显示“已保存”或最近保存时间 |
| 保存失败 | 显示“保存失败，请重试”，保留当前选择 |
| 网络异常 | 显示“网络异常，正在重试”，提醒用户暂勿关闭页面 |

### 5.2 保存失败

- 保存失败时保留用户当前选择，不清空答案。
- 页面应明确提示该答案尚未成功保存。
- 用户可以继续尝试保存，不需要重新进入诊断。
- 当前答案未确认保存时，不得显示“已保存”。
- 用户交卷前，应先完成尚未保存答案的处理。

### 5.3 修改答案

- 交卷前，同一道题可以多次修改。
- 页面最终应展示用户最后一次确认的选择。
- 再次进入诊断时，展示最近一次成功保存的答案。
- 交卷开始后，所有题目进入只读状态，不再允许修改。

## 6. 暂停、退出与恢复

### 6.1 主动暂停

用户点击“暂停诊断”时，提示：

> 当前已保存的进度将为你保留，下次可以继续完成。

提供以下操作：

- “继续答题”：关闭提示并停留在当前题。
- “确认暂停”：退出诊断，返回首页或首次流程入口。

### 6.2 直接离开

用户关闭页面、返回其他页面或退出登录时：

- 已成功保存的答案和进度继续保留。
- 再次进入时不从第 1 题重新开始。
- 不改变原题目及题目顺序。
- 不清除已保存答案。

如果仍有答案正在保存，应提示：

> 当前答案正在保存，立即离开可能导致本题答案未保存。

### 6.3 恢复诊断

用户重新登录、换设备或再次进入首次诊断时，应恢复：

- 原来的全部冻结题目。
- 原来的题目顺序。
- 已成功保存的答案。
- 已答和未答状态。
- 已完成题数。
- 上次答题位置。

恢复成功后提示：

> 已恢复你上次的诊断进度，当前完成 18/N 题。

恢复后可回到上次停留的题目，或定位到第一道未答题，但需要保持统一口径。

### 6.4 多设备使用

- 同一用户在不同设备上进入时，看到的是同一份未完成诊断。
- 一台设备产生新进度后，另一台设备继续操作时，应提示存在更新并同步最新进度。
- 一台设备交卷成功后，其他设备上的答题页应变为只读，并进入同一结果处理状态。

## 7. 交卷前检查

### 7.1 发起交卷

用户可以在最后一题发起交卷，也可以从题目导航区域主动发起交卷。点击“交卷”后先展示确认信息，不立即完成提交。

### 7.2 已完成全部题目

全部题目均已作答时，提示：

> 已完成 N/N 题。交卷后不能修改答案，确认提交吗？

提供：

- “继续检查”：关闭提示并返回答题页。
- “确认交卷”：提交本次诊断。

### 7.3 存在未答题

存在未答题时，突出显示未答数量：

> 还有 6 道题未作答。交卷后不能修改答案，未答题将按未作答记录。

提供：

- “返回检查”：返回答题页，并可快速定位第一道未答题。
- “仍然交卷”：再次确认后提交。

本期允许未答完交卷。未答题按未作答记录，不自动选择任何答案。

### 7.4 尚有答案未保存

- 交卷时如果仍有答案正在保存，提示“正在保存最后的作答，请稍候”。
- 保存完成后才能继续交卷。
- 保存失败时提示用户重试，不得在没有明确提示的情况下忽略该答案。

## 8. 交卷与重复操作

### 8.1 确认交卷

用户确认交卷后：

- 按钮显示“正在提交”，并停止响应连续点击。
- 页面题目和答案变为只读。
- 提交成功后进入结果处理页。
- 用户不能通过刷新、退出、重新登录或浏览器返回重新修改答案。

### 8.2 交卷成功

交卷成功后提示：

> 答卷已提交，正在为你生成诊断结果。

此后再次进入首次诊断，应进入处理页或报告页，不再进入可编辑的答题页。

### 8.3 交卷结果暂时不明确

如果确认交卷后遇到网络超时，页面提示：

> 正在确认交卷结果，请不要重复操作。

确认后的交互规则：

- 已交卷：进入结果处理页。
- 尚未交卷：恢复交卷操作，已答内容保持不变。
- 暂时无法确认：保留当前状态，允许用户稍后重新进入查看。

不得直接要求用户重新完成本次诊断。

### 8.4 重复交卷

连续点击、刷新重试、网络重发、换设备交卷均视为同一份诊断的重复操作。

- 同一份诊断只产生一次有效交卷和一次有效结算。
- 重复操作不得重复评分、重复生成报告、重复初始化画像或重复累计学习数据。
- 首次交卷已成功但结果仍在处理时，提示“本次诊断已经提交，正在处理结果”。
- 结果已经生成时，直接进入同一份诊断报告。
- 用户始终只看到一份有效诊断结果。

## 9. 评分与结果处理状态

### 9.1 状态展示

交卷后进入结果处理页，可按照实际进度展示：

1. 答卷已提交。
2. 正在评分。
3. 正在生成诊断报告。
4. 正在生成初始画像。
5. 结果已生成。

页面应说明：

> 你可以留在当前页面等待，也可以稍后回来查看。

用户可以刷新状态、返回首页等待或稍后重新进入查看，但不能返回修改答案、再次交卷或重新开始首次诊断。

### 9.2 处理时间较长

处理时间超过正常预期时，提示：

> 结果仍在生成中，你的答题记录已经保存，可以稍后查看。

处理时间较长不等于处理失败。不得展示虚假默认结果，也不得要求用户重新答题。

### 9.3 结果处理失败

明确失败时，提示：

> 答题记录已保存，但诊断结果暂时未能生成。

提供：

- “重新生成结果”。
- “稍后查看”。
- “联系支持”。

重新生成结果不要求用户重新答题或重新交卷。已经成功生成的内容继续保留，只恢复尚未成功的部分。

## 10. 诊断报告

### 10.1 展示条件

只有完成真实评分后，才能展示诊断报告。报告尚未完成时，只展示生成状态，不展示默认分数、模拟薄弱知识点、固定学习建议或其他占位结论。

### 10.2 报告内容

报告至少展示：

- 本次诊断对应的学习目标或考试资格。
- 诊断完成时间。
- 总题数、已答题数和未答题数。
- 正确题数、错误题数或总体正确率。
- 不同科目的表现。
- 不同知识点的初步表现。
- 优先学习方向。
- 结论的数据充足程度或可信程度。
- 初始画像入口和下一步学习入口。

### 10.3 真实数据规则

- 报告结论必须随用户真实答案变化。
- 薄弱知识点必须来自用户本次实际表现，不得固定展示预设内容。
- 未被本次诊断覆盖的知识点显示“暂无数据”。
- 题目太少或表现不稳定时，显示“数据不足”或“待验证”。
- 不因一道题答对就判断“已经掌握”。
- 不因一道题答错就判断“严重薄弱”。
- 未答题如实记录为未作答，不伪造成错误答案或默认答案。

### 10.4 结论文案

建议使用审慎、可理解的表达：

- 当前表现较好。
- 建议优先加强。
- 表现暂不稳定。
- 当前证据不足。
- 需要通过后续练习继续确认。

避免使用“已经完全掌握”“一定不会”“无法通过考试”等过度确定或带有否定评价的表达。

## 11. 初始学习画像

### 11.1 画像定位

初始画像是依据首次诊断形成的第一版学习判断，不是永久不变的能力结论。页面应说明：

> 初始画像来自本次诊断，后续会根据练习、订正和验证结果持续更新。

### 11.2 画像状态

知识点可使用以下用户可理解的状态：

- 当前表现较好。
- 正在掌握。
- 建议加强。
- 表现不稳定。
- 待进一步验证。
- 数据不足。
- 暂无数据。

### 11.3 画像业务规则

- 初始画像必须来自用户本次真实作答及评分结果。
- 每个画像结论必须对应本次诊断实际覆盖的知识点。
- 没有作答依据的知识点不能形成确定结论。
- 作答依据较少时，应降低结论确定性，并显示“数据不足”或“待验证”。
- 同一份诊断重复操作不能让画像数据重复增加。
- 刷新报告不能重复初始化画像。
- 报告和画像对同一知识点的结论应保持一致。
- 后续学习可以持续更新当前画像，但首次诊断报告应保留当时的初始结果供用户回看。

## 12. 完成后的用户去向

诊断报告和初始画像生成完成后，用户可以：

- 查看完整诊断报告。
- 查看初始学习画像。
- 查看优先学习方向。
- 进入学习首页。
- 开始系统提供的后续学习任务。

首次诊断完成后：

- 后续登录默认进入学习首页，不再重复要求完成首次诊断。
- 用户可以从学习记录中回看首次诊断报告。
- 修改每日学习时长或考试日期，不重新触发首次诊断。
- 更换考试资格且需要重新诊断时，应提前明确告知用户原因和影响，但不将用户重新标记为首次登录。

## 13. 异常场景交互规则

| 场景 | 交互规则 |
|---|---|
| 答题时断网 | 保留当前选择，显示尚未保存，网络恢复后继续保存 |
| 保存失败 | 不清空答案，明确提示失败并提供重试 |
| 关闭浏览器 | 下次恢复最近一次成功保存的进度 |
| 换设备登录 | 恢复同一份诊断，不创建新诊断 |
| 重复点击开始 | 进入已有诊断 |
| 重复点击交卷 | 显示已经提交，进入同一处理状态 |
| 交卷时网络超时 | 先确认交卷结果，不要求重新答题 |
| 评分时间较长 | 提示答卷已保存，可以稍后查看 |
| 结果生成失败 | 保留答卷，提供重新生成结果 |
| 报告生成失败 | 不重新答题，只恢复报告生成 |
| 画像生成失败 | 不展示默认画像，只恢复画像生成 |
| 交卷后浏览器返回 | 进入处理页或报告页，不能修改答案 |
| 多设备同时答题 | 使用同一诊断，提示并同步最新进度 |
| 多设备同时交卷 | 只产生一次有效交卷，进入相同结果 |

## 14. 验收标准

### 14.1 正常诊断

1. 用户保存有效学习目标后，可以进入不少于 10 题的首次诊断。
2. 用户可以正常选择、修改、跳题和检查答案。
3. 交卷前能够看到已答和未答数量，并进行二次确认。
4. 交卷后答案不可修改，用户进入结果处理页。
5. 处理完成后可以查看真实诊断报告和初始画像。

### 14.2 中断恢复

1. 用户答题中途关闭页面或退出登录。
2. 再次登录或换设备后，进入同一份诊断。
3. 原题目、原顺序、已保存答案和答题进度保持不变。
4. 用户可以从上次位置或第一道未答题继续。

### 14.3 重复交卷

1. 用户连续点击交卷、刷新重试或在其他设备再次交卷。
2. 用户始终进入同一个结果处理状态或同一份报告。
3. 不出现两次评分、两份报告、重复画像数据或重复学习结算。

### 14.4 结果异常

1. 评分或结果生成失败后，答卷继续保留。
2. 用户不能返回修改已交卷答案。
3. 用户可重新生成结果，不需要重新完成本次诊断。
4. 尚未成功生成报告或画像时，不展示演示、默认或随机数据。

### 14.5 真实数据

1. 用户答案变化时，对应评分、报告结论和画像结果随真实作答变化。
2. 未覆盖的知识点显示“暂无数据”。
3. 依据不足的知识点显示“数据不足”或“待验证”。
4. 报告与画像对同一知识点的结论保持一致。
5. 页面不得使用固定分数、固定薄弱项、模拟报告或默认画像替代真实结果。

## 15. 本期完成口径

本期首次诊断闭环完成，需要同时满足：

- 真实诊断题目（不少于 10 题）可以完整作答。
- 答案具有清晰的保存反馈。
