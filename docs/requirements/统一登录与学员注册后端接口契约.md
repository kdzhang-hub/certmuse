# CertMuse 统一登录与学员注册后端接口契约 V1.0

> 契约状态：V1.0 冻结，2026-08-11 同步 `web/student` 路由映射；接口字段与路径未变，后端尚未按本契约实现
> 适用对象：后端、前端、测试与安全评审
> 技术基线：RuoYi-Vue-Plus 6.x、Sa-Token、统一 `R<T>` 响应
> 关联基线：`统一登录界面业务与交互需求.md`

## 1. 目标与边界

本契约冻结 CertMuse 统一账号密码登录、管理员/学员身份分流、学员自助注册、当前身份查询和学员首次流程查询的后端接口。后端实现、数据库变更、默认角色初始化、注册开关启用和前端页面实现不属于本契约交付。

系统继续复用现有用户模型和认证体系，不增加第三种用户类型：

| 产品身份 | `userType` | 默认去向 | 权限模型 |
|---|---|---|---|
| 管理员、运营人员 | `sys_user` | 管理端 `/index` 或有权管理端目标 | 角色、菜单、按钮和数据范围 |
| 学员 | `app_user` | 学员首次流程或 `/learning/**` | `certmuse:student` 与本人数据所有权 |

`userType` 是认证主体类型，不等同于角色。角色决定可执行的操作，资源所有权决定学员可访问的数据。三者必须分别校验，不能只依赖前端路由隐藏。

## 2. 通用约定

### 2.1 响应包装

所有接口沿用现有 `R<T>` 包装：

```ts
interface ApiResponse<T> {
  code: number;
  msg: string;
  data?: T;
}
```

- 成功响应使用现有成功码并返回本契约定义的 `data`。
- 失败响应使用现有全局异常与错误码机制；前端可以展示安全处理后的 `msg`，但不得根据错误文案决定身份、权限或路由。
- 响应不得包含密码、验证码答案、密码散列、内部 SQL、角色主键、访问令牌以外的认证密钥或任意可执行跳转 URL。

### 2.2 认证与传输

- 登录和注册继续使用现有 `clientId`、`grantType=password`、图形验证码和接口加密机制。
- Sa-Token 登录标识继续使用 `userType:userId`，例如 `app_user:123`。
- `userType` 必须与账户记录精确匹配，只允许 `sys_user` 或 `app_user`；不得使用包含、前缀或模糊匹配。
- 管理端与学习端按同站点部署，共享既有会话机制；对外由同一来源分别承载统一认证入口、管理端和 `web/student` 的 `/learning/**`，不得在 URL、Referer、浏览器历史或应用日志中传递访问令牌。

## 3. 登录接口

### 3.1 请求

`POST /auth/login`

```ts
interface LoginRequest {
  username: string;
  password: string;
  code?: string;
  uuid?: string;
  clientId: string;
  grantType: 'password';
}
```

| 字段 | 必填 | 约束 |
|---|---:|---|
| `username` | 是 | 账号原值，不负责表达用户类型 |
| `password` | 是 | 仅用于本次认证，不得记录到日志 |
| `code` | 按配置 | 验证码开启时必填 |
| `uuid` | 按配置 | 与本次验证码一一对应 |
| `clientId` | 是 | 必须是启用且允许密码授权的客户端 |
| `grantType` | 是 | 固定为 `password` |

请求不得包含 `userType`。服务端必须在校验凭据并加载账户后，从账户记录确定身份类型。

### 3.2 成功响应

```ts
interface LoginResult {
  access_token: string;
  expire_in: number;
  client_id: string;
  scope?: string;
  userType: 'sys_user' | 'app_user';
  firstLogin: boolean;
}
```

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "access_token": "***",
    "expire_in": 1800,
    "client_id": "e5cd7e4891bf95d1d19206ce24a7b32e",
    "scope": "all",
    "userType": "app_user",
    "firstLogin": true
  }
}
```

### 3.3 业务规则

1. `userType` 取自认证成功的账户，客户端不能传入、选择或覆盖。
2. `firstLogin` 表示本次认证前该账号从未成功登录。服务端必须在一次原子操作内完成判定与首次成功登录记录，避免并发登录重复返回 `true`。
3. `firstLogin` 只用于欢迎提示、审计和统计，不直接决定学员落点；学员实际落点由 onboarding 状态决定。
4. `sys_user` 不查询学员 onboarding 状态；`app_user` 必须查询第 6 节接口后再分流。
5. 账户的 `userType` 为空、未知、非法或与会话身份不一致时，登录失败且不得签发可用会话。
6. 登录响应不得返回 `redirect`、完整目标 URL 或前端路由。登录前目标由前端按本地白名单验证。

## 4. 学员注册接口

### 4.1 请求

`POST /auth/register`

```ts
interface LearnerRegisterRequest {
  username: string;
  password: string;
  code?: string;
  uuid?: string;
  clientId: string;
  grantType: 'password';
}
```

| 字段 | 必填 | 约束 |
|---|---:|---|
| `username` | 是 | 2～30 个字符，全局唯一 |
| `password` | 是 | 8～30 个字符，按现有密码算法安全散列后保存 |
| `code` | 按配置 | 验证码开启时必填 |
| `uuid` | 按配置 | 与本次验证码一一对应，校验后失效 |
| `clientId` | 是 | 必须是允许自助注册的有效客户端 |
| `grantType` | 是 | 固定为 `password` |

`confirmPassword` 只在前端校验，不发送到服务端。请求出现以下任一字段时必须拒绝，不能忽略后继续注册：

- `userType`
- `userId`
- `roleId`、`roleIds` 或角色编码
- `deptId`、`postId`、`postIds`
- 菜单、按钮、权限或数据范围字段

### 4.2 成功响应

```ts
interface LearnerRegisterResult {
  username: string;
  userType: 'app_user';
}
```

```json
{
  "code": 200,
  "msg": "注册成功",
  "data": {
    "username": "student01",
    "userType": "app_user"
  }
}
```

成功响应不返回令牌，不自动建立会话。用户必须返回统一登录页完成认证。

### 4.3 创建规则

1. 自助注册只创建 `app_user`，服务端不得读取客户端提供的用户类型。
2. 新账户必须绑定角色编码 `certmuse:student`，且不能获得管理端菜单、按钮或管理数据权限。
3. 账户创建与默认角色绑定必须处于同一事务。默认角色不存在、被停用或绑定失败时整体回滚，不能留下无角色账户。
4. 用户名在所有用户类型之间全局唯一，不允许 `sys_user` 与 `app_user` 使用相同账号。
5. 注册开关关闭、客户端不允许注册、用户名重复、参数不合法、验证码错误或验证码过期时注册失败，不建立账户。
6. 密码不得明文保存、回显或写入业务日志；注册日志只记录必要的账号标识、结果和追踪信息。

## 5. 当前身份查询

`GET /system/user/getInfo`

现有响应中的 `user.userType` 必须保留，并与登录响应及 Sa-Token 会话一致：

```ts
interface CurrentUserInfo {
  user: {
    userId: string;
    userName: string;
    nickName: string;
    userType: 'sys_user' | 'app_user';
  };
  roles: string[];
  permissions: string[];
}
```

- 接口只返回当前会话对应的用户，不接受客户端指定 `userId`。
- 登录响应、用户记录、`LoginUser.userType` 和当前身份响应必须一致。
- 任一来源不一致时不得继续业务访问：客户端清理会话，服务端记录不包含令牌正文的安全审计事件。
- `app_user` 的角色结果必须包含 `certmuse:student`；`sys_user` 不得通过伪造学员角色改变认证主体类型。

## 6. 学员首次流程查询

`GET /api/learning/onboarding/status`

```ts
interface OnboardingStatus {
  goalStatus: 'NONE' | 'ACTIVE' | 'PAUSED';
  diagnosticStatus:
    | 'NOT_STARTED'
    | 'IN_PROGRESS'
    | 'PROCESSING'
    | 'COMPLETED'
    | 'FAILED';
  currentCertificationId?: string;
  activeSessionId?: string;
  nextAction:
    | 'SET_GOAL'
    | 'START_DIAGNOSTIC'
    | 'CONTINUE_DIAGNOSTIC'
    | 'WAIT_PROCESSING'
    | 'ENTER_HOME'
    | 'RETRY_DIAGNOSTIC'
    | 'CONTACT_SUPPORT';
}
```

### 6.1 访问和返回规则

- 仅已登录的 `app_user` 且具有学员权限时可调用；`sys_user` 调用返回无权访问。
- 用户身份从当前会话取得，不接受查询参数或请求体中的 `userId`。
- 服务端保证目标、诊断状态、有效会话和 `nextAction` 一致。
- 服务端只返回状态枚举和业务标识，不返回任意可执行 URL。
- `activeSessionId` 只有在当前学员拥有且会话有效时返回。

### 6.2 前端固定映射

| `nextAction` | 固定前端目标 |
|---|---|
| `SET_GOAL` | `/learning/onboarding` |
| `START_DIAGNOSTIC` | `/learning/diagnostic/intro` |
| `CONTINUE_DIAGNOSTIC` | `/learning/diagnostic/session` |
| `WAIT_PROCESSING` | `/learning/home?state=processing` |
| `ENTER_HOME` | 合法学习端原目标或 `/learning/home` |
| `RETRY_DIAGNOSTIC` | `/learning/diagnostic/intro?mode=retry` |
| `CONTACT_SUPPORT` | `/learning/home?state=support` |

以上路径由 `web/student` 本地路由表维护，仅用于前后端联调和验收；服务端仍只返回 `nextAction` 枚举，不返回这些路径。前端遇到未知枚举时进入安全错误态，不默认进入首页，也不执行服务端返回的字符串路由。

### 6.3 状态不一致错误

目标、诊断会话或报告记录无法组成合法 onboarding 状态时，接口不得猜测下一页面，返回 HTTP 500 且 `R.code=500`。`data.errorCode` 固定为 `ONBOARDING_STATE_INVALID`，`retryable=false`，并返回非空 `traceId`；服务端使用同一个 `traceId` 在统一异常边界记录一次完整错误。响应不得包含数据库状态、内部标识或异常原文。

## 7. 权限与数据隔离

### 7.1 端与接口权限

- `sys_user` 和 `app_user` 共用认证入口，但不能跨端访问。
- `/api/learning/**` 要求 `app_user` 身份和对应学员权限；仅隐藏菜单或路由不构成授权。
- 管理接口要求 `sys_user` 身份、具体菜单/按钮权限和适用的数据范围。
- 管理员查看或维护学员数据必须使用独立管理接口，不能复用学员“查看本人”接口绕过管理权限。

### 7.2 学员本人数据

学员目标、学习会话、答题、错题、任务、画像、验证和学习记录等自有接口必须遵守：

1. 所有者 `userId` 从 `LoginHelper.getUserId()` 获取，接口请求不得提供或覆盖。
2. 查询、更新和删除必须强制包含当前 `user_id` 条件，不能先按对象 ID 查询后在前端判断。
3. 路径对象必须执行所有权校验。对象不存在与对象属于其他学员使用相同对外结果，避免泄露资源是否存在。
4. 批量接口逐项约束所有权，不允许混入其他学员 ID。
5. 缓存键必须包含当前用户或资源所有权维度，避免跨学员缓存污染。
6. 后台任务、重试和事件消费继续携带并验证原业务对象的所有者，不能改用操作者作为学习数据所有者。

## 8. 失败场景

| 场景 | 必须行为 |
|---|---|
| 凭据错误、账户禁用 | 不签发会话；返回安全错误，不暴露账户细节 |
| 验证码错误或过期 | 本次验证码失效；不创建会话或账户 |
| 注册请求携带身份/权限字段 | 拒绝请求；不静默忽略 |
| 用户名重复 | 不创建账户或角色关联 |
| 默认学员角色不可用 | 注册事务整体回滚 |
| `userType` 缺失、未知或不一致 | 拒绝分流并清理会话 |
| `sys_user` 调用学习接口 | 返回无权访问，不查询学员业务状态 |
| 学员访问他人资源 | 与资源不存在使用相同对外结果 |
| onboarding 状态不一致 | 返回可追踪错误，不猜测下一页面 |

## 9. 契约验证清单

1. 登录、当前身份查询和会话中的 `userType` 完全一致。
2. 注册请求无法创建 `sys_user`、指定角色、部门、权限或所有者 ID。
3. 新注册账户固定为 `app_user`，并在同一事务中获得 `certmuse:student`。
4. 注册成功不返回令牌，登录成功响应才返回令牌。
5. `sys_user` 不查询 onboarding；`app_user` 能按所有 `nextAction` 恢复正确流程。
6. 外部、跨端或恶意登录前目标不由后端返回，也不能改变认证结果。
7. 学员不能读取、更新或删除其他学员的目标、会话、答题、错题、任务、画像和记录。
8. 无管理权限的用户不能通过学习接口、对象 ID 或批量接口绕过数据范围。
9. URL、Referer、浏览器历史、响应日志和服务端应用日志中不存在密码、验证码或访问令牌正文。
10. 契约字段、枚举、校验边界和错误行为在前后端类型与自动化测试中保持一致。
11. `/learning/onboarding`、`/learning/diagnostic/intro`、`/learning/diagnostic/session` 和 `/learning/home` 均由 `web/student` 提供，所有 `nextAction` 都能解析到已注册的学生端路由。

## 10. 兼容与实施边界

- 现有 `POST /auth/login`、`POST /auth/register`、`GET /system/user/getInfo` 路径和 `R<T>` 包装保持不变。
- 学生端前端目录固定为 `web/student`、业务路由统一为 `/learning/**`，不改变任何后端接口路径、请求字段或响应字段。
- 登录成功响应新增 `userType`、`firstLogin`；注册成功由空数据调整为 `LearnerRegisterResult`。
- 现有注册请求中的客户端 `userType` 字段废止，后端实现时必须拒绝该字段，而不是继续兼容。
- 后端实现必须另行评审首次登录原子记录、默认学员角色种子、事务边界、权限注解和所有权查询。
- 本契约不授权修改生产注册开关、执行数据库迁移或部署服务。

如本契约与早期页面需求中的“本期不开放注册”描述冲突，以本契约为准；找回密码、第三方登录和用户自行切换账户类型仍不在本期范围。
