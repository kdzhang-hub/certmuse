# U16 官方考试安排与考区报名信息后端接口契约 V1.2（待冻结）

> 契约版本：V1.2-rc1
> 状态：待 34 个考区基础数据核对完成后冻结
> 日期：2026-08-19
> 消费端：管理端「官方考试安排」、公共首页资格测试、考试介绍页

## 1. 目标与边界

U16 维护两类信息：全国考期内可考的高级资格及科目场次，以及各考区在该考期的报名、审核、缴费时间和官方链接。

本契约遵循“满足当前展示，保持最小实现”的原则：数据字段、状态和接口只覆盖首页、考试介绍、资格测试及管理端实际需要呈现或维护的内容；只为防止错误发布、并发覆盖、重复写入和事实失真增加必要约束。没有当前消费场景的历史查询、核验流程、快照模型、扩展状态和预留接口一律不进入 V1。后续需求出现时再独立评审，不提前扩大本模块。

本版保持以下简单边界：

- 只支持现有 `HIGH` 高级资格。
- 考期是唯一发布单位；资格安排、场次和考区报名记录随考期整体发布，不单独维护发布状态。
- 资格安排继承考期的全国来源；考区报名记录保存地方当期来源。
- 一个考期和一个考区只有一条报名事实，该记录适用于该考期全部资格。
- 公共端只读取当前发布版本，不提供 `superseded` 或 legacy 历史查询。
- 不做自动抓取、OCR、来源核验工作流、报名代办、缴费或资格审核。
- U12 只调整官方批次查询；既有预计批次和学习目标快照业务不变。跨日考试以 `examStartDate` 映射目标月份。

## 2. 数据模型与约束

### 2.1 考期和修订

`cm_exam_period` 是聚合根：

| 字段 | 规则 |
|---|---|
| `period_code` | `^[0-9]{4}-H[12]$`，与 `exam_year`、`half` 一致，创建后不可修改。 |
| `revision_no` | 同一 `period_code` 从 1 递增；唯一键为 `(period_code, revision_no)`。 |
| `supersedes_period_id` | 修订草稿指向其复制来源；首版为 `null`。 |
| `status` | `draft`、`published`、`superseded`。只允许草稿发布；发布新修订时在同一事务内替代旧版本。 |
| 来源 | `official_source_url`、`source_published_at`。资格安排不重复保存来源。 |
| 并发和审计 | `row_version`、创建/更新人和时间、发布人和时间。 |

数据库必须保证每个 `period_code` 最多一个草稿和一个当前发布版本。`POST /exam-periods` 只允许创建从未出现过的 `periodCode`；只要数据库存在该编码的任意草稿、已发布、已替代或 legacy 版本，一律返回 409。后续修订只能从当前已发布版本调用 `/revisions` 创建，避免修订链分叉。

### 2.2 资格安排和场次

`cm_exam_schedule` 表示一个考期内的一个资格，`(exam_period_id, certification_id)` 唯一。资格必须启用且级别为 `HIGH`。

- `exam_start_date`、`exam_end_date` 由场次最早开始和最晚结束时间按 `Asia/Shanghai` 日期推导；旧 `exam_date` 同步为 `exam_start_date`，仅用于兼容 U12。
- 每个安排至少一条场次；同一安排内 `session_code`、`sort_order`、`exam_subject_id` 各自唯一。
- `sessionCode` 为 `^[A-Z0-9_]{2,32}$`，`sortOrder` 为 1–99，`endTime > startTime`。
- H1 场次只能在 1–6 月，H2 场次只能在 7–12 月。
- `public_note` 为可空纯文本，最多 500 字符，不接受 HTML。

为在数据库层证明场次科目属于安排资格，迁移必须显式建立：

1. `UNIQUE cm_exam_schedule(id, certification_id)`；
2. `cm_exam_schedule_session.certification_id NOT NULL`；
3. 场次 `(exam_schedule_id, certification_id)` 外键到安排 `(id, certification_id)`；
4. 场次 `(exam_subject_id, certification_id)` 外键到已有科目候选键 `(id, certification_id)`。

### 2.3 考区和报名信息

`cm_exam_region` 是固定 34 项长期目录。本版每个考区只维护一个地方长期公告入口 `local_notice_url`，不再拆分“联系方式网址”和“公告网址”。不提供新增或物理删除考区接口，只允许更新机构、电话、长期入口、排序和启停状态。

`cm_exam_region_registration` 以 `(exam_period_id, region_id)` 唯一，包含：

- 必填 `registration_end`，可空 `registration_start`；如果开始时间存在，必须早于截止时间。
- 可空的 `review_start/review_end`、`payment_start/payment_end`；每一对必须同时为空或同时非空，且结束晚于开始。
- 可空的 `qualification_review_note`、`payment_note`，均为最多 500 字符纯文本。
- 必填 `official_source_url` 和 `source_published_at`。

不支持补报名例外字段。报名状态按服务器当前时间计算：

| 条件 | `availability` |
|---|---|
| 没有当前发布的地方报名记录 | `NOT_PUBLISHED` |
| `now >= registrationEnd` | `CLOSED` |
| `registrationStart == null` 且尚未截止 | `OPENING_UNKNOWN` |
| `now < registrationStart` | `UPCOMING` |
| `registrationStart <= now < registrationEnd` | `OPEN` |

### 2.5 URL、日期和历史边界

- 考期和报名记录的 `official_source_url` 只校验：绝对 HTTPS、1–2048 字符、无片段。服务不访问 URL，不判断机构域名。
- `local_notice_url` 允许绝对 HTTP 或 HTTPS，因为国家官网当前列出的多个地方机构入口仍为 HTTP；长度 1–2048 字符、无片段。前端以新窗口打开并使用 `noopener noreferrer`。
- 审计日志记录去除查询参数和片段后的来源 URL，避免泄露令牌；业务表保留原始合法 URL。
- `date` 使用 `YYYY-MM-DD` 和 `Asia/Shanghai` 业务自然日；`timestamptz` 输出 ISO-8601 带偏移格式。
- `sourcePublishedAt` 不晚于服务器当前时间 5 分钟。本文示例统一使用早于 2026-08-19 的时间，仅展示字段结构，不代表真实公告事实。
- 已替代版本和 legacy 数据仅供内部迁移、审计和 U12 兼容查询，不提供管理端或公共历史读取接口，也不建立考区展示快照。

## 3. HTTP 与并发通用约定

- ID 是不带符号、空格或前导零的十进制正整数字符串，且不得超过 Java `Long.MAX_VALUE`。
- 管理端要求登录和相应权限；公共接口使用 `@SaIgnore` 匿名读取。
- 真实 HTTP Status 必须等于 `R.code`。401/403 沿用认证兼容格式，其他失败使用第 6 节结构。
- 查询参数 `pageNum` 默认 1、范围 1–10000；`pageSize` 默认 20、范围 1–100。`PageResult` 响应只含 `rows`、`total`。
- 所有写操作要求 `X-Request-Id: UUID`。
- 考期本身的更新、删除、复制、发布使用 `expectedRowVersion`。
- 资格安排、场次、报名记录的新增、修改、删除全部使用 `expectedPeriodRowVersion`。任何子项写入成功后，考期 `rowVersion + 1`；版本不一致返回 409 `EXAM_GUIDANCE_PERIOD_VERSION_CONFLICT`。这样发布与子项编辑不能并发越过彼此。

## 4. 管理端接口

读取权限沿用 `certmuse:catalog:exam-schedule:list`；新增写权限为 `create`、`edit`、`publish`。不增加来源核验接口或权限。

## 5. 公共接口

### 5.1 资格目录

```http
GET /api/public/exam-guidance/qualifications
```

匿名返回所有启用资格，按 `sortOrder ASC, id ASC` 排序。每项返回 `certificationCode`、`certificationName`、`qualificationLevel`、`nearestExamStartDate`；后者取该资格最早一条已发布、官方且考试开始日期不早于上海当天的安排，无符合安排时为 `null`。该目录不表示某一考期可报考资格，也不返回管理端审计或修订字段。

### 5.2 资格测试上下文

```http
GET /api/public/exam-guidance/qualification-context?targetYear=2026&targetHalf=H2
GET /api/public/exam-guidance/qualification-context?targetHalf=UNKNOWN
```

H1/H2 时 `targetYear` 必填，范围为当前年至当前年 + 3；UNKNOWN 时不得传 `targetYear`。只返回当前发布考期中 `examEndDate >= today`、资格启用的安排，按资格 `sortOrder ASC, certificationId ASC`。

`availability` 只有：`OFFICIAL`、`PENDING_OFFICIAL`、`ENDED`。不存在当前发布版本时返回 `PENDING_OFFICIAL` 和空候选；已发布但全部资格结束时返回 `ENDED` 和空候选；UNKNOWN 没有未来候选时返回 422。

资格项逐字段返回 `certificationId`、`certificationCode`、`certificationName`、`level`、`examStartDate`、`examEndDate`、`publicNote`、`sessions`；场次返回 `examSubjectId`、`subjectName`、`sessionCode`、`startTime`、`endTime`、`sortOrder`。

### 5.3 考区和报名信息

```http
GET /api/public/exam-guidance/regions
GET /api/public/exam-guidance/regions?periodCode=2026-H2
```

不传 `periodCode` 时只返回启用考区长期信息，`registration=null`。传参时只接受当前发布版本；不存在、草稿、已替代或 legacy 均返回 404，不提供历史读取。

每个考区返回 `regionCode`、`regionName`、`regionType`、`institutionName`、`contactPhone`、`localNoticeUrl` 和 `registration`。报名对象固定返回 `availability`、六个报名/审核/缴费时间字段、两项公开说明、`officialSourceUrl`、`sourcePublishedAt`；没有报名记录时除 `availability=NOT_PUBLISHED` 外其余字段均为 `null`。

## 6. 幂等与失败响应

U16 写操作沿用 `cm_idempotency_record(action_code, request_id)`。规范化载荷包含协议版本、actionCode、管理员 ID、路径 ID、查询参数和键排序 JSON Body，使用 SHA-256。相同 requestId 和相同载荷回放首次完整 HTTP 状态及 `R`；不同载荷返回 409。

500 和网关超时允许客户端使用同一 requestId 安全重试。若首次请求已有终态记录，原样回放；仍处于 `processing` 时返回 409 `EXAM_GUIDANCE_REQUEST_IN_PROGRESS`、`retryable=true`。安全重试只保证保留期内不主动创建第二次写入，不保证首次请求一定成功。

U16 幂等记录每日清理，范围严格限制为 `action_code LIKE 'EXAM_GUIDANCE_%'` 且超过 24 小时的 `succeeded`、`failed`、`processing` 记录。删除超时 `processing` 后，同一请求再次到达可能重复执行；产品和技术接受该风险，因此本协议不是严格 exactly-once。清理任务不得删除业务表、发布记录或业务审计日志。

失败结构：

```json
{
  "code": 409,
  "msg": "请求与当前资源状态冲突",
  "data": {
    "errorCode": "EXAM_GUIDANCE_PERIOD_VERSION_CONFLICT",
    "retryable": false,
    "traceId": null,
    "fieldErrors": [],
    "details": null
  }
}
```

| HTTP | `errorCode` | `retryable` | 条件 |
|---:|---|---:|---|
| 400 | `EXAM_GUIDANCE_REQUEST_INVALID` | false | 字段、ID、URL、日期或场次不合法。 |
| 404 | `EXAM_GUIDANCE_RESOURCE_NOT_FOUND` | false | 管理资源不存在。 |
| 404 | `EXAM_GUIDANCE_PERIOD_NOT_PUBLIC` | false | 公共考期无当前发布版本。 |
| 409 | `EXAM_GUIDANCE_ROW_VERSION_CONFLICT` | false | 考期或考区自身版本冲突。 |
| 409 | `EXAM_GUIDANCE_PERIOD_VERSION_CONFLICT` | false | 子项写入携带的考期版本过期。 |
| 409 | `EXAM_GUIDANCE_IDEMPOTENCY_CONFLICT` | false | 相同 requestId 使用不同载荷。 |
| 409 | `EXAM_GUIDANCE_REQUEST_IN_PROGRESS` | true | 相同请求仍在处理中。 |
| 409 | `EXAM_GUIDANCE_STATE_CONFLICT` | false | 非法状态转换或修订链分叉。 |
| 409 | `EXAM_GUIDANCE_DUPLICATE_PERIOD` / `DUPLICATE_SCHEDULE` / `DUPLICATE_REGISTRATION` | false | 唯一约束冲突。 |
| 422 | `EXAM_GUIDANCE_PUBLISH_INCOMPLETE` | false | 缺来源、资格安排、场次或必填字段。`details.blockers` 指明资源和字段。 |
| 422 | `EXAM_GUIDANCE_NO_FUTURE_PERIOD` | false | UNKNOWN 没有未来资格。 |
| 500 | `EXAM_GUIDANCE_SYSTEM_FAILURE` | true | 未预期错误；使用同一 requestId 重试。 |
| 504 | `EXAM_GUIDANCE_REQUEST_TIMEOUT` | true | 服务端或网关超时；使用同一 requestId 重试。 |

4xx 默认 `traceId=null`；500/504 的 `traceId` 非空并对应服务端一次完整异常日志。401/403 沿用现有认证格式。
