```yaml

  - /api/learning/goals/switch

status: review_pending

depends_on:
  - U03-首次学习目标设置后端接口契约
  - 软考学习平台全流程业务流程与规则 V1 第 2、3、8 节
```

## 1. 目标与边界

本契约服务学员端`/learning/account`的“切换学习目标”。它只处理已有**进行中**目标的学员，切换到另一项考试资格，并为新资格建立新的进行中目标。

切换不是修改旧目标的资格、考纲或历史数据。一次成功切换在同一事务内完成：

```text
旧进行中目标 → 放弃其未交卷会话 → 暂停
                         ↓
                 新资格目标 → 新建为进行中
```

新旧目标拥有独立档案：旧目标的作答、任务、错题、画像、报告均保留在旧目标；新目标不复制它们。用户只会在切换完成后看到一个进行中目标，不存在可观察的“旧目标已暂停但新目标尚未建立”的中间状态。

本契约包含：

- 读取当前目标、可切换资格、目标考试批次和未交卷会话影响；
- 二次确认后切换到**不同资格**；
- 放弃旧目标的未交卷会话、暂停旧目标、新建目标及审计；
- 幂等、乐观并发、资格与批次有效性校验。

本契约不包含：

- 首次目标创建；无进行中目标的用户继续使用 U03 `/learning/onboarding`；
- 恢复暂停目标、考试结束后的结果确认、同资格延期或再次备考；
- 修改每日学习时长、考纲选择、官方报名信息或官方考试日期；
- 删除旧目标、迁移旧资格的画像/错题/作答，或结算被放弃会话；
- 学习计划和每日任务的具体生成接口。

同资格变更目标考试批次属于“延期或再次备考”，必须建立独立的后续契约，不能借用本接口把旧目标改写为新批次。请求中的资格与当前目标资格相同，一律拒绝。

## 2. 冻结业务与数据规则

1. 只有`cm_user_goal.status='active'`的当前目标可以发起切换。暂停目标只能恢复；已完成或已取消目标不能恢复或切换。
2. 新资格必须启用，并且存在当前可用的`cm_syllabus_version`。考纲由服务端确定，请求不得传递`syllabusVersionId`。
3. 新目标考试批次由`targetExamYear + targetExamMonth`组成。前端只能从所选资格的`examBatches`中选择；服务端同时快照该批次的`examBatchType`和官方批次的`targetExamDate`。官方批次使用其发布日期，预计批次的`targetExamDate=null`；不建立对`cm_exam_schedule`的外键。
4. 账户页不展示、也不提交每日学习时长。新目标的`cm_user_goal.daily_minutes`从旧进行中目标原样复制；该字段是现有表的必填事实，不因本页面未展示而写入浏览器默认值。
5. 旧目标下状态为`created`或`in_progress`的`cm_learning_session`均转为`cancelled`，`status_reason='goal_switched'`。已保存的草稿和已提交事实保留为历史；不补交、重评、结算或删除任何作答、错题、画像和报告。
6. 旧目标转为`paused`后不生成新任务、不允许新正式作答；旧任务、计划、会话、错题、画像和报告只读保留。新目标从零开始，后续由计划/任务契约创建其计划和任务。
7. 本接口只允许不同资格。故不复制旧目标的`cm_knowledge_profile`、`cm_subject_profile`、`cm_overall_profile`、`cm_error_record`或学习证据；这些记录均以`goal_id`隔离。
8. 当前批次已结束且待用户确认结果时，用户必须先走考试结果处理流程；资格已停止维护时由系统取消目标。本接口不绕过这些更高优先级门禁。

## 3. 实现前置：数据库迁移与审计兼容

现有数据库设计不能直接满足本契约，后端实现前必须新增有序 PostgreSQL 迁移；不得修改已部署的`003_learning.sql`、`006_constraints_indexes_seed.sql`或 U03 迁移。

### 3.1 当前约束冲突

1. 现有`uk_cm_user_goal_current ON cm_user_goal(user_id) WHERE status IN ('active','paused')`会阻止“旧目标暂停 + 新目标进行中”。这与全流程规则“暂停目标不占用进行中名额”冲突。
2. 现有`uk_cm_user_goal_change_request_id UNIQUE(request_id)`会阻止一次切换同时写入“旧目标暂停”和“新目标创建”两条不可变审计记录。

### 3.2 必需迁移

迁移至少完成下列变更并更新`verify_local.sql`断言：

```sql
DROP INDEX uk_cm_user_goal_current;
CREATE UNIQUE INDEX uk_cm_user_goal_active
    ON cm_user_goal(user_id)
    WHERE status = 'active';

ALTER TABLE cm_user_goal_change
    DROP CONSTRAINT uk_cm_user_goal_change_request_id;
ALTER TABLE cm_user_goal_change
    ADD CONSTRAINT uk_cm_user_goal_change_goal_request_type
    UNIQUE (goal_id, request_id, change_type);

ALTER TABLE cm_user_goal
    ADD COLUMN exam_batch_type varchar(20) NOT NULL DEFAULT 'legacy_unknown',
    ADD COLUMN target_exam_date date;
```

`cm_idempotency_record`既有`UNIQUE(action_code, request_id)`继续承担本接口的全局幂等性，不再由`cm_user_goal_change.request_id`承担跨用户唯一性。U03 需要同步调整其“变更表请求号全局唯一”的文字说明，但其单目标创建幂等行为不变。

迁移还必须：

- 新增隐藏权限`certmuse:learning:goal:switch`并授予`student`角色；
- 验证同一用户可同时存在一条`active`和多条`paused`目标，但不得存在两条`active`目标；
- 验证一次`GOAL_SWITCH`可写入两条`cm_user_goal_change`，同一目标、同一请求号、同一变更类型不可重复；
- 复用既有`trg_cm_user_goal_status`，其`active > paused`合法转换无需放宽；
- 验证旧目标会话的`created/in_progress > cancelled`状态转换仍受既有`trg_cm_learning_session_status`保护。

## 4. 通用约定

### 4.1 响应、身份与权限

所有成功和可预期失败均使用`R<T>`包装，真实 HTTP Status 必须等于`R.code`。前端只按`data.errorCode`处理业务分支，`msg`仅作脱敏展示兜底。

```ts
interface GoalSwitchErrorVo {
  errorCode: string;
  retryable: boolean;
  traceId: string | null;
  fieldErrors: Array<{
    field: string;
    code: 'REQUIRED' | 'INVALID_FORMAT' | 'OUT_OF_RANGE' | 'DUPLICATE' | 'NOT_FOUND' | 'UNSUPPORTED';
    message: string;
  }>;
  details: null | {
    abandonedSessionCount?: number;
  };
}
```

- 两个接口均要求`certmuse:student`与`certmuse:learning:goal:switch`权限；两者为 AND 关系。
- 用户 ID 只从登录会话读取。请求不得传递或覆盖`userId`、`currentGoalId`、`goalId`、`operatorId`、`dailyMinutes`、`syllabusVersionId`、状态、审计原因或任意跳转 URL。
- 401/403沿用认证授权兼容格式，只承诺`code`、`msg`和空`data`；4xx的`traceId=null`；5xx返回安全文案、非空`traceId`、空`fieldErrors`与`details:null`。
- 所有 ID 使用十进制正整数字符串；时间使用 ISO-8601 UTC 字符串，前端按`Asia/Shanghai`展示。

### 4.2 幂等与乐观并发

`POST`必须携带`X-Request-Id`：长度 1–100、客户端以`crypto.randomUUID()`生成。每次用户确认切换生成新请求号；网络错误或 5xx 重试同一动作时复用原请求号与相同载荷；修改任一字段或重新确认后生成新请求号。

`action_code`固定为`GOAL_SWITCH`。规范化载荷按固定字段顺序构造：

```json
{
  "certificationId": "900000000000000002",
  "targetExamYear": 2027,
  "targetExamMonth": 5,
  "expectedCurrentGoalVersion": 3,
  "confirmAbandonInProgress": true
}
```

服务端将规范 JSON 的 SHA-256 写入`cm_idempotency_record.payload_hash`。同`action_code + request_id`且载荷相同，回放首次成功响应；载荷不同或跨用户碰撞，返回`GOAL_SWITCH_IDEMPOTENCY_CONFLICT`。竞争请求等待首事务提交或回滚，提交后回放、回滚后重新执行业务校验；不得对外返回“处理中”。

`expectedCurrentGoalVersion`是当前目标的`row_version`。锁内版本不一致时返回可重试的`GOAL_VERSION_CONFLICT`，前端重新读取选项和影响后再次确认，不得盲目重试旧请求。

### 5.2 确认切换学习目标

```http
POST /api/learning/goals/switch
Content-Type: application/json
X-Request-Id: 3e52599b-1dde-4f56-a1b7-69987a83f934
```

```ts
interface SwitchLearningGoalRequest {
  certificationId: string;
  targetExamYear: number;
  targetExamMonth: 5 | 11;
  expectedCurrentGoalVersion: number;
  confirmAbandonInProgress: boolean;
}
```

| 字段 | 必填 | 规则 |
| --- | ---: | --- |
| `certificationId` | 是 | 十进制正整数；必须为不同于当前目标的启用资格，且有当前可用考纲。 |
| `targetExamYear` | 是 | 必须等于所选资格`examBatches`中一项的年份。 |
| `targetExamMonth` | 是 | 必须等于该项批次月份；前端不得手工构造批次。 |
| `expectedCurrentGoalVersion` | 是 | 非负整数；必须等于锁定当前目标的`row_version`。 |
| `confirmAbandonInProgress` | 是 | 当前存在`created/in_progress`会话时必须为`true`；无此类会话时只能为`false`或`true`，语义相同。 |

```json
{
  "certificationId": "900000000000000002",
  "targetExamYear": 2027,
  "targetExamMonth": 5,
  "expectedCurrentGoalVersion": 3,

}
```

## 6. 服务端事务与持久化顺序

`POST`的所有步骤必须在一个数据库事务内完成：

1. 读取同`GOAL_SWITCH + X-Request-Id`的幂等记录，按第4.2节回放或处理竞争；
2. 锁定当前用户唯一`active`的`cm_user_goal`，校验存在、资格维护状态、批次状态与`expectedCurrentGoalVersion`；
3. 重新校验新资格、服务端当前可用考纲、目标年月和“不同资格”规则；
4. 锁定旧目标全部`created/in_progress`会话。若数量大于0但`confirmAbandonInProgress=false`，整体回滚并返回确认错误；
5. 写入幂等记录，按会话状态机将这些会话更新为`cancelled`并写入`status_reason='goal_switched'`；不删除会话、题目快照、草稿或任何已存在的学习事实；
6. 将旧`cm_user_goal`从`active`更新为`paused`，`row_version + 1`；写入一条`cm_user_goal_change(change_type='switched_out')`，`before_data`和`after_data`均为`user_goal_snapshot/1.0`，`reason='switch_to_other_certification'`；
7. 新建`cm_user_goal(status='active', row_version=0)`：资格和考纲来自第3步，考试批次来自请求，`daily_minutes`复制旧目标；写入一条`cm_user_goal_change(change_type='switched_in')`，`before_data=null`、`after_data`为新目标`user_goal_snapshot/1.0`、`reason='switch_from_other_certification'`；
8. 将幂等记录置为`succeeded`并持久化完整成功响应，再提交事务。

任一验证、并发、会话取消、审计或插入失败均回滚，不得遗留已暂停旧目标、半创建新目标、部分取消会话、孤立审计记录或可回放的成功响应。

快照沿用`user_goal_snapshot/1.0`，其`goal`对象至少包含`id`、`certificationId`、`syllabusVersionId`、`targetExamYear`、`targetExamMonth`、`dailyMinutes`、`status`和`version`。快照是审计事实，`dailyMinutes`虽不返回账户页也必须保留。

## 7. 失败响应

所有下列4xx响应均为：

```json
{
  "code": 409,
  "msg": "当前学习目标已发生变化",
  "data": {
    "errorCode": "GOAL_VERSION_CONFLICT",
    "retryable": true,
    "traceId": null,
    "fieldErrors": [],
    "details": null
  }
}
```

| HTTP / `R.code` | `errorCode` | 条件 | `retryable` | 前端行为 |
| --- | --- | --- | ---: | --- |
| 400 | `GOAL_SWITCH_REQUEST_INVALID` | 缺字段、未知字段、ID/布尔/版本格式不合法。 | false | 显示字段错误。 |
| 400 | `TARGET_EXAM_BATCH_INVALID` | 年月到期、超过范围或月份不是5/11。 | false | 刷新选项并重新选择批次。 |
| 401 | `UNAUTHORIZED` | 会话失效。 | false | 进入登录流程。 |
| 403 | `LEARNING_GOAL_SWITCH_FORBIDDEN` | 非学员或缺少权限。 | false | 停止操作并显示无权限。 |
| 409 | `LEARNING_GOAL_NOT_ACTIVE` | 没有进行中目标，或当前目标已非进行中。 | false | 进入首次目标设置页。 |
| 409 | `GOAL_SWITCH_CONFIRM_REQUIRED` | 存在未交卷会话且未确认放弃。 | false | 展示`details.abandonedSessionCount`，二次确认后使用新请求号提交。 |
| 409 | `GOAL_VERSION_CONFLICT` | 当前目标版本、资格或状态已被其他设备/操作改变。 | true | 刷新切换选项，重新确认。 |
| 409 | `GOAL_SWITCH_IDEMPOTENCY_CONFLICT` | 相同请求号对应不同载荷或不同用户。 | false | 停止重试，刷新当前目标。 |
| 422 | `GOAL_SWITCH_SAME_CERTIFICATION` | 所选资格与当前资格相同。 | false | 告知此处只支持切换其他资格。 |
| 422 | `CERTIFICATION_UNAVAILABLE` | 新资格停用或不存在可用考纲。 | false | 刷新资格选项。 |
| 422 | `GOAL_RESULT_CONFIRMATION_REQUIRED` | 当前批次已结束且结果待确认。 | false | 进入结果处理流程。 |
| 422 | `GOAL_SWITCH_NOT_ALLOWED` | 资格停止维护或其他高优先级业务门禁。 | false | 展示服务端说明，不伪造可切换状态。 |
| 500 | `LEARNING_GOAL_SWITCH_FAILED` | 未分类系统或事务失败。 | true | 保留输入并用同一请求号重试，展示`traceId`。 |

字段错误只使用`REQUIRED`、`INVALID_FORMAT`、`OUT_OF_RANGE`、`UNSUPPORTED`；路径为请求 JSON 的 camelCase。错误响应不得暴露其他用户、旧会话题目/答案、SQL、堆栈、对象存储键或内部路由。

## 8. 安全与可观测性

- 资源所有权必须由当前会话用户与锁定目标的`user_id`同时校验；不得相信客户端的目标、资格、考纲或用户范围。
- 日志只记录当前用户、旧/新目标 ID、旧/新资格 ID、请求号、旧版本、放弃会话数量、结果错误码和`traceId`；不记录题干、答案、快照 JSON、错题、画像分值、报名信息或会话草稿。
- `cm_user_goal_change`为追加审计表，严禁更新或删除。`before_data/after_data`写入前使用既有版本化 JSON 工厂校验。
- 不通过异步补偿把半次切换“补齐”。事务失败后由同一幂等请求重试或重新发起；只有完整成功事务可改变当前进行中目标。

## 9. 验收用例

1. 有进行中“系统架构设计师”目标、无未交卷会话，切换到“系统分析师”成功：旧目标`paused`、新目标`active`、两条审计均存在、`daily_minutes`相同、仅一条`active`目标。
2. 旧目标有一条`created`和一条`in_progress`会话，预检返回两项影响；未确认提交返回`GOAL_SWITCH_CONFIRM_REQUIRED`且无任何数据变化；确认后两会话均为`cancelled`，旧目标暂停，新目标创建。
3. 旧目标有已提交或处理中会话：切换不删除、不重写其历史会话、报告、错题或画像；新目标不引用这些记录。
4. 选择当前同一资格返回`GOAL_SWITCH_SAME_CERTIFICATION`，旧目标、审计和会话均不变。
5. 使用过期批次、停用资格、伪造考纲、伪造每日时长、伪造旧目标 ID、伪造用户 ID分别被拒绝，且不产生部分记录。
6. 两个设备读取版本3；设备 A 切换成功后设备 B 用版本3提交，返回`GOAL_VERSION_CONFLICT`，不会暂停 A 创建的新目标。
7. 同请求号同载荷重复提交只回放首次成功响应；同请求号不同载荷或跨用户请求号碰撞返回`GOAL_SWITCH_IDEMPOTENCY_CONFLICT`。
8. 并发切换不同资格时，最终只有一个成功事务、仅一个进行中目标、无孤立新目标、无部分会话取消；另一个请求按幂等或版本冲突处理。
9. 无进行中目标访问 GET 或 POST 返回`LEARNING_GOAL_NOT_ACTIVE`；前端前往首次目标设置，不使用本切换接口创建首目标。
10. 数据库迁移后，同一用户允许一条`active`加多条`paused`目标；两条`active`仍被`uk_cm_user_goal_active`拒绝；同一次切换能写入两条审计，审计不可更新或删除。
