# U03 首次学习目标设置后端接口契约

```yaml
contract_id: learning-goal-onboarding-u03
contract_version: 1.0
module: U03
route: /learning/onboarding
scope: first_goal_only
status: review_pending
updated_at: 2026-08-12
```

## 1. 目标与边界

本契约定义学员首次流程中、且尚无有效学习目标时的目标设置接口。用户选择考试资格、目标考试年月和每日学习时长；保存成功后固定进入首次诊断说明页。

本页面只用于首次创建目标，不用于编辑、暂停、恢复或查看历史目标。已有`active`或`paused`目标的用户不得加载设置选项或再次创建目标；后续“调整学习目标”必须使用独立页面和独立契约。

“首次流程”不等同于登录次数：用户第一次登录后中途退出、但尚未创建目标时，下次登录仍按`SET_GOAL`回到本页面；创建目标后，后续状态由首次诊断进度决定，不再以`firstLogin`判断。

本契约不创建诊断会话、不维护官方考试安排、不实现题集维护或数据库迁移。诊断说明、预检和会话创建由首次诊断契约定义。

如与旧页面设计中“前端选择考纲”“考试日期不进入目标”“每日时长10～240分钟”的描述冲突，以本契约为准。

## 2. 冻结业务规则

1. 仅 onboarding 状态的`nextAction=SET_GOAL`可以进入`/learning/onboarding`。
2. 页面不显示、也不提交考纲；服务端为所选资格确定当前可用于首次诊断的考纲版本。
3. 用户填写的目标考试批次由`targetExamYear + targetExamMonth`组成，是学习目标事实，不等同于官方`cm_exam_schedule.exam_date`。
4. 选项按服务端`Asia/Shanghai`时间生成：当前年到往后4年；月份仅5月、11月；目标年月必须严格晚于服务端当前年月。
5. 每日学习时长为15～300分钟，默认30分钟。
6. 创建成功时只创建学习目标及其变更快照，固定返回`START_DIAGNOSTIC`；前端映射到`/learning/diagnostic/intro`并使用`router.replace`。
7. 创建目标后、诊断会话创建前，如果首次诊断资源下架、失效或无法唯一确定，诊断创建接口必须阻断并返回资源未就绪错误；不得静默换用新版题集。
8. 已创建诊断会话始终使用自己的冻结快照；后续题集变更不改写会话。

### 2.1 U03 页面内容与流程边界

页面只呈现以下用户可见内容：

1. 标题“设置学习目标”及简短说明：保存后将进入首次诊断说明，首次诊断用于了解当前基础；
2. 目标资格下拉选择；
3. 考试批次的年份、月份两个下拉选择；
4. 每天学习时长输入，展示单位“分钟”；
5. 主操作“保存学习目标，开始首次诊断”；
6. 加载、字段错误、选项失效和服务端失败的明确反馈。

页面不展示或允许用户操作以下内容：

- 考纲选择、官方考试具体日期、考试场次或倒计时；
- 首次诊断题目、答案、解析、提示、分数、报告或画像；
- “跳过首次诊断并进入正常学习首页”的入口；
- 用户ID、诊断会话ID、诊断完成状态或服务端返回的任意 URL。

保存学习目标不是开始答题。成功后仅进入诊断说明页，由诊断说明页展示50题、预计时间、诊断边界、暂停恢复和交卷后果，并由其“开始诊断”操作创建或恢复会话。

## 3. 共同约定

### 3.1 响应和错误包络

所有接口使用现有`R<T>`响应包装。前端以`R.code`决定行为，不只依赖真实 HTTP 状态；HTTP 状态沿用框架全局异常处理，不作为本契约的额外兼容承诺。

```ts
interface ApiResponse<T> {
  code: number;
  msg: string;
  data?: T;
}

interface ContractErrorVo {
  errorCode: string;
  retryable: boolean;
  traceId: string | null;
  fieldErrors: Array<{
    field: string;
    code: 'REQUIRED' | 'INVALID_FORMAT' | 'OUT_OF_RANGE' | 'DUPLICATE' | 'NOT_FOUND' | 'UNSUPPORTED';
    message: string;
  }>;
}
```

所有本契约定义的失败响应均返回`R<ContractErrorVo>`。前端以`data.errorCode`执行刷新、分流、重试或字段提示，`msg`仅作脱敏展示兜底。`fieldErrors.field`使用请求 JSON 的 camelCase 字段路径；无字段错误时固定返回空数组。

```json
{
  "code": 409,
  "msg": "当前用户已有有效学习目标",
  "data": {
    "errorCode": "GOAL_ALREADY_EXISTS",
    "retryable": false,
    "traceId": null,
    "fieldErrors": []
  }
}
```

错误响应不得包含 SQL、内部堆栈、令牌、密码、题目答案、对象存储键或其他用户资料。

### 3.2 身份、权限与所有权

- 接口要求已登录学员身份；用户ID从当前会话取得，请求不得传递或覆盖`userId`。
- `GET /api/learning/goals/options`要求`certmuse:learning:onboarding:query`。
- `POST /api/learning/goals`要求`certmuse:learning:goal:create`。
- 非学员身份或无权限返回`LEARNING_GOAL_FORBIDDEN`；不得读取或写入学员目标数据。
- 前端进入页面前、直接输入 URL、刷新及重新登录后都查询`GET /api/learning/onboarding/status`。只有`SET_GOAL`渲染此页面；未知枚举进入安全错误态。
- 收到`START_DIAGNOSTIC`时，前端本地映射至`/learning/diagnostic/intro`；收到其他状态时使用统一 onboarding 白名单映射，U03 页面自身不得猜测或覆盖服务端状态。
- U03 页面不提供绕过首次流程的普通学习首页跳转。用户离开或再次访问其他受保护学习页面时，路由守卫仍应依据 onboarding 状态分流。

### 3.3 幂等请求号

所有写请求必须携带请求头：

```http
X-Request-Id: <UUID>
```

请求体不允许出现`requestId`。请求号长度1～100字符，前端使用`crypto.randomUUID()`生成。

请求号为全局唯一：现有`cm_user_goal_change.request_id`已采用全局唯一约束。跨用户碰撞返回冲突，但不得泄露原请求所属用户或目标。

生命周期固定为：

1. 一次用户主动提交生成一个请求号；
2. 网络失败或`R.code=500`重试时复用该请求号及相同规范化载荷；
3. 用户修改任一业务字段后再次主动提交时生成新请求号；
4. 页面刷新后不保留请求号；刷新后的页面必须先按 onboarding 权威状态分流。

按钮 loading、`repeatSubmit`和防抖只优化交互，不构成后端幂等保障。

幂等优先级：

1. 相同`X-Request-Id`与相同规范化载荷：返回第一次已持久化的成功结果；
2. 相同`X-Request-Id`与不同规范化载荷：返回409 `GOAL_IDEMPOTENCY_CONFLICT`；
3. 新`X-Request-Id`但已有有效目标：返回409 `GOAL_ALREADY_EXISTS`。

规范化载荷固定为`certificationId`、`targetExamYear`、`targetExamMonth`、`dailyMinutes`。数据库唯一约束是最终保证；Redis 锁仅可减少并发竞争。

## 4. 获取首次目标设置选项

```http
GET /api/learning/goals/options
```

无查询参数和请求体。

### 4.1 成功响应

```ts
interface CertificationOptionVo {
  id: string;
  code: string;
  name: string;
}

interface ExamYearOptionVo {
  year: number;
  months: Array<5 | 11>;
  selectable: boolean;
}

interface LearningGoalOptionsVo {
  serverTime: string;
  timezone: 'Asia/Shanghai';
  certifications: CertificationOptionVo[];
  examYears: ExamYearOptionVo[];
  dailyMinutes: {
    min: 15;
    max: 300;
    defaultValue: 30;
  };
  defaults: {
    certificationId: string | null;
    examYear: number;
    examMonth: 5 | 11;
  } | null;
}
```

服务端时间为`2026-08-12`时的示例：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "serverTime": "2026-08-12T10:00:00+08:00",
    "timezone": "Asia/Shanghai",
    "certifications": [
      {
        "id": "900000000000000001",
        "code": "SYSTEM_ARCHITECT",
        "name": "系统架构设计师"
      }
    ],
    "examYears": [
      { "year": 2026, "months": [11], "selectable": true },
      { "year": 2027, "months": [5, 11], "selectable": true },
      { "year": 2028, "months": [5, 11], "selectable": true },
      { "year": 2029, "months": [5, 11], "selectable": true },
      { "year": 2030, "months": [5, 11], "selectable": true }
    ],
    "dailyMinutes": { "min": 15, "max": 300, "defaultValue": 30 },
    "defaults": {
      "certificationId": "900000000000000001",
      "examYear": 2026,
      "examMonth": 11
    }
  }
}
```

### 4.2 生成和前端消费规则

1. `certifications`只返回启用且当前具备可用首次诊断资源的资格，按业务排序、ID排序。
2. `examYears`始终返回当前年到往后4年。当前年无未来候选月份时，返回`months=[]`和`selectable=false`；前端必须禁用该年份。
3. 前端只渲染响应中的资格、年份和月份，不自行补充年份或月份，不使用浏览器时间判断合法性。
4. `defaults`选择第一个可用资格及时间上最近的未来批次；无可用资格或批次时返回`null`。
5. 当前用户已有`active`或`paused`目标时返回409 `GOAL_ALREADY_EXISTS`，前端必须重新查询 onboarding 状态并分流；不得返回空 options 伪装为无可选项。
6. options 加载失败时，页面只展示加载失败及“重新加载”操作；不得回退到本地写死的资格、年份、月份或浏览器时间计算。

## 5. 创建首次学习目标

```http
POST /api/learning/goals
Content-Type: application/json
X-Request-Id: 0f7cd9a8-4b29-4ba5-b202-b7fb5aac85dd
```

### 5.1 请求

```ts
interface CreateLearningGoalRequest {
  certificationId: string;
  targetExamYear: number;
  targetExamMonth: 5 | 11;
  dailyMinutes: number;
}
```

```json
{
  "certificationId": "900000000000000001",
  "targetExamYear": 2026,
  "targetExamMonth": 11,
  "dailyMinutes": 30
}
```

| 字段 | 必填 | 规则 |
| --- | ---: | --- |
| `certificationId` | 是 | 十进制正整数；资格必须启用且当前可用于首次诊断。 |
| `targetExamYear` | 是 | 服务端当前年到往后4年。 |
| `targetExamMonth` | 是 | 只能为5或11；与年份组合后严格晚于服务端当前年月。 |
| `dailyMinutes` | 是 | 整数，15～300。 |

请求不得包含`userId`、`goalId`、`status`、`version`、`requestId`、`syllabusVersionId`、考纲名称、官方考试日期、场次ID、诊断状态或任意跳转 URL。

### 5.2 服务端处理

服务端必须在同一事务中：

1. 重新检查当前用户没有`active`或`paused`目标；
2. 使用当前`Asia/Shanghai`时间重新校验目标年月和每日时长；
3. 校验资格启用；
4. 从所选资格当前唯一可用的`FIRST_DIAGNOSTIC`题集及其发布修订确定`syllabus_version_id`，前端不能覆盖；
5. 创建`cm_user_goal`和`cm_user_goal_change`；
6. 写入全局唯一的`request_id`、目标快照和审计信息；
7. 返回目标和`START_DIAGNOSTIC`，但不创建`cm_learning_session`。

无法唯一确定考纲、题集或发布修订，或者首次诊断资源不完整时，整体回滚并返回422 `FIRST_DIAGNOSTIC_NOT_READY`。

### 5.3 成功响应

```ts
interface CreateLearningGoalResultVo {
  goal: {
    id: string;
    certificationId: string;
    certificationName: string;
    syllabusVersionId: string;
    syllabusVersionName: string;
    targetExamYear: number;
    targetExamMonth: 5 | 11;
    dailyMinutes: number;
    status: 'ACTIVE';
    version: number;
  };
  nextAction: 'START_DIAGNOSTIC';
}
```

前端只允许把`START_DIAGNOSTIC`映射到`/learning/diagnostic/intro`，并使用`router.replace`跳转；不接受服务端 URL，不伪造会话ID或诊断完成状态。

创建请求进行期间，前端禁用重复点击并显示保存中；这不影响第3.3节规定的服务端幂等责任。

### 5.4 选项过期

用户停留页面期间，目标年月、资格或资源可能失效。创建接口永远使用写入时状态重新校验：

- 收到`TARGET_EXAM_BATCH_INVALID`时，前端重新请求 options，保留资格和每日时长，清除或重选失效年月；
- 收到`CERTIFICATION_UNAVAILABLE`时，前端重新请求 options，清除已失效资格和相关目标年月；
- 收到`GOAL_ALREADY_EXISTS`时，前端重新查询 onboarding 状态并分流；
- 收到`FIRST_DIAGNOSTIC_NOT_READY`时，前端保留输入并提示“首次诊断暂不可开始”，不创建部分目标。

## 6. 错误码

| `R.code` | `data.errorCode` | 条件 | `retryable` | 前端动作 |
| --- | --- | --- | ---: | --- |
| 400 | `GOAL_REQUEST_INVALID` | 缺失字段、未知字段、ID格式或类型不合法。 | false | 展示字段错误。 |
| 400 | `TARGET_EXAM_BATCH_INVALID` | 年月到期、超过范围或月份不是5/11。 | false | 刷新 options 后重选年月。 |
| 400 | `DAILY_MINUTES_OUT_OF_RANGE` | 每日时长不在15～300。 | false | 自动纠正边界并提示。 |
| 401 | `UNAUTHORIZED` | 未登录或会话失效。 | false | 进入登录流程。 |
| 403 | `LEARNING_GOAL_FORBIDDEN` | 非学员身份或无接口权限。 | false | 停止操作并显示无权限。 |
| 409 | `GOAL_ALREADY_EXISTS` | 已有`active`或`paused`目标。 | false | 查询 onboarding 状态并分流。 |
| 409 | `GOAL_IDEMPOTENCY_CONFLICT` | 相同请求号对应不同规范化载荷，或跨用户发生请求号碰撞。 | false | 停止自动重试并刷新状态。 |
| 422 | `CERTIFICATION_UNAVAILABLE` | 资格已停用或不再可用于首次目标。 | false | 刷新 options。 |
| 422 | `FIRST_DIAGNOSTIC_NOT_READY` | 无法唯一确定或校验首次诊断资源。 | true | 保留输入并提示稍后重试。 |
| 500 | `LEARNING_GOAL_CREATE_FAILED` | 未分类系统故障。 | true | 使用原请求号重试；展示 traceId。 |

## 7. 数据前置条件与快照兼容

实现前必须通过正式数据库迁移为`cm_user_goal`增加：

- `target_exam_year integer NOT NULL`；
- `target_exam_month smallint NOT NULL CHECK (target_exam_month IN (5, 11))`。

目标考试年月不与官方考试安排建立外键，也不覆盖官方考试日期。

`cm_user_goal_change.before_data/after_data`继续使用`user_goal_snapshot/1.0`，不升级 schema 版本。其`goal`对象中的`targetExamYear`与`targetExamMonth`规则固定为：

- 历史快照允许两个字段都缺失；
- 本契约数据库迁移上线后新写入的快照必须同时包含两个字段；
- 两字段只能同时存在或同时缺失；
- 存在时，`targetExamYear`为整数，`targetExamMonth`只能为5或11。

主目标、目标变更快照、请求号和审计记录必须在同一事务完成；不得只写主表而遗漏快照。

## 8. 验收断言

1. 非`SET_GOAL`用户无法通过直接 URL、刷新或重新登录停留在 onboarding 页面。
2. 前端只渲染 options 返回的批次；服务端当前为2026年5月时，2026年只返回11月。
3. 当前为2026年11月或12月时，2026年为`selectable=false`，默认批次为2027年5月。
4. 前端篡改月份、年份、时长或考纲字段时，服务端拒绝且不部分创建目标。
5. 同一请求号、相同载荷只产生一个目标和一条变更记录；不同载荷返回幂等冲突。
6. 新请求号但已有目标返回`GOAL_ALREADY_EXISTS`；GET options同样返回该冲突而非空列表。
7. 选项过期后前端刷新 options 并重选失效值，不按浏览器时间猜测合法性。
8. 创建成功后只返回`START_DIAGNOSTIC`，前端 replace 到诊断说明页，不创建或伪造诊断会话。
9. 首次诊断资源变更后，未创建会话的诊断创建请求被阻断；已创建会话仍读取自己的冻结快照。
10. 新目标快照包含目标考试年月；历史1.0快照缺少这两个字段仍可读取。
11. 页面仅展示第2.1节列出的目标设置信息；不出现考纲选择、诊断题目、答案、提示、模拟结果或跳过首次诊断入口。
12. 创建目标成功后只进入诊断说明页；尚未点击诊断说明页的“开始诊断”前，系统不存在诊断会话。
