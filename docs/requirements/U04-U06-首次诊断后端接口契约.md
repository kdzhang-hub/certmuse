```yaml
contract_id: first-diagnostic-u04-u06
contract_version: 1.1
module: U04-U06
routes:
  - /learning/diagnostic/intro
  - /learning/diagnostic/session
  - /learning/diagnostic/result
  - /learning/diagnostic/report
scope: first_diagnostic_lifecycle
status: implemented
updated_at: 2026-08-12
```

## 1. 目标与边界

本契约实现首次诊断的说明、创建或恢复同一份不少于10题的会话、作答保存、暂停、交卷、评分与结果生成状态、报告和初始画像读取、失败后的结果重试。

它落实《CertMuse 首次诊断业务与交互规则 V1.0》的业务闭环：诊断数据必须来自用户真实作答；中断、刷新、网络重试和换设备均恢复同一会话；交卷后不可修改；重复交卷不重复评分、报告、画像或学习结算；结果失败只恢复结果生成，不要求重新答题。

本契约不包含学习目标创建（见 U03）、题集编辑发布、评分算法细节、画像规则参数、日常练习、错题订正和任务生成的具体实现。

### 1.1 后端计算与前端兼容边界

首次诊断的评分、单题有效用时、整场有效用时、时间系数、叶子知识点证据、结算、知识点/科目/总体画像聚合、可信度、效率与风险、画像变化审计，全部由后端基于会话冻结快照和服务端时间事实计算、持久化并幂等重试。前端不上传计时秒数、评分、证据或画像字段；但为使服务端确认题目实际可见时间，答题页必须调用本契约第5.5节的计时事件接口。

前端继续只消费本契约既有的诊断状态、`nextAction`、题目作答快照、保存结果、处理阶段和报告响应。报告中的既有“已覆盖知识点初步表现”“优先学习方向”“数据充足程度/可信度”“初始画像摘要”由后端填充真实聚合结果；前端未展示的证据明细、结算参数、单题计时、内部评分与画像审计不得返回。

除第5.5节新增计时事件接口以及第5.1节增加的时间事实字段外，实现上述后端事实链不得改变既有接口 URL、HTTP 方法、请求字段、响应字段类型或固定枚举；本轮不得修改前端代码。若后续需要向前端展示新的画像细节，必须通过新的版本化接口契约单独批准。

管理端是本契约的内容前置：每个考试资格任意时刻只能有一个已发布、可用于新用户的`FIRST_DIAGNOSTIC`题集；它必须不少于10题、覆盖资格下三个有效考试科目，且所有题目修订、评分点和叶子知识点映射完整。叶子知识点必须配置重要度`1`、`2`或`3`，非叶子知识点的`importance`必须为`null`；任一映射叶子缺失重要度均阻断题集发布和学员端会话创建。学员端不在多份题集中选择。

## 2. 权威状态与固定分流

### 2.1 状态

服务端以当前用户有效目标、首次诊断会话、报告和画像生成状态共同计算下列状态：

| `diagnosticStatus` | 含义 | 用户可进入页面 |
| --- | --- | --- |
| `NOT_STARTED` | 有效目标存在，尚无有效首次诊断会话 | 诊断说明页 |
| `IN_PROGRESS` | 已创建且未交卷的会话 | 同一答题页 |
| `PROCESSING` | 已交卷，评分、报告或画像仍在处理 | 结果处理页 |
| `COMPLETED` | 报告和初始画像均已生成 | 诊断报告页 |
| `FAILED` | 答卷保留，但评分、报告或画像生成失败 | 结果异常页 |

`cm_learning_session.session_type='initial_diagnosis'`是首次诊断唯一会话类型。数据库会话状态到上述状态的映射必须由服务端集中实现，前端不得根据 URL、登录次数、localStorage 或题目数量推断。

首次诊断永久绑定创建时的`goalId`、考试资格、考纲版本和目标考试年月快照。后续仅调整每日学习时长或目标考试批次不影响原会话；切换资格或考纲时保留旧会话、报告和画像为历史，并要求新范围完成新的首次诊断。存在`IN_PROGRESS`会话时，服务端拒绝切换资格或考纲。学员没有取消诊断接口，只能暂停、退出和恢复；管理员异常取消必须记录原因，且不能成为用户绕过首次流程的途径。

### 2.2 路由白名单

服务端只返回固定枚举，绝不返回任意 URL。前端本地映射如下：

| `nextAction` | 本地路由 |
| --- | --- |
| `START_DIAGNOSTIC` | `/learning/diagnostic/intro` |
| `CONTINUE_DIAGNOSTIC` | `/learning/diagnostic/session` |
| `WAIT_PROCESSING` | `/learning/diagnostic/result` |
| `VIEW_DIAGNOSTIC_REPORT` | `/learning/diagnostic/report` |
| `RETRY_DIAGNOSTIC_RESULT` | `/learning/diagnostic/result?mode=failed` |

进入首次流程页面前、直接输入 URL、刷新和重新登录后，前端必须调用现有`GET /api/learning/onboarding/status`。其状态不是当前页面所允许状态时，前端 replace 到本地表中的目标；未知枚举进入安全错误态。

`VIEW_DIAGNOSTIC_REPORT`和`RETRY_DIAGNOSTIC_RESULT`是统一 onboarding 枚举的诊断结果扩展值。诊断状态为`COMPLETED`或`FAILED`时，`GET /api/learning/onboarding/status`必须优先返回这两个枚举，而不再以`ENTER_HOME`、`RETRY_DIAGNOSTIC`或`CONTACT_SUPPORT`表达诊断报告或结果重试。既有`ENTER_HOME`、`RETRY_DIAGNOSTIC`和`CONTACT_SUPPORT`继续保留给非诊断结果的兼容场景。

## 3. 通用响应、权限和请求号

所有接口使用`R<T>`。本契约的业务失败统一使用`R<DiagnosticErrorVo>`：

```ts
interface DiagnosticErrorVo {
  errorCode: string;
  retryable: boolean;
  traceId: string | null;
  nextAction: 'START_DIAGNOSTIC' | 'CONTINUE_DIAGNOSTIC' | 'WAIT_PROCESSING' | 'VIEW_DIAGNOSTIC_REPORT' | 'RETRY_DIAGNOSTIC_RESULT' | null;
  fieldErrors: Array<{
    field: string;
    code: 'REQUIRED' | 'INVALID_FORMAT' | 'OUT_OF_RANGE' | 'DUPLICATE' | 'NOT_FOUND' | 'UNSUPPORTED' | 'VERSION_CONFLICT';
    message: string;
  }>;
}
```

前端读取`R.code`和`data.errorCode`决定业务异常的行为，`msg`仅作脱敏展示兜底。诊断业务异常统一使用`DiagnosticErrorVo`；401/403沿用现有全局`R.fail`认证和授权异常格式，不承诺携带`DiagnosticErrorVo`，前端按`R.code`进入登录流程或显示无权限。响应不暴露答案、解析、评分规则原文、SQL、堆栈、令牌、单题计时事实、证据明细、结算参数、画像审计或其他用户数据。

所有写接口要求`X-Request-Id`请求头，长度1～100字符，推荐`crypto.randomUUID()`。请求体不得重复传`requestId`。请求号全局唯一；跨用户碰撞返回幂等冲突，不泄露原对象。

同一写接口的优先级固定为：

1. 相同请求号与相同规范化载荷：返回第一次已持久化结果；
2. 相同请求号与不同规范化载荷：409 `DIAGNOSTIC_IDEMPOTENCY_CONFLICT`；
3. 新请求号但当前状态不允许动作：返回对应状态冲突。

一次用户主动动作生成一个请求号；网络失败或`R.code=500`重试时复用；用户改动答案、操作对象或重新发起动作时生成新请求号；刷新页面后不持久化请求号。前端 loading、按钮禁用和防抖不替代服务端幂等。

全部接口要求当前学员身份及`certmuse:learning:diagnostic`权限。用户ID从会话取得；所有会话、题目、草稿、报告和重试查询都必须加当前`user_id`条件。

## 4. 诊断说明与会话创建

### 4.1 预检

```http
GET /api/assessment/diagnostics/preflight
```

成功返回：

```ts
interface DiagnosticPreflightVo {
  goal: {
    id: string;
    certificationId: string;
    certificationName: string;
    syllabusVersionId: string;
    syllabusVersionName: string;
    version: number;
  };
  diagnosticStatus: 'NOT_STARTED' | 'IN_PROGRESS' | 'PROCESSING' | 'COMPLETED' | 'FAILED';
  nextAction: 'START_DIAGNOSTIC' | 'CONTINUE_DIAGNOSTIC' | 'WAIT_PROCESSING' | 'VIEW_DIAGNOSTIC_REPORT' | 'RETRY_DIAGNOSTIC_RESULT';
  diagnosticRevision: {
    id: string;
    questionCount: number; // 不少于10
    estimatedMinutes: number;
    subjectBreakdown: Array<{ examSubjectId: string; subjectName: string; questionCount: number }>;
  } | null;
  existingSession: {
    id: string;
    answeredCount: number;
    totalCount: number;
    lastQuestionOrder: number;
    sessionVersion: number;
  } | null;
  blockers: Array<{ code: string; message: string }>;
}
```

`goal.version` 为当前有效学习目标的 `rowVersion`，以 JSON number 返回；仅在 `goal` 非空时返回。客户端在创建会话时将该值原样作为既有 `goalVersion` 传入；预检后目标更新时，既有创建接口继续返回目标版本冲突，客户端应重新预检。

`NOT_STARTED`时必须返回有效且不少于10题的`diagnosticRevision`；`IN_PROGRESS`时返回同一会话进度；其余状态不返回可创建的诊断修订。诊断说明页展示资格、实际题量、预计时间、诊断不代表正式考试成绩、答题过程中不展示答案/解析/提示/对错、可暂停恢复、交卷后不可修改、完成后生成报告和初始画像。

### 4.2 创建或恢复会话

```http
POST /api/assessment/diagnostics
X-Request-Id: <UUID>
```

```ts
interface StartDiagnosticRequest {
  diagnosticRevisionId: string;
  goalVersion: number;
}

interface StartDiagnosticResultVo {
  sessionId: string;
  status: 'IN_PROGRESS';
  resumed: boolean;
  answeredCount: number;
  totalCount: number;
  resumeQuestionOrder: number;
  sessionVersion: number;
}
```

创建规则：

1. `NOT_STARTED`时，服务端校验请求中的目标版本和诊断修订仍是该资格唯一可用、已发布且完整的首次诊断资源；然后原子创建唯一会话、冻结该题集的全部题目及其题序、题目修订、展示快照、评分点、知识点映射、画像规则版本和目标考试年月快照。
2. 只要当前用户、当前目标存在`IN_PROGRESS`首次诊断会话，任何“开始诊断”请求均返回原会话和`resumed=true`，不受新旧`X-Request-Id`或请求中诊断修订ID影响；只有相同请求号对应不同规范化载荷时返回`DIAGNOSTIC_IDEMPOTENCY_CONFLICT`。不得产生第二份诊断。
3. 已交卷、处理中、完成或失败时，返回409 `DIAGNOSTIC_STATE_CONFLICT`并附当前`nextAction`，前端按白名单分流。
4. 预检之后资源被下架、替换、题量少于10、题集声明题量与冻结题量不一致或快照无法完整冻结时，返回422 `FIRST_DIAGNOSTIC_NOT_READY`；不得静默改用新版题集。

恢复位置统一采用“上次成功保存的位置”；首次未保存位置为第1题。若该位置已交卷或不存在，服务端返回第一道未答题；全部已答但未交卷时返回冻结题单的最后一题。

## 5. 答题会话、题目和草稿

### 5.1 会话摘要

```http
GET /api/assessment/diagnostics/{sessionId}
```

返回会话摘要、`sessionVersion`、`currentQuestionOrder`、`answeredCount`、`unansweredCount`和与冻结题量一致的导航项。导航项只包含题序及`CURRENT`、`ANSWERED`、`UNANSWERED`状态，不包含答案、对错、分数、解析或知识点结论。

会话是`IN_PROGRESS`时可编辑；`PROCESSING/COMPLETED/FAILED`时返回对应`nextAction`且只读。非所有者与不存在会话对外统一404。

### 5.2 读取题目

```http
GET /api/assessment/diagnostics/{sessionId}/items/{questionOrder}
```

返回本会话冻结的`QuestionSnapshotForAnsweringVo`、最近一次成功保存的`answer`、`answerSaveState='SAVED'`和当前`sessionVersion`。题目内容只包含答题所需展示与作答结构，不返回正确答案、解析、单题判分、提示或中间画像结论。

路径中的`questionOrder`为冻结题单范围内的正整数。会话恢复后题目身份、顺序、题目修订和快照永远不变。

### 5.5 题目可见计时事件

```http
POST /api/assessment/diagnostics/{sessionId}/timer-events
X-Request-Id: <UUID>
```

```ts
interface DiagnosticTimerEventRequest {
  eventType: 'ENTER' | 'HEARTBEAT' | 'HIDDEN' | 'LEAVE';
  questionOrder: number;
  leaseId: string | null;
}

interface DiagnosticTimerEventVo {
  eventAccepted: boolean;
  leaseId: string | null;
  questionOrder: number;
  timerState: 'RUNNING' | 'STOPPED' | 'REPLACED';
  estimatedDurationSeconds: number;
  effectiveElapsedSeconds: number;
  serverTime: string;
}
```

前端在当前题真实渲染完成且页面可见后发送`ENTER`；批量预取题目不得发送。`ENTER`成功后保存返回的`leaseId`，页面可见期间每`10`秒发送`HEARTBEAT`。切题、隐藏、暂停、交卷和离开答题页时发送`HIDDEN`或`LEAVE`；新题或重新进入同一题后再次发送`ENTER`。同一题多次进入产生的服务端确认区间在该题原有效用时上连续累加，草稿保存不停止计时。

服务端同一会话同一时刻仅允许一个租约；新窗口或新设备的`ENTER`替换旧租约，旧租约响应`REPLACED`且不继续计时。超过`20`秒无有效心跳时，服务端关闭区间、保留已确认秒数，并将该题时间事实标记为无效；时间系数固定为`1.00`，不产生超时、速度或时间风险结论。计时事件不得递增`sessionVersion`。后端仅返回权威累计时间和服务端时间；倒计时与“超时 00:00”后的正向展示由前端本地完成并在心跳、刷新、恢复、重连或换设备后校准。

### 5.3 保存草稿和位置

```http
PUT /api/assessment/diagnostics/{sessionId}/items/{questionOrder}/draft
X-Request-Id: <UUID>
```

```ts
interface SaveDiagnosticDraftRequest {
  answer: unknown;
  expectedSessionVersion: number;
  currentQuestionOrder: number;
}

interface SaveDiagnosticDraftResultVo {
  savedAt: string;
  answered: boolean;
  answeredCount: number;
  sessionVersion: number;
}
```

创建会话时，服务端为每道`cm_session_question`创建唯一的`cm_question_attempt(attempt_no=1,status=in_progress)`与唯一的`cm_attempt_answer(grading_status=pending)`；初始`answer_data`为该题答案 schema 的空答案。

`answer`按冻结题目修订的答案模式校验；未选择答案可提交空答案，仅表示该题未答。每次草稿保存只更新该题唯一`cm_attempt_answer.answer_data/update_time`，并原子更新会话最后位置、已答统计和`sessionVersion`，不得创建第二条 attempt 或 answer。未交卷前同题可多次保存，最后一次成功保存值为恢复值；交卷时冻结同一条答案记录并将 attempt 转为`submitted`，之后禁止更新`answer_data`。

`expectedSessionVersion`不一致时返回409 `DIAGNOSTIC_SESSION_VERSION_CONFLICT`，响应`fieldErrors`标注`expectedSessionVersion`。前端重新读取会话摘要与当前题，提示“其他设备已有新进度，已同步最新内容”，不得静默覆盖。当前题保存失败时保留本地选择，显示“保存失败，请重试”；未收到成功响应不得显示“已保存”。

### 5.4 暂停

```http
POST /api/assessment/diagnostics/{sessionId}/pause
X-Request-Id: <UUID>
```

请求体为`{ "currentQuestionOrder": number, "expectedSessionVersion": number }`。暂停不取消会话、不改变题目、不清空答案，也不将会话改成终态；成功后仅持久化最后位置和审计事件。学员没有取消接口。用户确认暂停后可以离开；再次进入必须恢复同一会话。

若当前答案仍在保存，前端先完成或明确失败该保存请求，再允许调用暂停。直接关闭或离开页面时，已成功保存的答案和位置继续保留；前端可提示仍在保存的答案可能未保存，但后端不假称已保存。

## 6. 交卷、处理状态与结果重试

### 6.1 交卷预检

```http
GET /api/assessment/diagnostics/{sessionId}/finish-check
```

返回`answeredCount`、`unansweredCount`、`pendingSaveCount`、`sessionVersion`和`firstUnansweredQuestionOrder`。前端据此结合会话实际题量展示“完成N/N”或“还有N题未答”；允许未答题交卷，未答题如实保存为未作答，不自动填充答案。

`pendingSaveCount`只统计服务端已知的未完成写入；前端仍必须等待本地正在请求的草稿保存完成，不能以该字段代替本地保存状态。

### 6.2 确认交卷

```http
POST /api/assessment/diagnostics/{sessionId}/finish
X-Request-Id: <UUID>
```

```ts
interface FinishDiagnosticRequest {
  expectedSessionVersion: number;
}

interface FinishDiagnosticResultVo {
  sessionId: string;
  diagnosticStatus: 'PROCESSING';
  nextAction: 'WAIT_PROCESSING';
  submittedAt: string;
}
```

交卷规则：

1. 只允许`IN_PROGRESS`会话交卷；服务端验证版本和所有已提交草稿。
2. 原子冻结最终答案；没有保存答案的题创建“未作答”记录，不能伪造成错误或默认答案；会话转入`submitted/settling`，所有题目立即只读。
3. 同一事务创建或恢复唯一的`cm_async_job(job_type='DIAGNOSTIC_RESULT_PIPELINE', business_key='DIAGNOSTIC:{sessionId}')`。该任务 payload 保存`SCORING`、`REPORT_GENERATING`、`PROFILE_GENERATING`阶段状态、失败原因和traceId；评分任务、报告、画像和后续任务均由该编排任务幂等驱动，重复交卷不能创建第二次有效结算。
4. 成功后固定返回`WAIT_PROCESSING`。超时、刷新、换设备或重复点击以相同请求号重试时返回首次结果；使用新请求号再次交卷时也返回当前处理状态，不得再评分。
5. 交卷后的答题读取返回只读状态和`WAIT_PROCESSING`或报告/失败状态；不得恢复可编辑答案。

### 6.3 结果状态

```http
GET /api/assessment/diagnostics/{sessionId}/status
```

返回：

```ts
interface DiagnosticResultStatusVo {
  sessionId: string;
  diagnosticStatus: 'PROCESSING' | 'COMPLETED' | 'FAILED';
  nextAction: 'WAIT_PROCESSING' | 'VIEW_DIAGNOSTIC_REPORT' | 'RETRY_DIAGNOSTIC_RESULT';
  stages: Array<{
    code: 'SUBMITTED' | 'SCORING' | 'REPORT_GENERATING' | 'PROFILE_GENERATING' | 'COMPLETED';
    state: 'PENDING' | 'RUNNING' | 'COMPLETED' | 'FAILED';
  }>;
  failure: { message: string; traceId: string | null; retryAvailable: boolean } | null;
}
```

处理中前端展示“答卷已提交、正在评分、正在生成诊断报告、正在生成初始画像”的真实阶段；允许刷新或稍后查看，不允许回到答题修改。处理时间较长只能说明答卷已保存并可稍后查看，不得展示默认报告或画像。结果编排固定复用唯一`DIAGNOSTIC_RESULT_PIPELINE`异步任务；后端在`SCORING`阶段计算并冻结每题结果及服务端有效用时，在`REPORT_GENERATING`阶段生成报告，在`PROFILE_GENERATING`阶段生成证据、结算、画像聚合与报告同源结论。重试只从失败阶段继续，已成功阶段不重跑。

### 6.4 重新生成结果

```http
POST /api/assessment/diagnostics/{sessionId}/regenerate-result
X-Request-Id: <UUID>
```

仅`FAILED`且`retryAvailable=true`可调用。请求体为空。服务端复用同一会话、最终答案、冻结快照和`DIAGNOSTIC_RESULT_PIPELINE`，只重试失败的评分、报告、画像或任务生成阶段；不得新建会话、重新交卷、重复写入证据或要求用户重答。成功受理返回`PROCESSING/WAIT_PROCESSING`。

## 7. 诊断报告与初始画像

```http
GET /api/assessment/diagnostics/{sessionId}/report
```

报告读取按以下顺序判定：

1. 已存在`status='available'`的真实诊断报告时，返回该报告；即使整体`diagnosticStatus='FAILED'`，也不得因画像失败而隐藏已生成的真实报告。
2. 上述报告存在但初始画像失败时，响应必须标明`diagnosticStatus='FAILED'`、`profileStatus='FAILED'`和`nextAction='RETRY_DIAGNOSTIC_RESULT'`；前端显著提示“初始画像未生成”，允许重试结果，但不得提供进入学习首页入口。
3. 不存在可展示报告且整体状态为`PROCESSING`时，返回409 `DIAGNOSTIC_RESULT_PROCESSING`。
4. 不存在可展示报告且整体状态为`FAILED`时，返回409 `DIAGNOSTIC_RESULT_FAILED`。
5. 仅报告和初始画像均成功时，响应为`diagnosticStatus='COMPLETED'`，并允许进入学习首页。

报告成功响应至少包含`diagnosticStatus`、`profileStatus`和`nextAction`，以支持上述部分结果场景。

报告内容至少包含：学习目标/资格、诊断完成时间、总题数、已答和未答数量、真实正确/错误或总体正确率、分科表现、已覆盖知识点的初步表现、优先学习方向、数据充足程度/可信度、初始画像摘要及下一步学习入口。

未覆盖知识点必须表示“暂无数据”；证据不足表示“数据不足”或“待验证”。报告和初始画像对同一知识点必须使用同一结论来源。不得使用固定分数、固定薄弱项、随机数据、演示报告或默认画像。

前端据上述状态或错误码进入结果处理、结果异常或报告页。刷新报告不会重新评分、初始化画像或重复结算。

## 8. 事务、快照与数据前置条件

### 8.1 事务边界

- 会话创建：`cm_learning_session`、与冻结题量一致的`cm_session_question`、唯一的`cm_question_attempt`和空`cm_attempt_answer`、规则版本和幂等记录同一事务完成。
- 草稿保存：同一条`cm_attempt_answer`、会话最后位置、统计、会话版本、草稿幂等记录同一事务完成。
- 交卷：最终答案、未作答记录、会话状态、交卷幂等记录和唯一处理业务键同一事务完成。
- 结果重试：必须以已有会话和冻结快照为输入，幂等地创建或恢复处理工作；不得复制学习证据、报告或画像。

### 8.2 快照和禁止泄露

创建会话时冻结题目修订、题序、展示快照、评分快照、评分点、知识点映射、题目所属科目与画像规则版本。其 JSONB `schema_version`必须使用各既有结构规范中的已批准版本；新版本在迁移前不得临时写入。已创建会话永不引用“当前题目”替代快照。

会话主表字段保存可查询的冻结身份，且与题目快照共同构成历史事实：资格、考纲版本、题集发布修订、目标考试年月和画像规则版本均取创建时值。后续不得通过反查当前学习目标、当前题集或当前考纲替换这些冻结值。

### 8.3 必需迁移

现有表结构不足以持久化本契约的恢复和多设备并发规则。实现前新增有序 PostgreSQL 迁移，至少包括：

1. `cm_learning_session.last_question_order integer NOT NULL DEFAULT 1 CHECK (last_question_order >= 1)`；上限由服务端以冻结题单校验；
2. `cm_learning_session.row_version bigint NOT NULL DEFAULT 0 CHECK (row_version >= 0)`；
3. `cm_learning_session.certification_id bigint NOT NULL`、`syllabus_version_id bigint NOT NULL`、`collection_revision_id bigint NOT NULL`、`target_exam_year integer NOT NULL`和`target_exam_month smallint NOT NULL`；其中月份检查为`IN (5, 11)`，资格、考纲和题集修订建立外键；
4. 草稿写入的全局幂等记录，使用已有`cm_idempotency_record`并固定`action_code='DIAGNOSTIC_DRAFT_SAVE'`，或新增等价的全局唯一记录表；
5. 约束同一用户、同一目标最多一份有效`initial_diagnosis`会话（`created/in_progress/submitted/settling`）的部分唯一索引，已完成、已取消和已失效会话保留历史；
6. 复用`cm_async_job`并固定`DIAGNOSTIC_RESULT_PIPELINE`的唯一任务键和 payload schema；
7. 支持会话状态、草稿写入、交卷和结果重试的索引与状态迁移审计。

所有迁移必须同步更新数据库设计、约束验证脚本和本契约引用，不得直接改已部署迁移。

## 9. 认证与授权异常

401和403沿用现有全局`R.fail`格式，不要求或假设`data.errorCode`、`retryable`、`traceId`或`fieldErrors`存在。前端仅根据`R.code`处理：401清理失效会话并进入登录流程；403停止当前动作并显示统一无权限提示。认证/授权异常不列入第10节诊断业务错误码表。

| `R.code` | 响应 `data` | 条件 | 前端动作 |
| --- | --- | --- | --- |
| 401 | 无或沿用全局格式 | 会话失效、未登录或认证主体失效。 | 进入登录流程。 |
| 403 | 无或沿用全局格式 | 非学员身份或无诊断接口权限。 | 停止操作并显示无权限。 |

## 11. 验收断言

1. 保存有效目标后进入诊断说明，说明页展示资格、实际题量（不少于10题）、预计时间、诊断边界、暂停恢复、交卷后果和结果产物。
2. 首次点击开始创建一份且仅一份冻结题集会话；连续点击、刷新、断网重试或换设备再次开始均恢复同一会话。
3. 恢复会话时题目、题序、已保存答案、答题统计和上次成功保存位置完全一致；前端显示恢复进度。
4. 作答期间不返回或展示答案、解析、提示、单题对错、分数、正确率或能力结论。
5. 保存失败不清空本地答案且不显示已保存；多设备版本冲突不静默覆盖另一设备数据。
6. 用户可未答完交卷；交卷前看到已答/未答数量并经确认；未答题以未作答记录保存。
7. 交卷后所有题目只读。重复交卷只产生一次有效评分、报告、画像、证据和结算。
8. 处理页只显示真实处理阶段；长时间处理不显示默认结果、不要求重新答题。
9. 结果失败保留答卷；重新生成结果只恢复失败阶段，不创建新会话或重复画像/报告。
10. 报告和初始画像仅在真实评分完成后展示，随真实答案变化；未覆盖或证据不足知识点使用审慎状态。
11. 未完成首次流程时，任意受保护学习路由、刷新、直接 URL 和重新登录均按服务器状态回到对应首次流程步骤。
12. 所有写操作的相同请求号与相同载荷只返回首次结果；不同载荷返回幂等冲突。
13. 已有进行中会话时，任何“开始诊断”请求均恢复同一会话；学员没有取消入口，暂停和退出不改变会话内容。
14. 仅修改每日学习时长或目标考试批次不重做诊断；切换资格或考纲需要新的首次诊断，且进行中诊断时禁止切换。
15. 报告已生成但画像失败时，用户能查看真实报告但不能进入学习首页；结果重试只恢复失败阶段。
