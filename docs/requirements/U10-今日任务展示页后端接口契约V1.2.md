# U10 今日任务展示页后端接口契约 V1.2

> 状态：冻结实施基线。日期：2026-08-17。

## 1. 范围与不变量

本契约只定义任务列表、启动/继续、手动补充和自动补充。任务采用当前用户、当前 `active` 学习目标下的任务池模型，不含任务日期。

- 每项任务固定包含两个必需任务项，顺序为“知识点学习”“知识点练习”；学习不可跳过。
- 每项任务在生成时冻结 1–8 道单选题、最多 3 个已发布教材内容块和展示信息。合格题不少于 8 道时选择 8 道；不足 8 道时选择现有全部；没有合格题时不能生成该知识点任务。
- 练习完成以该任务实际冻结的全部题目均形成 `submitted` 有效提交为准，与正确率无关。
- 每项任务全生命周期只有一个 `session_type=daily_task` 会话。
- 同一用户、同一目标同时只能有一个未结束的 `daily_task` 会话；请求其他任务时返回当前任务，不创建新会话。
- 任务完成由两个 `cm_task_attempt(attempt_no=1,status=completed)` 事实推导，不保存任务状态。

## 2. 鉴权与公共约定

雪花 ID 使用十进制字符串，时间使用带时区 ISO-8601。`X-Request-Id` 必须为标准 UUID，服务端标准化为小写。真实 HTTP 状态等于 `R.code`。

权限均为 AND：

| 接口 | 权限 |
|---|---|
| 查询 | `certmuse:student` + `certmuse:learning:task:query` |
| 启动 | `certmuse:student` + `certmuse:learning:task:launch` |
| 补充 | `certmuse:student` + `certmuse:learning:task:supplement` |

## 3. 查询任务列表

`GET /api/learning/tasks`

请求参数：`keyword` 可选，去空格后 1–100 字符；`pageNum` 默认 1；`pageSize` 默认 10、范围 1–100。固定按 `create_time ASC,id ASC`。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "rows": [{
      "id": "1950000000000000001",
      "title": "架构风格专项学习",
      "phaseSummary": ["知识点学习", "知识点练习"],
      "knowledgePoint": "架构风格",
      "questionCount": 8,
      "completedQuestionCount": 3,
      "estimatedMinutes": 20,
      "updatedAt": "2026-08-17T09:30:00+08:00",
      "recommendation": "该知识点当前风险较高，建议优先巩固。",
      "action": "CONTINUE"
    }],
    "total": 1,
    "canShowSupplement": false
  }
}
```

列表只包含至少一个必需任务项尚无完成事实的任务。没有会话且没有任务项执行记录时 `action=START`，否则为 `CONTINUE`。`completedQuestionCount` 只统计该任务会话下 `submitted` 的题目提交。`total` 受关键词影响；`canShowSupplement` 使用未过滤可继续任务数，仅零任务时为 `true`。

## 4. 启动或继续任务

`POST /api/learning/tasks/{taskId}/launch`，请求头 `X-Request-Id` 必填，无请求体。

```json
{"code":200,"msg":"操作成功","data":{"taskId":"1950000000000000001","nextAction":"OPEN_LEARNING_CONTENT","sessionId":null}}
```

`questionCount` 是任务实际冻结题数，范围为 1–8。固定锁顺序为当前目标、当前活动任务会话、请求任务。首次启动内部创建唯一会话、复制该任务实际冻结的全部题目并创建学习项 `started` 记录；学习未完成时返回 `OPEN_LEARNING_CONTENT` 且对外 `sessionId=null`。学习项已完成时创建/读取练习项执行记录，将同一会话推进为 `in_progress`，返回 `OPEN_PRACTICE_SESSION` 和会话 ID。

若其他任务占用当前目标，返回 409 `TASK_SESSION_IN_PROGRESS`，`details` 包含 `currentTaskId/nextAction/sessionId`。已完成任务返回 `TASK_ALREADY_COMPLETED`；已有 `invalid/cancelled` 会话返回 `TASK_SESSION_NOT_RECOVERABLE`，均不得创建第二个会话。

## 5. 补充任务

`POST /api/learning/tasks/supplement`，请求头 `X-Request-Id` 必填，无请求体。自动调度在 `Asia/Shanghai` 每日 00:00 调用同一领域指令。

```json
{"code":200,"msg":"操作成功","data":{"beforeAvailableCount":0,"requestedCount":4,"createdCount":4,"refreshRequired":true}}
```

锁定目标后计算 `N` 和 `X=max(0,4-N)`。`X=0` 不检查规则和内容，但记录零创建批次。`X>0` 要求唯一已发布画像规则，算法版本为 `TASK_RECOMMENDATION_V1`。候选知识点必须启用推荐、属于目标考纲，并具有已发布教材内容和至少 1 道合格单选题；排除当前未完成任务池已使用的知识点和题目。每个候选知识点最多选择 8 道题：可选题不少于 8 道时冻结 8 道，不足 8 道时冻结现有全部。

风险顺序为 `urgent → weak → needs_retest → pending_verification → needs_review → expired → unassessed → provisional → learning → proficient → mastery_candidate → mastered`，同风险按重要度降序、知识点 ID 升序。题目优先从未有效提交，再按最近提交时间升序、题目 ID 升序。能生成 `1..X` 项即部分成功；零项才返回 `TASK_CONTENT_UNAVAILABLE`。

## 6. 失败响应

除认证/权限失败外，预期失败返回 `data.errorCode/retryable/traceId/fieldErrors/details`。字段错误码仅允许 `REQUIRED`、`INVALID_FORMAT`、`OUT_OF_RANGE`。

| HTTP | errorCode | 条件 |
|---:|---|---|
| 400 | `TASK_REQUEST_INVALID` | 请求参数、任务 ID 或请求号非法 |
| 404 | `TASK_NOT_FOUND` | 任务不存在、非本人或不属于当前目标 |
| 409 | `TASK_ALREADY_COMPLETED` | 两个必需项均已完成 |
| 409 | `TASK_IDEMPOTENCY_CONFLICT` | 请求号载荷冲突或仍在处理 |
| 409 | `TASK_SESSION_IN_PROGRESS` | 其他任务占用当前目标 |
| 409 | `TASK_SESSION_NOT_RECOVERABLE` | 唯一会话无效或已取消 |
| 422 | `LEARNING_GOAL_NOT_ACTIVE` | 没有唯一当前有效目标 |
| 422 | `TASK_CONTENT_UNAVAILABLE` | 需要补充但一项也无法生成 |
| 503 | `TASK_RULE_VERSION_UNAVAILABLE` | 已发布画像规则不是唯一一版 |
| 500 | `TASK_OPERATION_FAILED` | 未知异常由模块边界安全处理 |

## 7. 验收

覆盖分页和关键词、START/CONTINUE、有效提交与正确率无关、首次启动、学习完成后进入练习、其他任务占用、完成/不可恢复、幂等回放及冲突、`N=0/2/4/>4`、部分补充、内容/规则不可用、午夜分页调度、目标间失败隔离和多实例调度去重。
