# 学生端学习记录后端接口契约 V1

> 状态：待实施。日期：2026-08-19。
> 路由前缀：`/api/learning/history`。
> 消费端：学生端「学习记录」页。
> 2026-08-20更新：本文第4.6、4.7节旧模拟试卷历史已由《学生端统一考试历史后端接口契约V1》替换，旧`/simulations/**`不再提供兼容。
> 当前页面采用每日任务、题目历史、考试历史三个页签。它是只读查询契约，不创建、修改或删除任何学习事实。

## 1. 目标与边界

学习记录页帮助用户回顾已经发生的学习事实，而不是按每次作答简单罗列流水。页面按以下对象聚合：

- **每日任务**：一项完成的任务一行；详情列出该任务当时实际作答的冻结题目及对错。
- **题目历史**：当前目标下同一道题一行；详情按时间展示该题全部有效作答和订正情况。
- **模拟试卷历史**：当前目标下同一逻辑模拟卷一行；详情展示历次完成成绩、分数趋势和某次考试的逐题对错。

本契约只读取已经持久化的事实。题目练习、订正和每日任务不展示逐题用时；模拟卷仅展示整卷总用时。没有数据时必须返回空分页，不得返回 Mock、估算时长或虚构分数。

本版不包含：历年真题整卷历史、资料阅读记录、学习时长统计、画像公式、学习记录删除、题目重新判分、模拟开考/答题/交卷、报告修订版本浏览。历年真题中的题目在本页与其他来源题目一样，按`questionId`归入题目历史。

## 2. 数据依据与聚合不变量

| 页面对象 | 主查询事实 | 聚合键 | 展示边界 |
|---|---|---|---|
| 每日任务 | `cm_learning_task`、`cm_task_item`、`cm_task_attempt`、`cm_learning_session(source_task_id)`、`cm_task_question`、作答表 | `goal_id + task_id` | 只返回完整完成的任务：两个必需任务项均存在完成事实，且唯一`daily_task`会话已结算完成；任务标题和题目均使用生成时冻结快照。 |
| 题目历史 | `cm_session_question`、`cm_question_attempt`、`cm_attempt_answer`、`cm_error_record`、订正表 | `goal_id + question_id` | 同题来自诊断、每日任务、知识点练习、模拟、订正或验证均归入一行。 |
| 模拟试卷 | `cm_learning_session`、`cm_collection_revision`、`cm_collection`、报告和作答表 | `goal_id + collection_id` | 逻辑试卷一行；若题集修订不同，在详情内分组，禁止跨修订比较分数。 |

所有聚合必须同时限制`user_id=当前登录用户`和`goal_id=选定目标`。同一道题或同一模拟卷在不同目标下是不同记录，绝不跨目标合并。

题目和任务详情必须从`cm_session_question.presentation_snapshot`、`grading_snapshot`、`knowledge_snapshot`或`cm_task_question`冻结快照读取；不得因题库当前版本、题目下架或题集改版改变历史题面、题型、难度、知识点或对错结果。

模拟卷总用时不是逐题用时之和。模拟正式开考时，服务端必须在同一事务内冻结`duration_seconds_snapshot`，并写入`deadline_time = started_time + duration_seconds_snapshot`。历史接口的字段口径固定为：`durationLimitSeconds`直接取`duration_seconds_snapshot`，用于展示正式限时；`durationSeconds`取`min(submitted_time, deadline_time) - started_time`，用于展示实际考试用时。因此自动交卷任务延迟或客户端收到结果较晚时，展示时长也不得超过正式截止时间。`deadline_time`、`duration_seconds_snapshot`和相关约束由`20260818_add-simulation-session-contract.sql`提供；部署模拟正式开考前，目标数据库必须已执行该迁移。没有开始、提交、截止或限时快照，或截止时间不等于开始时间加限时快照时，返回`durationSeconds=null`、`durationLimitSeconds=null`和`durationStatus='UNAVAILABLE'`，不得计算、补零或从当前试卷配置反推。

## 3. 公共约定

所有接口要求已登录学生账号，权限为`certmuse:student`与`certmuse:learning:history:query`的 AND。实施时必须通过新增迁移授予学生角色该隐藏权限；本契约不新增业务事实表。

- 身份、用户和目标范围只从服务端登录态及目标记录确定；客户端不得传`userId`。
- 雪花 ID 使用十进制字符串；时间为带时区 ISO-8601 字符串，业务时区固定`Asia/Shanghai`。
- 所有接口均为 GET，不使用`X-Request-Id`，不得写入学习事实、目标/会话状态、错题状态、评分或画像数据；访问日志与监控日志按平台通用规范处理。
- 真实 HTTP Status 必须等于`R.code`。401/403沿用认证兼容格式，`data=null`。
- `pageNum`默认1，范围1–10000；`pageSize`默认10，范围1–100。空字符串按未传处理。
- `score`、`maxScore`为十进制字符串，最多两位小数；`scoreRate`为0至1的 JSON number，最多八位小数。前端不得以浮点等值判断业务结果，应使用`attemptResult`、`reportStatus`和范围比较。

### 3.1 目标范围

三个列表接口及其详情接口均接受可选`goalId`。

- 传入时，必须是当前用户拥有的目标，不要求状态为`active`；暂停、已完成和已取消目标的历史可读。
- 未传时，服务端使用当前用户唯一`active`目标；没有进行中目标时返回422 `HISTORY_GOAL_REQUIRED`，前端先调用第4.1节获取可查看目标并让用户选择。
- 目标停止维护、考试批次结束待确认或目标暂停时，查询历史仍可用；这些状态只限制新的学习行为，不限制本契约。

### 3.2 统一枚举与结果口径

| 字段 | 枚举/规则 |
|---|---|
| `sessionSource` | `initial_diagnosis → INITIAL_DIAGNOSIS`；`daily_task`、`task_test → DAILY_TASK`；`self_practice → SELF_PRACTICE`；`simulation → SIMULATION`；`correction → CORRECTION`；`independent_verification → INDEPENDENT_VERIFICATION`；`simulation_verification → SIMULATION_VERIFICATION`。其他合法或未来类型暂返回`OTHER`，新增`self_diagnosis`时必须先冻结映射。 |
| `attemptResult` | 仅对“有效提交”计算：`CORRECT`为已评分且`scoreRate=1`；`INCORRECT`为已评分且`scoreRate<1`；`SKIPPED`为`is_skipped=true`；`PENDING_SCORING`为已提交但答案仍待评分。有效提交指`attempt.status IN ('submitted','graded')`、`submitted_time`非空且答案`grading_status!='invalid'`。 |
| `correctionStatus` | 按以下顺序聚合：① 任一关联知识点存在`unresolved`或`correcting`错误事实，返回`PENDING_CORRECTION`；② 否则存在成功`cm_correction_record`，返回`CORRECTED`，`pending_verification`或`resolved`不另增页面状态；③ 没有任何错误事实，返回`NONE`；④ 仍存在错误事实却不能匹配前三项，属于数据一致性错误，返回`HISTORY_READ_FAILED`，不得伪装成`NONE`。 |
| `reportStatus` | `AVAILABLE`、`PROCESSING`、`FAILED`、`UNAVAILABLE`。只有`AVAILABLE`才返回分数。 |

`SKIPPED`优先于分数判断；无效作答不计入正确题、错误题、分数趋势或错题统计。`PENDING_SCORING`不计入正确题或错误题，直到有效评分产生；`in_progress`草稿从所有历史列表和次数统计中排除。

## 4. 接口定义

### 4.1 查询可查看的学习目标

`GET /api/learning/history/goals`

返回当前用户全部至少拥有一条可展示记录的目标；当前进行中目标排在第一位，其余按`lastRecordAt DESC, goalId DESC`稳定排序。可展示记录指有效提交作答、完整完成的每日任务或已生成报告；仅生成任务但尚未形成上述记录的目标不返回。该接口仅用于历史范围选择，不返回画像、错题或题目内容。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "rows": [{
      "goalId": "1950000000000000001",
      "certificationName": "系统架构设计师",
      "syllabusVersionName": "2025年版",
      "targetExamDate": "2026-11-07",
      "status": "ACTIVE",
      "isCurrent": true,
      "lastRecordAt": "2026-08-19T09:30:00+08:00"
    }]
  }
}
```

`lastRecordAt`取以下非空时间的最大值：有效提交作答的`submitted_time`、完整完成每日任务会话的`settled_time`、报告的`generated_time`。没有可展示记录的目标不返回。`targetExamDate`可为`null`，例如预计批次。

### 4.2 查询每日任务历史

`GET /api/learning/history/tasks`

| 参数 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| `goalId` | string | 否 | 见第3.1节。 |
| `keyword` | string | 否 | 去首尾空格后1–100字符；匹配冻结任务标题或知识点名称。 |
| `completedFrom` / `completedTo` | date | 否 | `YYYY-MM-DD`，按`Asia/Shanghai`完成日期过滤；同时传入时起始不得晚于结束。 |
| `subjectId` | string | 否 | 十进制正整数。 |
| `knowledgePointId` | string | 否 | 十进制正整数。 |
| `pageNum` / `pageSize` | integer | 否 | 见第3节。 |

固定按`completedAt DESC, taskId DESC`排序。完整完成任务必须同时满足：该任务恰有`item_order=1`的知识学习项和`item_order=2`的知识点练习项；两个任务项各自至少存在一条`cm_task_attempt(attempt_no=1,status='completed')`事实；关联的唯一`daily_task`会话为`completed`且`settled_time`非空。`completedAt`固定取该会话的`settled_time`；未完成、会话已取消或无效、或完成会话缺少`settled_time`的任务均不进入列表，最后一种属于数据一致性错误。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "rows": [{
      "taskId": "1950000000000000101",
      "title": "架构风格专项学习",
      "knowledgePoint": {"id":"1950000000000000301","name":"架构风格"},
      "subject": {"id":"1950000000000000201","name":"系统架构设计"},
      "questionCount": 8,
      "correctCount": 6,
      "incorrectCount": 2,
      "skippedCount": 0,
      "completedAt": "2026-08-19T09:30:00+08:00"
    }],
    "total": 1
  }
}
```

### 4.3 查询每日任务历史详情

`GET /api/learning/history/tasks/{taskId}`

查询参数`goalId`可选，规则与第3.1节一致。路径参数`taskId`必须为十进制正整数。只允许读取当前用户、选定目标中的已完成任务；不存在、非本人、目标不匹配或尚未完成统一返回404 `HISTORY_TASK_NOT_FOUND`。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "taskId": "1950000000000000101",
    "title": "架构风格专项学习",
    "completedAt": "2026-08-19T09:30:00+08:00",
    "knowledgePoint": {"id":"1950000000000000301","name":"架构风格"},
    "summary": {"questionCount":8,"correctCount":6,"incorrectCount":2,"skippedCount":0},
    "questions": [{
      "questionId": "1950000000000000401",
      "questionOrder": 1,
      "stemPreview": "在需要将一系列独立数据处理步骤按顺序组合的场景中……",
      "questionType": "CHOICE",
      "difficulty": "MEDIUM",
      "knowledgePoints": [{"id":"1950000000000000301","name":"架构风格"}],
      "attemptResult": "CORRECT",
      "score": "1",
      "maxScore": "1",
      "scoreRate": 1,
      "currentCorrectionStatus": "NONE"
    }]
  }
}
```

`questions`按冻结题序升序，题干只返回摘要，不返回正确答案、解析或AI评分内部信息。当前每日任务只允许同步判分的选择题，因此完整完成的每日任务不得出现`PENDING_SCORING`，且必须满足`questionCount = correctCount + incorrectCount + skippedCount`。题目待评分、统计不守恒或完整任务没有作答事实均属于数据一致性错误，接口返回500 `HISTORY_READ_FAILED`，不得静默补“错误”。

### 4.4 查询题目历史

`GET /api/learning/history/questions`

| 参数 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| `goalId` | string | 否 | 见第3.1节。 |
| `keyword` | string | 否 | 去首尾空格后1–100字符；匹配最近有效冻结题干摘要。 |
| `questionType` | enum | 否 | `CHOICE`、`CASE`、`ESSAY`。 |
| `difficulty` | enum | 否 | `EASY`、`MEDIUM`、`HARD`。 |
| `knowledgePointId` | string | 否 | 十进制正整数；匹配任一冻结知识点。 |
| `correctionStatus` | enum | 否 | `NONE`、`PENDING_CORRECTION`、`CORRECTED`。 |
| `lastAnsweredFrom` / `lastAnsweredTo` | date | 否 | `YYYY-MM-DD`，按`Asia/Shanghai`最后有效作答日期过滤。 |
| `pageNum` / `pageSize` | integer | 否 | 见第3节。 |

固定按`lastAnsweredAt DESC, questionId DESC`分页。列表以`questionId`聚合，`attemptCount`统计当前目标内全部有效提交；`lastAttempt`取最新有效提交。题型、难度、题干摘要和知识点取`lastAttempt`对应快照，因此旧版本题目不会改写历史，题目修订后也不会把主列表的最新属性错误地回填到旧作答。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "rows": [{
      "questionId": "1950000000000000401",
      "stemPreview": "在需要将一系列独立数据处理步骤按顺序组合的场景中……",
      "questionType": "CHOICE",
      "difficulty": "MEDIUM",
      "knowledgePoints": [{"id":"1950000000000000301","name":"架构风格"}],
      "attemptCount": 4,
      "lastAnsweredAt": "2026-08-19T09:30:00+08:00",
      "lastAttempt": {"sessionSource":"DAILY_TASK","attemptResult":"CORRECT","scoreRate":1},
      "correctionStatus": "PENDING_CORRECTION"
    }],
    "total": 1
  }
}
```

### 4.5 查询题目历史详情

`GET /api/learning/history/questions/{questionId}`

查询参数`goalId`可选，规则与第3.1节一致。只返回选定目标中至少有一条有效提交的题目；否则返回404 `HISTORY_QUESTION_NOT_FOUND`。详情按`answeredAt DESC, attemptId DESC`排列，使用每次作答自己的冻结快照；不以最新题库内容覆盖历史。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "questionId": "1950000000000000401",
    "stemPreview": "在需要将一系列独立数据处理步骤按顺序组合的场景中……",
    "attemptCount": 4,
    "history": [{
      "attemptId": "1950000000000000501",
      "sessionId": "1950000000000000601",
      "sessionSource": "DAILY_TASK",
      "answeredAt": "2026-08-19T09:30:00+08:00",
      "stemPreview": "在需要将一系列独立数据处理步骤按顺序组合的场景中……",
      "questionType": "CHOICE",
      "difficulty": "MEDIUM",
      "knowledgePoints": [{"id":"1950000000000000301","name":"架构风格"}],
      "attemptResult": "CORRECT",
      "answerSummary": "选择 A",
      "score": "1",
      "maxScore": "1",
      "scoreRate": 1,
      "skipped": false
    }],
    "correction": {
      "status": "PENDING_CORRECTION",
      "wrongCount": 1,
      "skipCount": 0,
      "events": [{
        "occurredAt": "2026-08-18T09:12:00+08:00",
        "eventType": "WRONG_ANSWER",
        "sessionSource": "SELF_PRACTICE",
        "statusAfter": "PENDING_CORRECTION"
      }]
    }
  }
}
```

顶层`stemPreview`取最新有效作答的冻结题干摘要，仅用于页面标题或摘要；不得读取当前题库，也不得假设冻结题面存在独立`title`字段。

`answerSummary`是面向历史列表的通用答案摘要：单选题按冻结选项标签生成，例如“选择 A”；多选题按冻结选项顺序生成，例如“选择 A、C”；案例和论文题仅返回“已提交答案”或“答案已不再保留，评分结果仍有效”，不得假设存在选项标签，也不返回原始主观题答案。

`correction.events`按时间倒序，由错误事实和成功订正事实组成；它不是错误记录的完整状态审计。`eventType`完整枚举为`WRONG_ANSWER`、`SKIPPED`、`CORRECTED`、`REOPENED`。其中`REOPENED`不是数据库状态值：仅当同题已存在较早的成功订正事实、之后又出现新的错误事实时，由服务端按事实时间顺序派生。接口不得声称数据库保存了每一次状态迁移或返回不存在的历史状态原因。

### 4.6 查询模拟试卷历史

`GET /api/learning/history/simulations`

| 参数 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| `goalId` | string | 否 | 见第3.1节。 |
| `keyword` | string | 否 | 去首尾空格后1–100字符；匹配逻辑模拟卷名称。 |
| `subjectId` | string | 否 | 十进制正整数。 |
| `completedFrom` / `completedTo` | date | 否 | `YYYY-MM-DD`，按最后一次完成日期过滤。 |
| `minScoreRate` / `maxScoreRate` | decimal | 否 | 0–1，最多两位小数；同时传入时最小值不得大于最大值；只匹配最后一次完成考试的报告，且该报告必须为`AVAILABLE`。 |
| `pageNum` / `pageSize` | integer | 否 | 见第3节。 |

固定按`lastCompletedAt DESC, collectionId DESC`分页。只返回至少有一份`session_type='simulation'`且`status='completed'`会话的逻辑模拟卷。列表的“最后成绩”取最后完成会话的`cm_assessment_report(report_type='simulation')`；报告未可用时该卷仍返回，但`latestResult.score/maxScore/scoreRate=null`并携带实际`reportStatus`。传入`minScoreRate`或`maxScoreRate`时，只使用最后完成会话的报告：该报告非`AVAILABLE`则此试卷不匹配任何分数范围，不得以更早成绩替代。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "rows": [{
      "collectionId": "1950000000000000701",
      "collectionName": "系统架构设计师模拟卷（一）",
      "subject": {"id":"1950000000000000201","name":"系统架构设计"},
      "attemptCount": 3,
      "lastCompletedAt": "2026-08-19T10:30:00+08:00",
      "latestResult": {"reportStatus":"AVAILABLE","score":"25","maxScore":"50","scoreRate":0.5},
      "durationSeconds": 6420,
      "durationLimitSeconds": 7200,
      "durationStatus": "AVAILABLE"
    }],
    "total": 1
  }
}
```

### 4.7 查询模拟试卷历史详情

`GET /api/learning/history/simulations/{collectionId}`

可选查询参数`goalId`规则与第3.1节一致。可选查询参数`sessionId`为十进制正整数，必须属于当前用户、选定目标、该逻辑试卷且状态为`completed`。未传时使用最近完成的一次；不存在完成记录、越权或不属于该卷统一返回404 `HISTORY_SIMULATION_NOT_FOUND`。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "collectionId": "1950000000000000701",
    "collectionName": "系统架构设计师模拟卷（一）",
    "revisionGroups": [{
      "revisionId": "1950000000000000711",
      "revisionNo": 1,
      "attempts": [{
```

## 5. 失败响应

除401/403外，预期失败使用以下统一结构：

```json
{
  "code": 422,
  "msg": "请选择可查看的学习目标",
  "data": {
    "errorCode": "HISTORY_GOAL_REQUIRED",
    "retryable": false,
    "traceId": null,
    "fieldErrors": [],
    "details": null
  }
}
```

| HTTP / `R.code` | `errorCode` | 条件 | 前端行为 |
|---:|---|---|---|
| 400 | `HISTORY_REQUEST_INVALID` | 查询参数、日期范围、分数范围、分页或路径 ID 不合法 | 展示字段错误，不重试。 |
| 403 | `HISTORY_FORBIDDEN` | 不是学生或缺少查询权限 | 停止查询，显示无权限。 |
| 404 | `HISTORY_GOAL_NOT_FOUND` | `goalId`非本人所有或不存在 | 刷新目标列表。 |
| 404 | `HISTORY_TASK_NOT_FOUND` | 任务不存在、不属于范围或尚未完成 | 返回任务历史列表并刷新。 |
| 404 | `HISTORY_QUESTION_NOT_FOUND` | 题目不存在、不属于范围或没有有效作答 | 返回题目历史列表并刷新。 |
| 404 | `HISTORY_SIMULATION_NOT_FOUND` | 模拟卷/考试记录不存在或不属于范围 | 返回模拟历史列表并刷新。 |
| 422 | `HISTORY_GOAL_REQUIRED` | 未传`goalId`且用户没有进行中目标 | 读取目标范围后让用户选择。 |
| 500 | `HISTORY_READ_FAILED` | 未预期查询、快照解析或数据一致性故障 | 显示安全失败提示与`traceId`。 |

400字段错误仅使用`REQUIRED`、`INVALID_FORMAT`、`OUT_OF_RANGE`；字段路径使用请求参数 camelCase 名称。5xx必须返回安全文案和非空`traceId`，不得泄露SQL、堆栈、其他用户数据或内部快照全文。

## 6. 行为、安全与可观测性

- 详情资源校验必须在查询条件中同时包含`user_id`、`goal_id`及对象 ID；不得先按对象 ID 查询后再在应用层判断所有权。
- 所有列表`total`均为聚合后的对象数，不是作答、错误记录或报告行数；分页必须在聚合后执行。
- 题目历史只合并逻辑`question_id`相同的作答；不同题目即使题干相同也不得合并。模拟历史只合并逻辑`collection_id`相同的会话；不同模拟卷即使名称相同也不得合并。
- 题目订正状态仅作为历史展示，不能通过本接口关闭错误记录、更新画像或触发验证；详情中的`CORRECTED`不等于掌握。
- 模拟列表和详情只读取已完成考试。当前模拟开考仍关闭时，列表应自然为空，不能用已发布但未开考的模拟卷替代历史记录。
- 审计日志只记录用户 ID、目标 ID、接口名、对象数量、分页、结果码和`traceId`；不得记录题干全文、选项、答案、解析、评分快照、画像数据或完整响应体。

## 7. 验收用例

1. 同一任务的学习项和练习项均完成后，任务历史只显示一行，完成时间与任务会话结算时间一致；详情题序、题干快照和对错与当时作答一致。
2. 一个任务未完成、已取消或无效时，不出现在默认每日任务历史中，且不能通过详情接口伪造已完成记录。
3. 同一题分别在知识点练习、每日任务和模拟中作答三次，题目历史只显示一行，`attemptCount=3`；详情按真实时间列出三次来源和结果。
4. 同题修订后，旧作答仍显示旧快照；主列表的题型、难度和题干摘要使用最近一次有效作答快照，不读取当前题库覆盖历史。
5. 同题答错、订正答对、后续再次答错后，详情显示错误事实和成功订正事实；后一条错误事实仅在存在较早成功订正时标记为`REOPENED`，主列表状态为`PENDING_CORRECTION`。接口不得虚构完整错误状态迁移历史。
6. 两个不同目标下作答同一道题，切换目标后各自只显示一条本目标记录，次数、最后日期和订正状态不互相影响。
7. 同一逻辑模拟卷同一修订完成三次，模拟列表只显示一行、`attemptCount=3`；详情按`completedAt ASC, sessionId ASC`动态展示第1至第3次的可比较分数。
8. 同一模拟卷有两个修订时详情分为两个`revisionGroups`，每组考试次数从1开始；不跨修订生成折线比较结论，已下架修订的历史仍可读。
9. 模拟报告处理中时历史行存在但最新分数为空，前端显示“结果处理中”，不显示0分；携带分数范围时该行不匹配。缺失开始、提交、截止或限时快照，或截止时间与限时快照不一致时，显示“用时不可用”。
10. 题目订正事件只返回`WRONG_ANSWER`、`SKIPPED`、`CORRECTED`、`REOPENED`；`REOPENED`仅由“先成功订正、后新错误”的事实顺序派生，不作为数据库状态持久化。
11. 完整每日任务的题目统计满足`questionCount = correctCount + incorrectCount + skippedCount`；若存在待评分题、统计不守恒或缺少作答事实，返回`HISTORY_READ_FAILED`。
12. 非本人`goalId`、题目、任务、模拟卷或`sessionId`均返回统一404，不泄露其名称、分数、是否存在或题目内容。
13. 各列表按聚合对象分页，`total`不因一道题多次作答、一个任务多题或一份试卷多次考试而膨胀。
