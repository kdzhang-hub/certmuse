## 1. 文档边界

本文档统一保存知识点练习设置页（U08）和答题页（U09）的现行后端接口契约。U08 负责返回可练知识树、创建会话和冻结题单；U09 只读取 U08 冻结的会话快照，负责进入会话、读取题目、提交答案和结束练习。两个子契约的版本独立演进，但 Git 中只维护本文件，不再以文件名版本号创建副本。

## 2. U08 知识点练习设置页后端接口契约（V1.7）


### 1. 目标与边界

本契约仅服务学生端 `/learning/question-bank/knowledge-practice` 知识点练习设置页。页面固定两栏：左侧为当前学习目标考纲的可见知识点树；右侧为当前点击节点的详情。

左栏 UI 仅展示层级和知识点名称，不展示题量、已练题数、掌握度或重要度。右侧展示当前节点的掌握度、重要度和题量；父节点还展示下一层可见知识点的编号、名称和题量。

设置页按当前目标考纲全部启用未删除节点的**统一聚合层**裁剪树。设该考纲全部科目中最大的 `treeDepth` 为 `M`；第 `M - 2` 层是统一聚合层（即倒数第三层）。第 `M - 1`、`M` 两个最底层节点均不返回给前端，其题目供给归入最近的第 `M - 2` 层可见祖先。较浅分支已经结束的节点仍须返回和展示，不能因其本身是叶子而隐藏。

例如原始树最大深度为 5：第 3 层的 `知识点 A` 已结束；第 3 层的 `子章节 B` 下有第 4 层 `知识点 B.1`，其下有第 5 层 `知识点 B.1.a`。接口只返回至第 3 层，`A` 与 `B` 都是可练习节点；`A` 仅聚合自身范围，`B` 聚合自身、`B.1` 与 `B.1.a` 的范围。前端不得补取、展示或还原两个隐藏层的节点。用户不能多选节点、不能选题量，也不显示任何“已练/总题数”统计。

只有没有可见子节点的节点可以开始练习。点击“去练习”时，服务端冻结该节点范围内的全部可练题并返回答题页地址。存在可见子节点的父节点只供浏览，不可开始练习。

本契约不定义题单读取、逐题作答、退出、评分、报告、错题或画像结算；这些属于后续答题页接口契约。设置页不查询或返回用户历史作答，因此答题页也不得据此展示“此题已做过”。

本契约冻结接口行为和开发前置条件，不实施数据库迁移或目录治理。后端交付必须同时执行第 2.4 节列出的迁移和数据治理要求。

### 2. 共同约定

#### 2.1 响应、身份与权限

全部响应使用 `R<T>` 包装，真实 HTTP Status 必须等于 `R.code`。前端只根据 `data.errorCode` 处理业务失败，`msg` 仅作脱敏展示兜底。

```ts
interface KnowledgePracticeErrorVo {
  errorCode: string;
  retryable: boolean;
  traceId: string | null;
  fieldErrors: Array<{
    field: string;
    code: 'REQUIRED' | 'INVALID_FORMAT' | 'OUT_OF_RANGE';
    message: string;
  }>;
  details: null | {
    answerPath: string;
  };
}
```

- `GET /setup` 必须同时具备 Sa-Token 权限标识 `certmuse:student` 和 `certmuse:assessment:knowledge-practice:query`。
- `POST /api/assessment/knowledge-practices` 必须同时具备 Sa-Token 权限标识 `certmuse:student` 和 `certmuse:assessment:knowledge-practice:start`。`certmuse:student` 是权限标识，不以角色名称替代；两项校验为 AND 关系。
- 用户、学习目标、资格、考纲和科目均由当前会话及当前学习目标确定；请求不得传递 `userId`、`goalId`、`certificationId` 或 `syllabusVersionId`。
- 401/403 沿用认证授权兼容格式，只承诺 `code`、`msg` 和空 `data`。4xx 不返回 `traceId`；5xx 返回安全文案、非空 `traceId`、空 `fieldErrors` 和 `details:null`。

#### 2.2 节点读模型

```ts
interface KnowledgePracticeMasteryVo {
  currentDirectAbility: number | null;
  profileStatus:
    | 'unassessed'
    | 'provisional'
    | 'urgent'
    | 'weak'
    | 'learning'
    | 'proficient'
    | 'mastery_candidate'
    | 'mastered'
    | 'needs_retest'
    | 'pending_verification'
    | 'needs_review'
    | 'expired';
  confidenceLevel: 'unassessed' | 'low' | 'medium' | 'high' | 'expired';
}

interface KnowledgePracticeNodeVo {
  id: string;
  parentId: string | null;
  examSubjectId: string;
  syllabusNumber: string;
  syllabusTitle: string;
  treeDepth: number;
  sortOrder: number;
  importance: 1 | 2 | 3;
  questionCount: number;
  mastery: KnowledgePracticeMasteryVo;
  children: KnowledgePracticeNodeVo[];
}
```

除 `questionCount` 和 `children` 外，节点字段直接来自现有 `cm_knowledge_point`；不新增数据库字段。`children` 仅包含本接口可见的直接子节点，前端以 `children.length > 0` 判断是否显示展开操作，不使用 `hasChildren` 字段。

`importance` 直接读取节点自身重要度。前端固定将 `1`、`2`、`3` 映射为“补充”“常规”“核心”，不得要求后端新增中文展示字段或对空值使用默认值。

`mastery` 直接读取该节点自身的 `cm_knowledge_profile.current_direct_ability`、`profile_status` 和 `confidence_level`；父节点不从子节点聚合，前端也不得计算。无画像记录时必须返回固定对象：`currentDirectAbility:null`、`profileStatus:'unassessed'`、`confidenceLevel:'unassessed'`。前端仅将固定状态枚举映射为中文文案；数值范围由现有数据库约束确定为 0–100。

`questionCount` 是查询聚合结果，不是数据库新字段。它表示该节点自身及其原始后代范围内、符合第 2.3 节资格的去重题目数；对可练习节点，范围包含其下方两个统一隐藏层的节点。不表示用户已练题数、覆盖率或任何历史统计。

所有 ID 为十进制正整数字符串；时间如后续接口需要返回，使用 ISO-8601 UTC 字符串，前端按 `Asia/Shanghai` 展示。

#### 2.3 目录裁剪、题目资格和容量

1. **统一聚合层**按当前学习目标固定考纲中，`del_flag='0'`、`status='0'` 节点的最大 `treeDepth` `M` 计算；停用或已删除节点不参与计算。`M - 2` 是倒数第三层的聚合层，`M - 1` 与 `M` 是统一隐藏的最底两层。该计算在全部科目之间统一进行，不按分支或科目分别计算；`M` 必须不小于 3。
2. 可见树返回所有 `treeDepth <= M - 2` 的启用未删除节点，不重写其 ID、`parentId`、`treeDepth` 或排序字段。所有 `treeDepth >= M - 1` 的节点均隐藏；其题目供给归入最近的可见祖先（必为第 `M - 2` 层节点），不得按分支重新计算聚合层。
3. 节点可以在第 `M - 2` 层之前结束。同一父节点的子节点允许同时存在“已在可见树结束的节点”和“仍有下一层可见子节点的分支”；这不是目录错误。当前目标范围内任一可见节点的 `importance` 必须为 `1`、`2` 或 `3`。`M < 3` 或违反重要度约束时，GET 和 POST 返回 `PRACTICE_DIRECTORY_INVALID`，不返回局部树，并记录目录告警。
4. 一个可见节点的原始范围为它自身及所有原始后代。没有可见子节点的节点可以开始练习；其题单包含直接关联到该节点的题目，以及关联到其全部隐藏后代（最多为两个最底层）的题目。存在可见子节点的父节点只供浏览，不创建练习。
5. 每个 `question_id` 至多进入一次。可练题必须同时满足：
   - `cm_question.del_flag='0'`；
   - 在该题全部 `published` 修订中，选取 `revision_no` 最大的一条 `cm_question_revision`；
   - 所选修订题型严格为 `CHOICE`；`CASE`、`ESSAY` 及其他题型一律不计入题量或题单。`knowledge_mapping_status` 不作为知识点练习题目资格条件；
   - 存在该修订对应的 `cm_question_knowledge`，其 `exam_subject_id` 与关联知识点的 `exam_subject_id` 均等于当前节点科目；关联知识点位于当前节点原始范围、当前目标考纲且启用未删除。`cm_question.exam_subject_id` 不作为本接口的题目资格条件；
   - 满足第 2.5 节的快照源数据完整性条件。
6. `GET /setup` 的 `questionCount` 与 POST 冻结题单必须使用同一资格规则。题库在页面加载后变化时，POST 以创建时的实时资格结果为准，不读取历史作答，也不截断题单。
7. 题单按 `cm_question.id` 升序冻结。实时合格题数必须介于 `1` 与 `150`（含）之间；`151` 题及以上返回 `PRACTICE_QUESTION_LIMIT_EXCEEDED`，不得创建部分题单或会话。

#### 2.4 开发前置：数据库并发约束与重要度治理

后端实现前必须新增有序 PostgreSQL 迁移，且不修改既有已部署迁移。迁移至少包含：

```sql
CREATE UNIQUE INDEX uk_cm_learning_session_active_self_practice
    ON cm_learning_session(user_id, goal_id)
    WHERE session_type = 'self_practice'
      AND status IN ('created', 'in_progress');
```

`cm_knowledge_point.importance` 的历史空值必须由目录治理明确补齐为 `1`、`2` 或 `3`；完成空值审计后，迁移将该字段改为 `NOT NULL`。U08 不把 `NULL` 映射为“常规”或任何其他值。

#### 2.5 会话题目快照最小规范

POST 仅选择存在唯一 `status='published'` 的 `cm_profile_rule_version` 作为 `cm_learning_session.rule_version_id`。找不到该版本时返回 `PRACTICE_RULE_VERSION_UNAVAILABLE`；不得选取 draft、retired 或临时规则。

每个进入题单的题目都必须在同一事务中写入 `cm_session_question`，并冻结下列事实。快照不得在后续答题时反查当前题目、当前知识点或当前规则替代。

| 目标字段 | 冻结规则 |
| --- | --- |
| `exam_subject_id` | 当前可见节点所属科目。 |
| `evidence_group_key` | 取 `coalesce(nullif(btrim(cm_question.evidence_group_key), ''), 'Q:' || question_id)`；为空时以题目 ID 生成稳定键，用于画像去重。 |
| `difficulty_snapshot` | 取最新已发布修订的 `difficulty`；为空时冻结为 `medium`，不作为题目资格条件。 |
| `estimated_seconds_snapshot` | 直接取修订的正整数 `estimated_seconds`；允许为 `null`。 |
| `presentation_snapshot` | `knowledge_practice_presentation/1.0`：固定含 `schema_version`、`questionType:'CHOICE'`、`stem`、`difficulty`、`estimatedSeconds`、按 `sort_order` 排序的完整 `options` 与 `images`。每张图片冻结题目修订既有的对象标识（或存储路径）、替代文字和排序事实，绝不冻结临时签名 URL 或 Controller 拼接的存储服务 URL。不得包含答案、解析或评分点。 |
| `grading_snapshot` | `knowledge_practice_grading/1.0`：固定含 `schema_version`、`questionType:'CHOICE'`、修订 `answer`、`analysis`、`maxScore:1.00` 与评分规则；冻结 `answer` 的 `schema_version`、`answer_type`、`selection_mode`（如存在）及 `value`。`analysis` 可为 `null`，答题页只展示本快照中的解析，不回查当前题目修订。 |
| `knowledge_snapshot` | `knowledge_practice_knowledge/1.0`：固定含 `schema_version` 和该修订全部合格映射项，项内含知识点 ID、科目 ID、关系角色与排序。 |
| `scoring_point_snapshot` | `knowledge_practice_scoring_points/1.0`：固定为空 `items`；U08 不创建主观题评分点快照。 |

CHOICE 缺少可解析答案、选项或任一其他必填快照源时，该题不符合第 2.3 节资格，不进入 GET 计数或 POST 题单；记录题库数据告警。证据组和难度分别按本表兜底规则冻结。若筛选后无题，按 `PRACTICE_NODE_UNAVAILABLE` 处理。

### 4. 从当前节点开始练习

```http
POST /api/assessment/knowledge-practices
Content-Type: application/json
X-Request-Id: 0f7cd9a8-4b29-4ba5-b202-b7fb5aac85dd
```

`X-Request-Id` 必填。服务端以 `UUID.fromString` 解析，解析成功后以其小写标准 36 字符串作为查询、哈希和落库值；空白、不可解析或超过 100 字符均为 `PRACTICE_REQUEST_INVALID`。客户端不得复用已使用的请求号。

```ts
interface StartKnowledgePracticeRequest {
  knowledgePointId: string;
  expectedGoalVersion: number;
}

interface StartKnowledgePracticeVo {
  sessionId: string;
  totalCount: number;
  answerPath: string;
}
```

| 请求字段 | 必填 | 规则 |
| --- | ---: | --- |
| `knowledgePointId` | 是 | 十进制正整数；必须是 `GET /setup` 返回的当前可见节点，`children` 为空且创建时实时 `questionCount>0`。 |
| `expectedGoalVersion` | 是 | `setup.goal.version` 原样返回的非负整数。 |

#### 4.1 幂等、并发和事务顺序

本操作的 `action_code` 固定为 `START_KNOWLEDGE_PRACTICE`。规范化载荷为服务端构造的 `knowledge_practice_start/1.0` JSON，其字段为 `userId`、`knowledgePointId`、`expectedGoalVersion`；`userId` 不是客户端请求字段。对其规范 JSON 计算 SHA-256 作为 `payload_hash`。

`cm_idempotency_record` 的 `expires_time` 为创建时起 24 小时，成功响应使用既有资源和响应回放字段持久化。保留期结束不授权客户端复用请求号；因 `cm_learning_session.request_id` 唯一键发生的复用冲突仍返回 `PRACTICE_IDEMPOTENCY_CONFLICT`，不得创建第二个会话。

同一数据库事务按以下顺序执行：

1. 查询相同 `action_code + request_id` 的幂等记录；相同哈希且 `succeeded` 时直接回放首次成功响应，哈希不同（含不同用户）返回 `PRACTICE_IDEMPOTENCY_CONFLICT`。首次写入该唯一键的事务尚未结束时，竞争请求必须等待其提交或回滚：提交后重新读取并回放成功响应；回滚后本请求继续执行完整校验和创建流程。不得对外返回 `PRACTICE_REQUEST_IN_PROGRESS`。
2. 依次校验当前有效目标及资格门禁、`expectedGoalVersion`、目录有效性和目标节点、实时题目资格与 150 题上限、唯一已发布规则版本。首次诊断状态不参与创建门禁。
3. 在本事务中创建幂等记录、`cm_learning_session.session_type='self_practice'` 且 `status='created'` 的会话，并按题目 ID 升序写入完整 `cm_session_question` 快照；再将幂等记录更新为 `succeeded` 和成功响应。幂等记录插入发生唯一冲突时，等待冲突事务结束后重新读取记录并按第 1 步处理；活动会话部分唯一索引发生冲突时，按本节的原会话规则处理。
4. 任一步骤失败均回滚事务，不得遗留成功会话、半份题单或可回放的成功结果。

同一 `user_id + goal_id` 已有 `self_practice` 会话状态为 `created` 或 `in_progress` 时，不得新建第二份会话；部分唯一索引冲突后查询该用户、该目标的原会话，返回 `PRACTICE_SESSION_IN_PROGRESS`，并仅在 `data.details.answerPath` 返回原会话答题路径。不同目标的活动自练不互相阻塞。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "sessionId": "900000000000000801",
    "totalCount": 18,
    "answerPath": "/learning/session/practice?sessionId=900000000000000801"
  }
}
```

`answerPath` 使用现有学生端答题壳 `/learning/session/practice`，真实会话 ID 经查询参数 `sessionId` 传递；`:kind` 固定为 `practice`，不是会话 ID。

```json
}
```

### 6. 安全与可观测性

- 不返回题面、答案、解析、评分点、统一隐藏的最底两层节点、画像公式、历史作答、其他用户数据或内部快照。
- `PRACTICE_SESSION_IN_PROGRESS` 的 `answerPath` 仅可指向当前用户、当前目标下的会话；不得返回会话 ID 之外的题单内容。
- 访问日志仅记录接口、用户、目标范围校验结果、节点 ID、实时题量、会话 ID、结果码、规范化请求号和 `traceId`；不记录题面、答案、完整快照或令牌。
- 对目录不合规和被排除的快照源数据记录告警标识及资源 ID，不记录题面、答案或完整快照。
- 设置页读模型可按用户、目标和目标版本短期缓存；目录、画像、题目供给或目标变化后必须失效。创建接口不得用缓存替代实时范围校验。

### 7. 验收用例

1. GET 返回两栏所需可见树；全考纲统一最底两层节点不出现，倒数第三层聚合其全部题目；较浅分支的末层节点保留。左栏 UI 不展示题量、掌握度、重要度或已练统计。
2. 右侧仅展示当前节点画像与重要度；父节点显示下属总题量和下一层名称/题量，最低可见节点显示本节点题量及“去练习”。
3. 每个节点直接返回自身重要度和画像；无画像记录时固定返回未评估对象，前端不计算父节点值。
4. `children` 是唯一展开依据；不存在 `hasChildren`、`practicedQuestionCount`、覆盖率或历史作答字段。
5. 题目资格覆盖最新已发布 CHOICE 修订、已确认有效映射、直接节点关联题、最底两层隐藏后代聚合题、映射科目一致性、快照源完整性及 `question_id` 去重；CASE、ESSAY 及其他题型均不得计数或冻结；题序为题目 ID 升序。
6. 存在可见子节点的父节点、两个隐藏层节点、跨考纲、映射科目不一致、已停用、无题节点均不能创建练习；没有可见子节点的较浅末层节点和倒数第三层聚合节点均可创建练习。POST 与 GET 使用同源资格规则，POST 以实时题库结果为准。
7. 无有效目标/目标资格门禁优先于 POST 目标版本、节点及题目资格；首次诊断未完成不阻断设置页或创建练习，业务门禁不泄露目录、题量或画像。
8. 同一用户相同规范化 UUID 和载荷只创建一个会话并回放首次响应；UUID 大小写视为同一请求；空白或不可解析 UUID 返回 400。不同用户或不同载荷使用相同请求号返回 `PRACTICE_IDEMPOTENCY_CONFLICT`。同一请求号的并发调用等待首事务结束：首事务成功即回放，首事务回滚则继续执行，绝不对外暴露处理中状态。
9. 同一用户、同一目标的并发启动最多创建一个活动自练；不同目标不互相阻塞。已有进行中会话时仅返回自己的 `details.answerPath`，不得自动结束原会话。
10. 150 道实时合格题可成功冻结全量题单；151 道返回 `PRACTICE_QUESTION_LIMIT_EXCEEDED`，不得截断或创建部分会话。
11. 混合层级允许存在；仅 `importance=null` 或非枚举值返回 `PRACTICE_DIRECTORY_INVALID`。无已发布规则版本返回 `PRACTICE_RULE_VERSION_UNAVAILABLE`。
12. 仅 CHOICE 生成第 2.5 节规定的有效快照；CASE、ESSAY 和其他题型，以及缺失可解析答案或选项的 CHOICE，均不计入题单；缺失难度或证据组时按第 2.5 节兜底规则冻结。
13. 401/403、字段错误、版本冲突、业务门禁和 500 均符合 `R<T>`、真实 HTTP 状态、稳定错误码和安全响应规范。

## 3. U09 知识点练习答题页后端接口契约（V1.2）

```yaml
contract_id: learner-knowledge-practice-answering-u09
contract_version: 1.1
module: U09
routes:
  - /api/assessment/knowledge-practices/{sessionId}
  - /api/assessment/knowledge-practices/{sessionId}/items/{questionOrder}
  - /api/assessment/knowledge-practices/{sessionId}/items/{questionOrder}/submit
  - /api/assessment/knowledge-practices/{sessionId}/complete
scope: learner-knowledge-practice-answering
status: handoff_ready
updated_at: 2026-08-17
```

### 1. 目标与边界

本契约服务学生端 `/learning/session/practice?sessionId=...` 知识点练习答题页。它复用既有答题骨架的题目区、答题卡、上一题/下一题、逐题提交、已提交题回看、“退出练习”和“结束练习”入口。

本期只支持 U08 V1.5 已冻结的 `CHOICE` 题目。页面按需读取当前题，不一次返回完整题单；用户可以任意跳题。选择但未提交的答案仅在当前浏览器页面内暂存，刷新、退出或结束时直接丢弃。

点击“提交本题”后，答案立即持久化、同步判分并锁定。页面即时展示对错、正确答案和冻结解析。错误题创建错题记录；所有已提交题按冻结映射写入画像。未提交题绝不创建作答、错题或画像证据。

“退出练习”和“结束练习”均结束本次会话并回到知识点练习设置页；没有暂停、恢复、草稿、计时、提示、结果页、CASE、ESSAY、AI 评分，亦不显示任何历史“此题已做过”标记。

### 2. 共同约定

#### 2.1 响应、身份与可见性

全部响应使用 `R<T>` 包装，真实 HTTP Status 必须等于 `R.code`。前端只根据 `data.errorCode` 分支，`msg` 仅作安全展示兜底。

```ts
interface KnowledgePracticeAnswerErrorVo {
  errorCode: string;
  retryable: boolean;
  traceId: string | null;
  fieldErrors: Array<{
    field: string;
    code: 'REQUIRED' | 'INVALID_FORMAT' | 'OUT_OF_RANGE';
    message: string;
  }>;
  details: null;
}
```

- 四个接口均要求 Sa-Token 权限 `certmuse:student` 和 `certmuse:assessment:knowledge-practice:answer`，两者为 AND 关系。后端交付前必须新增有序 PostgreSQL 权限迁移，并向学生角色授予后者；本契约不执行该迁移。
- `sessionId`、`questionOrder` 为十进制正整数路径参数；`sessionId` 适用于全部接口，`questionOrder` 仅适用于单题读取和提交。不可解析的非十进制值为 `INVALID_FORMAT`，零、负数或数值溢出为 `OUT_OF_RANGE`，均返回 400 `PRACTICE_REQUEST_INVALID`。会话不存在、不是当前用户所有，或不是 `session_type='self_practice'` 时，统一返回 404 `PRACTICE_SESSION_NOT_FOUND`。
- 两个 POST 的 `X-Request-Id` 必填；服务端以 `UUID.fromString` 解析，解析成功后以小写标准 36 字符串查询、计算哈希和落库。缺失或空白为 `REQUIRED`、不可解析为 `INVALID_FORMAT`、超过 100 字符为 `OUT_OF_RANGE`，均返回 400 `PRACTICE_REQUEST_INVALID`；字段路径固定为 `X-Request-Id`。客户端不得复用已使用的请求号。
- 答题页只读取 `cm_session_question` 的冻结快照，绝不反查当前题目修订、当前知识点、当前解析或用户历史作答。会话快照中的图片仅保存既有对象标识或存储路径；响应 `images[].url` 必须通过既有 OSS 抽象生成，不得由 Controller 拼接存储服务 URL，也不得依赖冻结的临时签名 URL。
- 401/403 沿用认证授权兼容格式，只承诺 `code`、`msg` 和空 `data`。4xx 不返回 `traceId`；5xx 返回安全文案、非空 `traceId`、空 `fieldErrors` 和 `details:null`。

所有数组均使用稳定顺序：`navigation` 按 `questionOrder ASC`；`options`、`selectedOptionLabels` 和 `correctOptionLabels` 按冻结选项顺序；`images` 按 `sortOrder ASC` 再按其冻结稳定标识；`fieldErrors` 按字段路径升序。`images[].sortOrder` 与冻结快照相同。

#### 2.2 题目、答案与反馈读模型

```ts
type ChoiceSelectionMode = 'single' | 'multiple';

interface ChoiceOptionVo {
  label: string;
  content: string;
}

interface KnowledgePracticeNavigationItemVo {
  questionOrder: number;
  state: 'SUBMITTED_CORRECT' | 'SUBMITTED_INCORRECT' | 'UNANSWERED';
}

interface KnowledgePracticeSessionVo {
  sessionId: string;
  sessionStatus: 'IN_PROGRESS' | 'COMPLETED';
  totalCount: number;
  submittedCount: number;
  navigation: KnowledgePracticeNavigationItemVo[];
  nextAction: 'CONTINUE_PRACTICE' | 'RETURN_KNOWLEDGE_PRACTICE';
  returnPath: string | null;
}

interface KnowledgePracticeItemVo {
  sessionId: string;
  questionOrder: number;
  totalCount: number;
  question: {
    questionType: 'CHOICE';
    stem: string;
    selectionMode: ChoiceSelectionMode;
    options: ChoiceOptionVo[];
    images: Array<{ url: string; alt: string | null; sortOrder: number }>;
  };
  submission: null | {
    selectedOptionLabels: string[];
    correct: boolean;
    correctOptionLabels: string[];
    analysis: string | null;
  };
}
```

`question` 从 U08 冻结的 `presentation_snapshot` 和 `grading_snapshot` 投影而来。`selectionMode` 由冻结答案 schema 的 `selection_mode` 直接确定，`selectedOptionLabels` 始终为数组；不使用字符串、题目 ID 或前端推断的单选/多选规则。

`submission:null` 时不得返回学生答案、正确答案、对错或解析。`submission` 存在仅代表本会话当前题已提交，不代表用户历史上是否做过该原题。

#### 2.3 作答、判分与画像事实

1. U08 创建会话时只写入 `cm_learning_session` 和 `cm_session_question`；不为未答题预创建 `cm_question_attempt` 或 `cm_attempt_answer`。
2. 单题提交时，在同一事务内为该 `session_question` 创建唯一 `attempt_no=1` 的 `cm_question_attempt`，写入唯一 `cm_attempt_answer`，并将 attempt 从 `in_progress` 转为 `submitted`。本次 `X-Request-Id` 同时写入 `create_request_id` 与 `submit_request_id`。`answer_data` 使用服务端持久化 schema `knowledge_practice_choice_answer/1.0`，至少包含 `schema_version` 与选项数组 `value`；最终 `grading_status='graded'`。答对固定写入 `score=1.00`、`max_score=1.00`、`score_rate=1.00000000`，答错固定写入 `0.00`、`1.00`、`0.00000000`，且 `submitted_time` 非空。
3. 服务端仅使用冻结 `grading_snapshot` 同步判分。单选答案必须恰含一个有效选项；多选答案必须为非空、去重后的有效选项集合，且集合与冻结正确答案完全一致才算正确。选择题得分固定为 `1.00` 或 `0.00`。
4. 提交成功后，服务端按 `knowledge_snapshot` 中全部冻结有效的最小知识点映射，创建单题画像结算和证据。答对产生正向证据，答错产生负向证据；自主练习不使用计时或提示系数。
5. 答错时，对每个被结算的最小知识点创建唯一 `cm_error_record`。复用现有 `uk_cm_error_record_attempt_id_knowledge_point_id`、单题结算和当前有效证据唯一约束，保证重试和并发不会重复扣分、重复建错题或重复提高可信度。
6. 未提交题没有 attempt、answer、error record、profile settlement 或 learning evidence；它不是空白提交、跳过或错误作答。

#### 2.4 幂等与并发

提交操作的 `action_code` 为 `SUBMIT_KNOWLEDGE_PRACTICE_ITEM`，规范化载荷为服务端构造的 `knowledge_practice_submit/1.0` JSON，含 `userId`、`sessionId`、`questionOrder` 与规范化选项数组。结束操作的 `action_code` 为 `COMPLETE_KNOWLEDGE_PRACTICE`，规范化载荷为服务端构造的 `knowledge_practice_complete/1.0` JSON，含 `schemaVersion`、`userId`、`sessionId`。两者均对规范 JSON 计算 SHA-256 作为 `payload_hash`，并使用 `cm_idempotency_record` 既有的资源和成功响应回放字段；`expires_time` 为创建时起 24 小时。保留期结束不授权客户端复用请求号。

选项标签严格区分大小写，既不 trim 也不改写。结构和格式校验通过后，服务端按冻结选项顺序排序为规范化数组；多选 `["A", "B"]` 与 `["B", "A"]` 具有相同语义和相同幂等载荷。

相同 `action_code + request_id` 的记录，哈希不同（包括不同用户）时返回 `PRACTICE_IDEMPOTENCY_CONFLICT`；哈希相同且已成功时回放首次成功响应。首次写入该唯一键的事务尚未结束时，竞争请求必须等待其提交或回滚：成功提交后回放，回滚后本请求继续执行完整流程。不得对外返回 `PRACTICE_REQUEST_IN_PROGRESS`。

`submit` 与 `complete` 在幂等校验后都必须锁定同一 `cm_learning_session` 并在锁内重新校验状态。`submit` 先获得锁时，先完成本题作答、判分、错题和画像结算，随后 `complete` 以锁内最新已提交数结束会话；`complete` 先获得锁并完成时，后续 `submit` 返回 `PRACTICE_SESSION_NOT_ACTIVE`，不得新增作答或画像。`complete` 的完整状态推进在一个事务内完成，对外摘要只能观察到 `IN_PROGRESS` 或 `COMPLETED`。

```json
}
```

已提交题的 `submission` 返回该题冻结解析、正确选项和用户提交选项，前端只能只读回看，不能再次提交。

### 5. 提交单题

```http
POST /api/assessment/knowledge-practices/{sessionId}/items/{questionOrder}/submit
Content-Type: application/json
X-Request-Id: 0f7cd9a8-4b29-4ba5-b202-b7fb5aac85dd
```

```ts
interface SubmitKnowledgePracticeItemRequest {
  answer: {
    value: string[];
  };
}

interface SubmitKnowledgePracticeItemVo {
  questionOrder: number;
  submittedCount: number;
  feedback: NonNullable<KnowledgePracticeItemVo['submission']>;
}
```

请求体必须是 JSON 对象，`answer` 必填且不得为 `null`，`answer.value` 必填且为非空字符串数组；每项不得为 `null`、非字符串、空字符串或全空白字符串。上述 JSON、必填、类型和格式错误均为 400 `PRACTICE_REQUEST_INVALID`：缺少/空 `answer` 的字段路径为 `answer`，`value` 的结构错误为 `answer.value`，无法解析的 JSON 使用字段路径 `body`。数组中标签格式正确但不属于冻结选项、存在重复标签、单选数量不为 1，或不符合冻结 `selectionMode` 时，均为 422 `PRACTICE_ANSWER_INVALID` 且 `fieldErrors` 为空。服务端不 trim 标签；非空但含额外空白的标签按原值作为冻结选项匹配失败处理。

本操作 `action_code`、规范化载荷、幂等回放和竞争等待规则见第 2.4 节。

同一题已由其他请求成功提交时，新请求号返回 `PRACTICE_ITEM_ALREADY_SUBMITTED`；前端重新读取该题并以只读反馈渲染。提交失败时前端保留本地选择并允许使用新请求号重试；未收到成功响应不得将题目标为已答。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "questionOrder": 2,
    "submittedCount": 4,
    "feedback": {
      "selectedOptionLabels": ["A", "C"],
      "correct": false,
      "correctOptionLabels": ["A", "B"],
      "analysis": "解析内容"
    }
  }
}
```

### 6. 结束练习

```http
POST /api/assessment/knowledge-practices/{sessionId}/complete
X-Request-Id: 215afef7-ec44-4666-aaf7-96d59efb8478
```

无请求体。页面的“退出练习”和“结束练习”均调用本接口；前端如有正在进行的单题提交，必须等待其成功或明确失败后才允许结束。

```ts
interface CompleteKnowledgePracticeVo {
  sessionId: string;
  sessionStatus: 'COMPLETED';
  submittedCount: number;
  returnPath: '/learning/question-bank/knowledge-practice';
}
```

服务端只保留此前已成功提交的题；单题提交已完成作答、判分、错题和画像结算，`complete` 不重新结算任何题。`created` 会话允许直接结束：在同一事务中先转为 `in_progress` 并写入 `started_time`，再依既有状态机依次转为 `submitted`、`settling`、`completed`，写入 `submitted_time` 与 `settled_time`。`in_progress` 会话直接按同一状态机结束；无论 `submittedCount` 是否等于 `totalCount`，终态均为 `completed`。不得为未提交题补建 attempt、answer、错题或画像证据，也不得创建结果页或等待异步任务。

本操作 `action_code`、规范化载荷、幂等回放和竞争等待规则见第 2.4 节。会话已经 `completed` 时，新请求号也返回相同的完成结果，不得报错或重复结算。

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "sessionId": "900000000000000801",
    "sessionStatus": "COMPLETED",
    "submittedCount": 4,
    "returnPath": "/learning/question-bank/knowledge-practice"
  }
}
```

### 7. 失败响应、安全与验收

```json
{
  "code": 409,
  "msg": "该题已提交，不能修改",
  "data": {
    "errorCode": "PRACTICE_ITEM_ALREADY_SUBMITTED",
    "retryable": false,
    "traceId": null,
    "fieldErrors": [],
    "details": null
  }
}
```

| 接口 | HTTP / `R.code` | `errorCode` | 条件 | `retryable` | 前端行为 |
| --- | --- | --- | --- | ---: | --- |
| 全部 | 404 | `PRACTICE_SESSION_NOT_FOUND` | 会话不存在、非本人或非自练会话。 | false | 返回知识点练习设置页。 |
| 全部 | 400 | `PRACTICE_REQUEST_INVALID` | 路径参数、请求号、JSON、必填字段、字段类型、空数组、空字符串或其他格式/范围约束不合法。 | false | 根据稳定排序的 `fieldErrors` 修正；不得匹配 `msg`。 |
| POST 提交 | 422 | `PRACTICE_ANSWER_INVALID` | 标签格式正确但不属于冻结选项、重复，或不符合冻结单选/多选规则。 | false | 保留本地选择并提示修改。 |
| GET 单题、POST 提交；POST 结束的非 `created`/`in_progress`/`completed` 状态 | 409 | `PRACTICE_SESSION_NOT_ACTIVE` | 会话未处于允许读取、提交或结束的状态。已完成会话的 complete 例外，返回成功回放结果。 | false | 读取摘要并按 `nextAction` 返回设置页。 |
| POST 提交 | 409 | `PRACTICE_ITEM_ALREADY_SUBMITTED` | 同题已成功提交。 | false | 重读题目，按只读反馈展示。 |
| POST 提交、结束 | 409 | `PRACTICE_IDEMPOTENCY_CONFLICT` | 相同请求号对应不同用户或规范化载荷。 | false | 停止自动重试，生成新请求号。 |
| 全部 | 500 | `KNOWLEDGE_PRACTICE_ANSWERING_SYSTEM_FAILURE` | 未预期系统或结算故障。 | true | 保留本地状态，提示重试并记录 `traceId`。 |

安全与验收要求：

1. 未提交题不返回答案、对错、解析或历史作答标识；已提交题只返回当前用户、当前会话的反馈。
2. 题目、答案、解析、选项和画像快照不得写入访问日志；日志只记录会话、题序、提交结果、请求号与 `traceId`。
3. 单选、多选、选项顺序互换、非法选项、重复请求、跨设备 `submit/complete` 并发、正确/错误提交、任意跳题、`created` 零题结束和部分题提交结束均有可断言用例；竞争请求必须验证等待并回放或在首事务回滚后继续执行。
4. 错题与画像结算只来自提交成功的题，按冻结映射和既有唯一约束验证不重复；未提交题必须验证无 `cm_question_attempt`、`cm_attempt_answer`、`cm_error_record`、`cm_profile_settlement` 或 `cm_learning_evidence`。
5. 覆盖 `sessionId`、`questionOrder`、`X-Request-Id`、JSON、`answer`、`answer.value` 的 400 字段错误，以及冻结规则导致的 422；字段错误和所有响应数组必须满足第 2.1 节排序。
6. 不存在结果页、计时、提示、草稿、暂停、恢复、CASE、ESSAY 或 AI 评分接口；完成会话旧链接只能安全返回设置页。
