# U07 学员知识点目录映射后端接口契约 V1

```yaml
contract_id: learner-knowledge-point-directory-u07
contract_version: 1.0
module: U07
route: /api/learning/knowledge-points
scope: learner-current-goal-knowledge-point-lookup
status: handoff_ready
updated_at: 2026-08-13
```

## 1. 目标与边界

本契约提供学员端通用、只读的知识点目录映射：前端以稳定的`knowledgePointId`批量取得当前学习目标范围内的考纲编号、名称和所属科目。它供当前学习画像、任务、错题、资源和首次诊断完成页共同复用；业务接口继续只传递知识点ID和自身业务事实，不在每个响应中重复拼接目录字段。

首次诊断报告是一次性结果页；它可调用本接口把报告中的ID显示为“`syllabusNumber syllabusTitle`”。学员长期查看的是随正式作答持续更新的当前画像，当前画像同样调用本接口解析名称。本接口不创建、修改、删除或计算画像、报告、题目、学习目标或知识树。

本接口只解析调用者当前有效学习目标（`cm_user_goal.status IN ('active','paused')`）所固定的`syllabus_version_id`内、可见的知识点。它不提供管理端知识树、跨资格查询、跨考纲历史比较、树形结构、父节点路径、题目映射、重要度、推荐参数、描述正文或任何画像结论。

数据库已具备所需事实，无需新增表或迁移：

- `cm_user_goal(user_id, certification_id, syllabus_version_id, status)`确定学员当前范围；有效目标由部分唯一索引`uk_cm_user_goal_current`约束。
- `cm_knowledge_point(id, syllabus_version_id, exam_subject_id, syllabus_number, syllabus_title, status, del_flag, row_version)`提供稳定ID和展示目录。
- `cm_exam_subject(id, certification_id, subject_code, subject_name)`提供科目名称；`cm_syllabus_version(id, certification_id, version_name)`限定考纲归属。
- 有效目录查询必须使用`cm_knowledge_point.syllabus_version_id`与当前目标相等、`del_flag='0'`、`status='0'`；使用现有索引`uk_cm_knowledge_point_active_number`和知识点主键/关联条件，不依赖前端缓存或题目快照。

本接口返回当前目录名称，不替代需要冻结名称的历史快照。若将来某个正式历史凭证需要永久展示“当时名称”，该凭证必须在自己的冻结快照中保存名称和编号，并另立契约；不得通过本接口倒查当前名称冒充历史快照。

## 2. 共同约定

### 2.1 响应和错误包络

全部响应使用现有`R<T>`包装；真实HTTP Status必须等于`R.code`。前端仅根据`data.errorCode`处理业务失败，`msg`只作脱敏展示兜底。

```ts
interface KnowledgePointDirectoryErrorVo {
  errorCode: string;
  retryable: boolean;
  traceId: string | null;
  fieldErrors: Array<{
    field: string;
    code: 'REQUIRED' | 'INVALID_FORMAT' | 'OUT_OF_RANGE';
    message: string;
  }>;
}
```

401/403沿用认证与授权兼容格式，只承诺`code`、`msg`和空`data`，不承诺`errorCode`。4xx不产生`traceId`；5xx返回安全文案、非空`traceId`和空`fieldErrors`。

### 2.2 身份、权限与范围

- 接口仅允许已登录`app_user`调用；用户ID从当前会话取得，查询参数不得传递`userId`、`goalId`、`certificationId`、`syllabusVersionId`或`examSubjectId`。
- 权限固定为`certmuse:learning:knowledge-point:query`；实现同时校验学员身份`certmuse:student`。后台账号和无权限账号不得读取目录。
- 服务端先读取调用者唯一有效目标。没有有效目标时返回409 `LEARNING_GOAL_NOT_ACTIVE`，不根据请求ID猜测资格或考纲。
- 每个请求只查询当前目标的`syllabus_version_id`和同一资格下的科目；不得因调用者提交其他范围的ID而返回其存在性、名称、编号、删除状态或其他元数据。

## 3. 批量获取知识点目录映射

```http
GET /api/learning/knowledge-points?ids=900000000000000101,900000000000000102
```

请求无Body、无`X-Request-Id`。`ids`是一个逗号分隔的十进制正整数列表；前端必须先去重后请求。服务端仍须自行去重，不能依赖前端。

| 查询参数 | 必填 | 规则 |
| --- | ---: | --- |
| `ids` | 是 | 1～100个去重后的十进制正整数ID；单个ID不超过19位；不允许空片段、空白、负数、小数、科学计数法、非数字或额外查询参数。 |

### 3.1 成功响应

```ts
interface KnowledgePointLookupVo {
  id: string;
  syllabusNumber: string;
  syllabusTitle: string;
  examSubjectId: string;
  examSubjectName: string;
}

interface KnowledgePointDirectoryVo {
  items: KnowledgePointLookupVo[];
}
```

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "items": [
      {
        "id": "900000000000000101",
        "syllabusNumber": "1.3.2",
        "syllabusTitle": "架构风格",
        "examSubjectId": "900000000000000011",
        "examSubjectName": "综合知识"
      },
      {
        "id": "900000000000000102",
        "syllabusNumber": "1.4.1",
        "syllabusTitle": "质量属性",
        "examSubjectId": "900000000000000011",
        "examSubjectName": "综合知识"
      }
    ]
  }
}
```

服务端按请求中ID的首次出现顺序返回命中的项目；前端不得依赖数据库自然顺序。`items`可为空。请求中不存在、已删除、已停用、超出当前目标考纲范围或不属于当前目标资格的ID一律静默省略，且不返回`missingIds`、`forbiddenIds`或任何区分原因的字段。

前端将`items`构建为`Map<id, KnowledgePointLookupVo>`。当前页面未命中的ID只能显示“知识点信息不可用”，不得改用其他考纲、本地写死名称或请求管理端接口。

### 3.2 服务端查询规则

服务端在一次只读查询中完成以下约束：

1. 从会话获得`userId`，锁定或一致性读取该用户唯一的`active`/`paused`学习目标；若不存在则返回`LEARNING_GOAL_NOT_ACTIVE`。
2. 规范化`ids`：按逗号拆分、拒绝格式非法值、按首次出现顺序去重、校验数量不超过100。
3. 查询`cm_knowledge_point kp`，关联`cm_exam_subject es`与`cm_syllabus_version sv`；必须同时满足：
   - `kp.id IN (:ids)`；
   - `kp.syllabus_version_id = goal.syllabus_version_id`；
   - `kp.del_flag = '0'`且`kp.status = '0'`；
   - `es.id = kp.exam_subject_id`且`es.certification_id = goal.certification_id`；
   - `sv.id = kp.syllabus_version_id`且`sv.certification_id = goal.certification_id`。
4. 仅投影本契约定义的5个展示字段。不得返回`parent_id`、`tree_depth`、`description`、`importance`、`diagnostic_enabled`、`recommendation_enabled`、`row_version`、审计字段或数据库状态字段。
5. 对命中结果按输入序号重排后返回。请求不存在或跨范围不构成错误，也不记录为安全告警；仅按常规访问审计记录用户、目标、命中数量、请求数量、耗时、结果码和`traceId`（如有）。

### 3.3 前端消费与缓存规则

- 任一页面收集本页需要展示的知识点ID，去重后最多100个发起一次请求；超过100个时按最多100个一批顺序请求并合并映射，不并发放大请求。
- 前端仅可做页面内或会话内短期缓存，缓存键至少包含`syllabusVersionId`和知识点ID；切换学习目标、收到目标范围变化或登出时必须清除。
- 目录查询失败不应隐藏画像、任务或报告中的业务事实；保留其状态、数量和分数，并以“知识点信息暂不可用”降级显示。401/403交由全局登录/无权限处理。

## 4. 失败响应

### 4.1 参数格式错误

```json
{
  "code": 400,
  "msg": "请求参数不正确",
  "data": {
    "errorCode": "KNOWLEDGE_POINT_LOOKUP_INVALID",
    "retryable": false,
    "traceId": null,
    "fieldErrors": [
      {
        "field": "ids",
        "code": "INVALID_FORMAT",
        "message": "ids必须是逗号分隔的正整数列表"
      }
    ]
  }
}
```

| HTTP / `R.code` | `errorCode` | 条件 | `retryable` | 前端行为 |
| --- | --- | --- | ---: | --- |
| 400 | `KNOWLEDGE_POINT_LOOKUP_INVALID` | `ids`缺失、空、格式非法、包含空片段或去重后超过100个。 | false | 记录前端调用错误；当前页降级展示，不以`msg`分支。 |
| 401 / 403 | 不承诺 | 未登录、非学员或无`certmuse:student`/`certmuse:learning:knowledge-point:query`权限。 | 不承诺 | 交给全局认证或无权限处理。 |
| 409 | `LEARNING_GOAL_NOT_ACTIVE` | 当前用户没有`active`或`paused`学习目标。 | false | 重新查询onboarding状态并按白名单分流；清理目录缓存。 |
| 500 | `KNOWLEDGE_POINT_LOOKUP_SYSTEM_FAILURE` | 未预期查询或序列化故障。 | true | 保留页面业务事实，提示稍后重试；使用`traceId`支持排查。 |

## 5. 安全与可观测性

- 不记录完整`ids`原文、知识点名称、用户输入的展示内容或任何会话令牌；访问日志只记录请求ID数量、命中数量和范围校验结果。
- 错误响应不得包含SQL、表名、约束名、目标/考纲ID、内部堆栈、其他资格知识点或其存在性。
- 本接口为只读，不使用幂等请求号，不产生学习事件、画像证据、报告变更、任务变更或数据库写入。
- 可选Redis缓存仅允许缓存公开目录投影，键使用`certmuse:learning:knowledge-point-directory:{syllabusVersionId}:{id}`，TTL不超过10分钟；知识点名称、状态或考纲发布变更时必须失效。未启用缓存时不得影响接口语义。

## 6. 验收用例

1. 有效目标下请求两个当前考纲、启用且未删除的知识点：200，返回ID、编号、名称、科目ID和科目名称，顺序与请求首次出现顺序一致。
2. 重复提交同一ID：200，每个ID最多返回一次。
3. 请求100个合法ID：200；去重后101个合法ID：400 `KNOWLEDGE_POINT_LOOKUP_INVALID`，字段错误指向`ids`且为`OUT_OF_RANGE`。
4. `ids`缺失、`ids=`、`1,,2`、`1,abc`、`-1`、`1.5`：400 `KNOWLEDGE_POINT_LOOKUP_INVALID`，不查询目录。
5. 请求当前考纲有效ID与不存在ID混合：200，仅返回有效命中项，不返回未命中原因或ID列表。
6. 请求其他资格、其他考纲、已删除或停用知识点ID：200且静默省略；不得暴露名称、编号或存在性。
7. 用户没有有效目标：409 `LEARNING_GOAL_NOT_ACTIVE`；不得按请求ID推断范围。
8. 未登录、后台账号或缺少任一学员/目录查询权限：沿用401/403兼容响应，不返回目录数据。
9. 当前画像页目录查询500：画像数值和状态仍展示，名称降级为“知识点信息暂不可用”，响应具有非空`traceId`。
10. 切换学习目标、目标失效或退出登录后：前端清除旧考纲目录缓存；后续请求只返回新目标范围内项目。

## 7. 实施入口

- 后端：`backend/ruoyi-modules/ruoyi-certmuse`，学员读模型归属`learning`域；目录数据通过明确的`catalog`服务契约读取，禁止`learning`域直接访问`catalog` Mapper。
- 前端：`web/student/src/api/certmuse/learning/`增加通用目录API；首次诊断结果页、未来“当前学习画像”页、任务、错题和资源页按需调用。
- 数据：只读`cm_user_goal`、`cm_knowledge_point`、`cm_exam_subject`、`cm_syllabus_version`；无迁移、无回填、无写入。
